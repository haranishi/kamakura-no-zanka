# 道しるべ（画面側）の実ブラウザ確認（7.2・7.3・7.4の一部）

2026-10-27。1280×720・1440×900・1024×768、DPR1、GPU付きのChromeで確認した。矢にだけ従う自動歩行は、3つの道とも里の中心へ着く。確認の途中で、実装の問題を3つ見つけて直した。

## 見つけて直した問題

| 問題 | 原因 | 直し方 |
|---|---|---|
| b3の北の基準路を、最初に作るとき約10秒固まる | 道の帯の外の接続区間（forest[8]→north[0] など）で見通しが塞がれると、世界全体（約17万セル）の格子を作った。通れる判定を約110万回呼んだ（1回約22µs）。復帰路（Gと迷いの助け）も同じ作り | 接続区間と目的地の補正は、区間のまわりだけの格子（6m、足りなければ24m、最後が世界全体）で探す。基準路の長さと経路は、全11本とも変わらない |
| 足もとの矢が、主人公の体に隠れて見えない | 後ろから見るカメラでは、主人公の前方の地面は、20m以上離さないと体に隠れる（計算と実画面で確認）。前方1.6mの設計の想定が成り立たなかった | 矢の深度判定を切り、体の上にも重ねて描く。地面に沿った形は保つ |
| 縁の矢の向きが縦にゆがむ | カメラ空間のxとyは同じ縮尺なのに、アスペクト比で割っていた | 割り算をやめた |

あわせて、助けの文がヒント（「C で屈む…」）と重なったので、目的文の枠の中へ移した。`H`（画面の表示を隠す）で3Dの矢・柱・粒が残ったので、隠すようにした。

## 構築の時間（M4 Pro・Chrome）

| 基準路 | 直す前（冷えた） | 直した後（冷えた） | 温まった後 |
|---|---:|---:|---:|
| front | 19ms | 19ms | 0.5ms |
| north | **10,007ms** | 106ms | 4ms |
| south | 179ms | 247ms | 3ms |

読み込み中に、判定のキャッシュを温める（`Game.warmGuide`、約0.6秒、一度だけ）。b3の開始は約42ms、道を選んだ直後は約8msになる。通れる判定の呼び出し回数の上限は、`tests/valley-guide-world.test.mjs` が縛る。

## 確認した内容

| 項目 | 結果 |
|---|---|
| 矢に従う自動歩行（`regress-follow-guide.mjs`） | front 32秒・north 42秒・south 47秒で、b2→b3→b4の里の中心へ着く。道外れ・迷いの強調は一度も出ない |
| 南北の切替（`regress-guide-switch.mjs`） | 脇道を選んで南の畦道に立つと3.5秒後に south へ、北の斜面道に立つと3.5秒後に north へ。切替後は道外れ・強調が消える |
| G | 粒120・約5秒。直後の連打は拒否。設定が「なし」でも使える。動きを減らす設定では粒48 |
| 迷いの助け | 道から外れると、足もとの矢が強まり、縁の矢（距離つき）と助けの文が出る |
| 初回案内 | 移動のヒントが終わった約9秒後に、b0で一度だけ「迷ったら G で、導きの風を呼べます」 |
| 設定「道しるべ」 | 「はっきり」「ひかえめ」「なし」の出し分け、保存（`kamakura-valley-settings`）、不正な値は「はっきり」 |
| 性能 | 1コマの平均は、案内の有無で差なし（13.5ms）。描画呼出は+2、三角形は+22 |
| 3画面比 | 矢・縁の矢・距離・助けの文が、重ならずに収まる |

## 残り（本人・次の作業）

- 実機（iPhone・低性能のPC）での見え方と、読み込みの約0.6秒の増加。
- 未見者の3秒理解（7.4）。「目的が出て3秒以内に向きが分かるか」を、初めて遊ぶ人で。
- 中心到達後の戦闘目的と、b5への進行を実プレイで（7.12）。
- 軽い既知の点: 脇道を選んで南の畦道へ向かうとき、北の道から離れて畦道に着くまでの間（約50m）は、道外れの強調が出る。矢は北の道へ戻る向きを示す。畦道に着いて3秒後に、案内の道が切り替わる。
