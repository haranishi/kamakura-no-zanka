## 測定（`perf3.json`）

第2周（dee083d の写し）と第3周を、同じ条件で交互に測った（M4 Pro・Chrome・1280×720・DPR1）。同じ時間帯に、別の写しで変異検査が走っていた（両方の版に同じ負荷）。

全16回（遠景の板を170〜420mで1.4倍に広げた時点）。最大の描画呼出は全ての組で同じ、最大三角形は全ての組で16〜280少ない。

| 品質・場面 | p95 第2周（1回目/2回目） | p95 第3周 | 最大呼出 | 最大三角形（1回目） |
|---|---|---|---|---|
| 標準・移動 | 15.9 / 15.8 ms | 16.1 / 16.2 ms | 744 / 740（同じ） | 4,106,596→4,106,428 |
| 標準・戦闘 | 14.8 / 15.0 ms | 15.0 / 15.0 ms | 669 / 680（同じ） | 3,799,173→3,799,053 |
| 軽量・移動 | 14.1 / 13.9 ms | 14.3 / 14.0 ms | 722（同じ） | 3,455,781→3,455,749 |
| 軽量・戦闘 | 11.7 / 11.8 ms | 11.7 / 11.8 ms | 641 / 647（同じ） | 3,129,442→3,129,426 |

p95が0.1〜0.4ms増えた組があったので、標準・移動で切り分けた（`ab`）。遠景の板を広げない版は第2周と同じ（16.0/16.0ms）だった。
そこで広がりを200〜460m・1.35倍に狭め（採用）、標準・移動を3往復で測り直した（`final`）：p95の平均 第2周 15.60/15.33ms → 第3周 15.77/15.37ms、
1800コマの時間は 25.79/22.37s → 25.93/22.18s。差は0.1ms刻みの揺れの範囲で、増えたとは言えない。全ての回が予算内（標準20ms・軽量33.3ms・呼出900・三角形500万）。

木の1パスの三角形（Node・実際の配置）：開始地点 891,988→891,796、林道 806,460→806,308（4地点とも第2周以下）。
読み込み：ファイル・素材の追加なし。JSは約8.9KB増（多くは注釈）。毎コマの確保は増やしていない（頂点に4値の属性を足しただけで、割り当ての処理は同じ）。

## 残る欠点と未確認

- 広葉は「小さな球の房の束」に見える（房の一つひとつは殻のまま）。若木（Q11）は第2周のまま（房を増やすと形の試験4件が崩れ、時間内に直せず戻した）。
- 葉の無い枝は減ったが残る（Q06の左の杉）。カメラの真横を通る枝は、根元側に房が無いので縮めても棒が見える。
- 未着手：葉の絵を3種以上・木ごとの大きさと傾き（盲検の4）、杉の型3〜4種・不規則な段・根元の広がり・樹皮の割れと色むら（5）、遠景の縁のギザギザ。
- 未確認：本人の目、別役の盲検（第3周）、Safari・Firefox・実機、動画での縮み（房が根元へ畳まれる動き）・LODの帯・遠景の広がり。
