# 8.3a 刃の軌跡と小さな改善：前後の記録（2026-10-30）

振りの向きと速さが帯で読めるようになり、突きと侍大将の二段目は振りの最中に当たるようになった。どちらも表示だけの変更で、戦闘の論理は前後で一致している。
設計・採った方式・捨てた案は `.kiro/specs/hidden-valley-slice/design-combat-trail.md`。ここは測った結果と画像の置き場。点数は付けていない（別役の盲検採点は未実施）。

実ゲームの固定カメラ（2人を真横から見る）・seed 1333・同じ入力で撮ったコマ割り。各コマの下に、主人公と相手の技・位相・技の経過秒を書いた。「[停止]」は命中の停止中のコマ。

| 場面 | 見どころ |

| B 強斬り | 真上からの縦の斬り。コマ34〜44で、最も濃く幅広い帯が上から下へ残る |

撮り方：`KZ_TAG=before|after PLAYWRIGHT_MODULE=… node tools/valley-play.mjs tools/scenarios/capture-combat-trail.mjs --seed 1333 --out <フォルダ>`（変更前は main の 9bf9eea、変更後はこのブランチ）。

## 測った結果

- 刃の動き（`blade-motion-{before,after}.json`・`tools/scenarios/measure-combat-trail.mjs`）：手を加えていない11技は、手首と切先の速さの山・道のりが前後で同じ値。突きは手首の山が判定の始めより242ms早かったのが8ms遅いへ、侍大将の二段目は手首が速い区間の終わりが判定の終わりより238ms遅かったのが12ms早いへ。
- 切り出しの表（`move-segments-after.json`・`tools/measure-move-segments.mjs --compare ../baseline/move-segments-before.json`）：変わったのは2技の速さだけ（突き 0.6→予備0.29／振り1.8／戻り0.61倍、二段目 0.67→0.67／1.67／0.67倍）。使用割合は同じ。
- 帯の決まり（`regress-slash-trail.json`・`tools/scenarios/regress-slash-trail.mjs`）：区間の外で足した数0、寿命のうちに消える、停止中に詰まらない、抜刀の層の7コマで足さない、やり直しで0、揺れ0・動きを減らすでも出る、描画呼出の増加1、三角形は最大128。三段目の停止は0.07秒のまま。弾きの火花は相手の刃の速度（−7.8, 1.8, −0.8 m/秒）の向きへ偏り、平均の水平の向きとの余弦は0.995。
- 論理（`tools/scenarios/regress-attack-timing.mjs`）：同じ入力列で、斥候との320コマ（突き・袈裟を含む）と、侍大将との520コマ（二段目4回を含む）が前後で一致。
- 性能：帯の処理は平均0.011ms/コマ（6回の測定とも0.010〜0.011ms）。同じページで帯あり・なしを150コマずつ交互に各1500コマ測った中央値は14.5/14.7ms。描画呼出は最大で682→683、三角形は最大で56増えた。測った時刻は別の作業のビルドとブラウザで負荷が高く（load average 12〜16）、p95は17.9〜31.1msと揺れたので、0.3msの精度での判定と静かな時刻の8試行は残件。

## 自分の目で見た所見（採点ではない）

主人公の帯は、一段目の上からの弧、強斬りの縦の斬り、三段目の払いで、振りの向きと速さが読めた。命中の停止のコマでは帯が止まり、斬った線が一瞬残る。
二段目は、止まったコマで帯が短い白い板に見えたので、遅い刃ほど薄くする形にした（後の画像は直したあと）。
敵の帯は薄墨で弱く、明るい地面と空の前では読めるが、横から見た突きは刃の動きがカメラへ向くので薄い。予兆の金色の光とは、時機（光は振る前で止まる）と色で取り違えない。
