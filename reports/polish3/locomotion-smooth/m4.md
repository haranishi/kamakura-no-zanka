## 結論
- 効いたのは壁際・木の間・段差。家の角を走り抜けるときの瞬間の寄せ（1コマで1.18m）が無くなった。木が密な所では、1コマに1m以上寄せる跳びが、32通り中17通りから2通りへ減った。棚田・土手のカメラの上下の揺れ（加速度）は半分以下になった。
- 平地は元から滑らか。台本の加加速度 p99 は 209.5→185.8（−11%）。これは旋回の尾を外した物差しで、旧い定義では −3.6%（239.8→231.1）。止まりの山の最大は −14%。写真ではほぼ見分けられない。
- 盲検（画面全体の連続写真・Opus 3人×9場面）：27件中、同点24・新の勝ち3（家の角）・旧の勝ち0。画角を広げた版で採点した（下の「画角」）。
- 走りで画角を最大+3度広げる機能は、既定オフ（`?fov=on` で入る）にした。盲検で良し悪しが付かず、広げた分だけ描画が重い。画角なしの既定は main と同じ重さ。
- 論理（位置・向き・速さ・歩容・接地）は762コマすべて main と同じ。関節も完全一致。戦闘の論理も main と一致（斥候320・侍大将520コマ）。

## 画角（`?fov=on` のときだけ）
- ならした速さ 3.2→5.0m/秒で 0→+3度。上げ ω4・戻し ω3。「画面の揺れ・衝撃」の倍率を掛け、0 と「動きを減らす」では広げない。
- 既定オフの理由：盲検で良し悪しが付かない（構図 5.96 対 5.96）。描画が重い（画角あり：移動の p95 +0.3ms・平均 +0.24ms で約2%、木の間のCPU +0.19ms/コマ。画角なしは差なし）。好みが分かれる。
- 盲検は画角ありの版で採点した。既定（画角なし）は、前との画素差が平地で3〜5%（画角ありは約19%）に縮み、壁際・棚田・旋回の動きの違いは同じ。既定そのものは盲検にかけていない。

## 門番の確かめ（不具合を戻すと失敗する）
`KZ_MUTATE=predict`（先回りを切る）→ 家の角で1.18m の跳びで失敗。`vertical`（上下を1段に）→ 棚田の上下の加速度31で失敗。`hold`（寄せの下限を外す）→ 木の間で0.094（約0.35m）割って失敗。`fov`（画角が揺れの倍率を読まない）→ 揺れ0で60.98度になり失敗。追従を弱めて滑らかに見せる逃げ（ω4・先読みなし）→ 主人公の画面上の流れ 0.87（前は0.11）で失敗。

## 性能（標準品質・main と交互・3回ずつ）
- 画角なしの既定：移動の p95 は main 26.1・M4 26.0ms、平均 19.93・19.79ms（旧カメラに戻した対照 19.54）。戦闘の p95 は 24.4・24.4ms。描画呼出は同じ、三角形は +0.04%。この回は機械が遅い状態で、絶対値は最初の測定（13ms台）より重い。差だけ読む。
- 画角あり（最初の測定・機械が速い状態）：移動の p95 15.7→16.0ms、平均 13.46→13.74ms（約2%）、戦闘は同じ。三角形 +0.3%。
- `guide-hitch`（道外れの助けで1コマが詰まらない試験）は、p99 が 33.4ms の境目にあり、機械の状態で main でも 26〜36ms の間を揺れた（main は交互の4回中3回が33.4ms超）。最終版も同じ揺れ方で、差は平均 +0.3ms。最初の1回は M4（画角あり）でも 25.7ms で合格した。
