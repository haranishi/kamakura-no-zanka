# Design: 刀を握る手（タスク8.6a・R17.7・R18.8）の実測と採用方式

本人の評価（2026-10-30・プレイ後）「手の持ち方が変。剣の。そこも修正してほしい」への対応。Issue #10。数値の目標は**設計目標**（実測値は明記）。

## 実測：柄は右手首の関節を通っていて、指を曲げるだけでは握れない

主人公・兵・侍大将の人物GLBと、刀の付け方（`config.js` の `GRIP.tachiDrawn`）を、手の骨の局所（結合姿勢）で測った（2026-10-30）。

| 項目 | 実測 |
|---|---|
| 骨 | 3体とも24本で指の骨は無い（`LeftHand`・`RightHand` が末端）。手は体と同じ1つのメッシュの一部（主人公の右手1,325頂点） |
| 指の形 | 4本は側面でつながった1つの面（指の帯の頂点の連結成分は1つ）。結合姿勢で手のひらは下、親指は前 |
| 柄の軸 | 柄の軸は手の骨の局所 Z 軸そのもので、**右手首の関節の中心を通る**（全動作の全コマで距離0） |
| 握る位置 | 握る溝（指の付け根の少し手前の手のひらの上）は、柄の軸から約12cm。右手の親指は柄頭の側を向く |
| 左手 | 構えで柄の軸から3〜4cm、攻撃の多くのコマで9〜37cm（片手のコマ） |

依頼の前提（柄は手のひらの前にあり、指を巻けばよい）は成り立たなかった。柄を手のひらへ動かすと刃の軌跡が変わる（禁止）。

## 判断と捨てた案

| 判断 | 理由 | 捨てた案 |
|---|---|---|
| 指の骨を合成する。4本は1つの板の鎖（付け根・中・先）、親指は2関節 | 指が側面でつながり、1本ずつに分ける境目が無い。板の曲げでも、寄りで「握っている」と読めた（画像） | 拳の差し替え（質感が変わる）、1本ずつの鎖 |
| **見える腕を写し（上腕・前腕・手）にし、写しだけを二関節IKで柄へ寄せる**。刀は今までどおり動作の手の骨に付く | 柄は手首を通るので、手そのものを約12cm動かすしかない。動作の骨を動かさないので、刀・抜刀の層（8.2）・既存の測定は変わらない | 動作の骨を動かし、刀の付け方を毎コマ補正する案（8.2の握りの測定と定位置の検査の意味が変わる）、刀を手のひらへ動かす案（軌跡が変わる） |
| 握る形（関節の角・柄の中心線の高さ・親指）は、型ごとに実際の頂点で合わせる | 2次元の近似では、親指と侍大将の指が5〜14mmめり込んだ | 2次元の接線の式だけで決める |
| 柄のまわりの手の回りは0（構えの握り）。腕が届かないコマだけ、右肩から届く弧の中で0に最も近い回りへ寄せる（毎秒20radまで） | 抜刀の前半は、構えの握りのままだと4〜14cm届かない。u の予定表で回すと、速い抜刀で2コマに詰まって跳んだ（隣の4倍） | 予定表で −110°→0 に回す案 |
| 抜刀中の左手は鞘を握る（重みは抜刀の層の左手と同じ）。両手持ちの左手は二段目 | 左手首も鞘の軸の上（`LEFT_HOLD`）で、同じ問題 | — |

## 契約

- 写しは毎コマ、動作の骨から写し直してから動かす。動作の骨・刀・鞘・論理（`combat.js`）には触れない。後処理は残らない。
- 重みの付け替えは型の形（全員で共有）に1回だけ（`geometry.userData.handRig`、読み込みの間）。骨と骨組みは人物ごとに作る。腕の頂点は写しへ、手の頂点は手のひら・指・親指へ分ける（4つまで・合計255）。
- 握る重み：右手は、手の刀が見えて手に付いている間1（落とす・降参で0.08秒かけて離す）。抜刀・納刀の間は進み具合 u から決め、腕が柄へ届く区間の後ろ3分の2で入れる（最初のコマに12cmのずれを一度に足すと跳んだ）。左手は抜刀の層の左手の重み。鞘の軸の向き（±）は握り始めのコマで決める（毎コマ選ぶと、内積が0をまたぐコマで手が半回転した）。
- 握っていない手は、指を軽く曲げる（付け根0.16・中0.22・先0.12rad、親指0.10・0.08rad）。
- 対象は刀を持つ主人公・兵・侍大将（兵の弓手も同じ型なので、指の軽い曲げだけ）。村人・弥十郎の型は変えない。
- 柄の位置と向き（`GRIP.tachiDrawn`）は変えない。刀の軌跡（切先の位置）は変更前と1mm以内（実測0）。

## 構成

純粋層（Node）：`hand-grip.js`（手の形の測定・重みの分け方・指の姿勢・握りの合わせ・配列を作らない二関節IK・届く回り）。結線：`hand-rig.js`（型の準備・写しの骨・毎コマの適用）。`characters.js` の `update()` は、抜刀の層の `apply()` のあとに `hands.apply()`。

## 合否と、2026-10-30の実測

| 項目 | 目標 | 実測 |
|---|---|---|
| 皮のめり込み（手のひら・指・親指の全頂点と柄・鞘） | 2mm以下 | 最大1.4mm（31場面・全コマ） |
| すき間（指の付け根・中の節、4本×2節で柄にいちばん近い皮） | 3mm以内 | 構え・攻撃：主人公4.5mm以下・兵3.7mm以下。抜刀中：5.9mm以下（手を楕円の柄のまわりに回すため細い側に当たる）。侍大将：12.9mm（手が厚く、板の曲げでは小指の側が閉じきらない）。**目標未達**。回帰の合格線は6mm（侍大将は記録だけ） |
| 跳び（見える手首の位置・向き、指先の骨） | 隣の動きの3倍以下 | 最大2.98倍 |
| 骨の戻り（動作の骨を、層を切った同じ人物と比べる） | 1e-6rad以下 | 6e-8rad以下。握っていない手の写しは動作の骨と一致 |
| 刀の軌跡（`record-sword-tips.mjs`、変更前の版と比べる） | 1mm以下 | 116列・22,379コマで0.0000mm |
| 腕が握りの位置へ届かないコマ | — | 速い抜刀・納刀の1〜2コマ（最大30mm。回りの変化を毎秒20radに抑えるため） |
| 実ゲームの主人公（`regress-hand-grip-game.mjs`・4場面） | 抜き切ったら柄を握り、抜く間は鞘を持ち、納め切ったら解ける | すべて満たす。めり込み最大1.0mm |
| 論理（`regress-attack-timing.mjs`、変更前の版と比べる） | 一致 | 320コマ一致（攻撃の開始20・83・252） |
| 性能 | 描画呼出・三角形を増やさず、標準p95≤20msを壊さない | 骨24→40本。描画呼出682・三角形4,188,713は同じ。型の準備43〜64ms（読み込みの間）。毎コマの更新は1人約0.01ms増、毎コマの新しい確保なし。p95は同じ条件の前後で26.6→25.8ms（差なし。測定中に別の作業がMacで動き、前後とも20msを超えた＝静かな環境での再測定が要る） |

純粋層の試験8件・変異20件（すべて検出）。前後の画像と数値の置き場は reports/polish3/hand-grip/README.md。
