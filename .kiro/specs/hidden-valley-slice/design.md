# Design: 隠れ谷の縦切り（全体）

詳細は design-world.md（地形・風景）・design-characters.md（人物・動作）・design-gameplay.md（戦闘・判断・任務）・
design-contracts.md（純粋ロジックの契約）。ここには全体の構造と、コードを消すと失われる判断だけを書く。

## 位置づけ

v18の庭のしごと（`/`、一人称、GLB一枚）は回帰検証と比較のため残す。縦切りは別の入口 `/valley/` に新設し、
`dist/valley/` の ES Modules として作る。ビルド不要・依存追加なし・Three.js 0.180.0 同梱を引き継ぐ。
追加してよい同梱物は、同じ版の Three.js 付属ファイル（SkeletonUtils 等）と、出所を記録した素材だけ。

## 層（上が下を呼ぶ。逆は禁止）

| 層 | 中身 | 規則 |
|---|---|---|
| harness | `qa.js` `shots.js` | `?qa=1` のときだけ読み込む。通常プレイと成功を区別する |
| app | `main.js` 入力・ループ・結線 | 論理と見た目の間を橋渡しするだけ。規則を書かない |
| view | 地形・大気・植生・水・建物・人物・FX・HUD | Three.js と DOM を使う。進行状態を持たない |
| logic | `combat` `enemy-ai` `companion-ai` `nav` `quest` `save` `terrain-height` | **Three.js・DOM・Math.random・Date.now を使わない**。Nodeで単体検査する |
| data | `world-data` `story-data` `config` | 純データ。描画・当たり・配置・敵配置が同じ問い合わせを読む |

## 約束（全モジュール共通）

- 単位はメートル・秒。Y上、X東、Z南（北は -Z）。yaw は Y 軸回りで、前方ベクトルは `(-sin yaw, 0, -cos yaw)`（v18と同じ）。
- glTF の人物は +Z を向く。表示の回転は `rotation.y = yaw + PI`。
- 論理は固定刻み 1/60 s のアキュムレータで進め、`dt` は 1/30 s を超えない。乱数は seed 付き（mulberry32）を引数で受ける。
- 乱数の系列は機能ごとに分ける（地形・植生・敵配置・戦闘のゆらぎ）。後から機能を足しても既存の絵を組み替えない。
- 見た目の調整値は `config.js` に集め、`?lk=キー:値,...` で書き換えずに試せる（固定画角の比較用）。

## 主要な判断と、捨てた案

| 判断 | 理由 | 捨てた案 |
|---|---|---|
| 地形は純データから手続き生成し、高さ・衝突・配置が同じ関数を読む | 周回のたびに作り直せる。衝突と見た目がずれない | Blender製の地形GLB（再生成が遅い・衝突とLODが別管理） |
| 人物は Meshy→Blender で骨へ動作を写し替えた GLB | 作者の別作品（非公開）で道具と90本の動作が既にある。追加クレジットがほぼ要らない | Mixamo（規約と手作業）、動作の新規購入 |
| 物理エンジンを使わず 2.5D カプセル | 依存なし・決定的・テスト可能。高さは解析関数で得られる | Rapier（依存追加。この規模では過剰） |
| 戦闘の当たりは「動作の当たり区間 × 扇形の間合い」 | 安定し、Nodeでテストできる。見た目の刃の軌跡とは独立 | 刃のメッシュ衝突（不安定・検査不能） |
| 後処理は自前の最小パス（MSAA→ブルーム→階調→ビネット） | 依存を増やさない。必要な効果は小さい | postprocessing ライブラリ・SSAO |
| 霧は高さ依存に差し替え、空・環境光・水面と同じ大気設定から色を取る | 谷底の霧と空気遠近が出る。地平線に継ぎ目が出ない | 素のFogExp2、色の個別指定 |
| 敵の同時攻撃を2人に制限、警戒の伝播を12mに制限 | 企画書の約束。囲まれて理不尽になるのを防ぐ | 全員で殴る・谷全体の連鎖 |

## 性能予算（未測定の設計目標。実測は検証記録に分けて書く）

- 標準品質: 1440×900・DPR上限1.5で p95 20ms 以内。軽量: p95 33.3ms 以内。
- 描画呼び出し 900 以下。人物の同時表示 14 体（高詳細 6・中詳細 8）。
- 読み込み 90MB 以下。人物は 1 体 6MB 以下（質感 2048px・WebP）。
- 戦闘単位は 20 体までの負荷場面を作る。常時 20 体で戦わせない。

## 検証の骨組み

1. Node単体: 規則（戦闘・判断・任務・保存・地形の高さと通行・配置の重なり）。変異させて門番になっているか確かめる。
2. ブラウザ: `?qa=1` の `window.__valley` で時刻固定・瞬間移動・状態取得・1コマ送り。通しの自動操作と固定画角撮影。
3. 独立評価: 画面（固定画角）と体験（通し）を別役で採点。上限3周。同じ失敗が2周続いたら原因と残件を報告する。
4. 比較は同じ画角・同じ乱数・同じ時刻・落ち着いてから撮る。点が下がったら周ごとに切り戻せるよう、変更に周回タグを付ける。
