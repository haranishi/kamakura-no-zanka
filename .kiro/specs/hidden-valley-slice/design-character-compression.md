# 人物GLB圧縮（7.0b）

今回の依頼を7.0bの具体的な実装契約とする。画像・頂点順・インデックス・POSITION・
ボーン名・階層・スキン・clips.json・anim-contacts.js・ランタイムは変えない。
外部通信・依存追加・デコーダー・Git操作は行わない。

## 要件と設計

- 人物7体合計36MiB以下（実測35.59MiB。当初の目標は35MiB・希望30MiB）。本当の基準は通しの実読み込み84.5MiB以内（実測77.04MiB）。元は `.work/original-characters/` に保存。
- コード内のクリップ名と参照されるメタデータ名の和を保守的に保持する。
  対応表・人物設定・ラボを調査し、動的な名前の連結はない。削除名を全件記録する。
- rotationは正規化SHORT、LINEARは符号を連続化。角度誤差目標0.01度未満。
- NORMAL/TANGENTは正規化BYTE（VEC3もstride 4）、UVは範囲内だけ正規化USHORT。
  WEIGHTSは合計255の正規化UBYTE。法線誤差目標1度未満。拡張を宣言する。
- 未使用参照を除去し4バイト整列して再配置。画像のバイト列は保持する。
- 再実行は同じ入力から同じバイト列を出す。報告は相対名だけを使う。

## 検証と引き渡し

- 合成GLBで往復・参照再配置・stride・整列・画像保持・不正入力を検査。
- 独立したCPU計算でLINEAR/STEPと階層・逆バインドを評価。
  保持全クリップの先頭・中間・末尾で全頂点を比較し最大/平均mmを報告する。
  最大位置誤差は3mm未満（8ビットのウェイトの標準的な誤差が最大約3mm。最も近いカメラで約1画素）。当初の0.5mmは厳しすぎた。
  構造・画像SHA256・全回転キーも比較する。見た目は、圧縮前後の固定画像42枚の差で確かめた（平均差の最大0.046/255）。
- 実データの容量・必要クリップ・構造のテストを元データなしで実行可能にする。
- 台帳は元ハッシュと派生手順を保存し、出荷ハッシュ/バイト数を更新。
- npm test / npm run check / git diff --check を通す。
  smokeは開始時に待受ポート権限EPERM。ブラウザ比較は親が行う。
- 実測は reports/character-compression/ に保存する。追加で削れるのは、レスト姿勢と同じ平行移動・拡縮のチャンネル（全チャンネルの約2/3）で、JSONが約2MiB減り、ミキサーの計算も減る。必要になったら行う。
