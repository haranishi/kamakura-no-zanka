# 設計：走り・歩きの滑らかさ

2026-11-04。[要件](requirements-locomotion.md)（R33〜R39）を具体化する設計案。前の担当の見た目の直し（design-locomotion.md）を土台にし、速さ・加減速・足運び・接地・上半身・カメラを「滑らかさの契約」で組み直す。
数値は**初期値（設計目標）**で、M0 の標本化と盲検採点で調整する。パスは `dist/valley/` 基準。純粋層は画面・時計・乱数を直接読まず、渡された値だけで進める部分。

## 1. 調査で分かった事実（読んだコードと測定値）

- 速さ：加速18・減速28m/秒²の直線、旋回上限は受け6・走り9・通常14rad/秒。入力を離すと体は1コマで止まり、速さの値だけが下がる（actors.js:434–456）。
- 動作の選択：歩き0.15/0.08、小走り2.1/1.8、走り3.7/3.3m/秒のヒステリシス。再生倍率は0.55〜2に制限（anim-data.js:14–15）。
- 動作の接地中の足の速さ（前の担当の測定）：Run 2.903・Jog 2.13・Samurai_Walk 1.217・Walk_Fight_Forward 0.769・屈み1.357m/秒。**走り5m/秒はRunの約1.72倍**で、歩調だけで合わせると足がせわしなくなる。
- 動作データは左着地の割合（contacts）と腰の高さの範囲だけを持ち、足位置の時系列は無い。Nodeだけ（tools/lib/glb.mjs＋同梱three）でGLBを標本化して得られることを確かめた。7体の骨の名前と階層は共通。
- 人物の更新順：mixer→接地通知→体幹ばね→腕の開き→刀→握り→弓（characters.js:243–275）。人物どうしの押し分けはその後（game.js:661–675）。**脚のIKは押し分けの後の別パスに置く**。
- 腕・体幹・頭は動作データのまま。走りの専用の層は無い。カメラの注視点は一次遅れ（前の担当が臨界減衰に変更済み）。速さ連動の画角は無い。
- 速さの依存：`SPEED` は actors.js:31 の表だけ。仲間の追従は最大5.2m/秒、敵の走りは3.6/3.2。とどめの突進13・回避3.2m/0.52秒は独立。矢の先読みは主人公の速さを直接使う。任務の略奪損失は経過時間で決まる。

## 2. 速さの表と歩容（M1）

- 表 `LOCO`（actors.js か新規の純粋層）に、層ごとの目標の速さを置く。初期値：慎重1.3・受け歩き1.5（変えない）・通常移動3.0（旧2.5）・走り5.0（変えない）。**候補の表を URL の切替で見比べられる**（`?loco=a|b|c` と個別指定 `&walk=&sprint=`）。決める人は本人。
- 歩容の選択は、動作ごとの「対応する速さの範囲」で決める（Walk→Jog 1.7/1.4、Jog→Run 2.7/2.4m/秒をヒステリシスの初期値）。範囲は gait-table の接地速度×歩調と歩幅の許容から導く。
- 速さを上げるときの波及を同じ変更で直す：仲間の追従上限と前へ出る判定、敵の走り（主人公の通常移動を下回らない）、矢の先読み、案内の評価間隔、略奪損失の試験。戦闘の規則とdash・回避は変えない。

## 3. 加速・減速・旋回（M1）

- 速さは時間で決める：走り出しは約0.22秒、止まりは約0.18秒の滑らかな曲線（smootherstep）。位置は速さの積分で、入力を離しても速さが0になるまで進む（走りで約0.45m、通常で約0.27m）。コマ数に依存しない。
- 旋回：向きは進む向き主導。上限は速さに応じて14→7rad/秒へ下げ、鋭い向き変えでは目標の速さを下げる。逆向きの入力は、減速しながら向きを回す（スキッド）。
- 壁・斜面：実際に進んだ距離から足の再生の速さを決める（前の担当の仕組みを維持）。足踏みを続けない。
- 受け・屈み・回避・攻撃・会話などの入力以外の停止は従来どおり。`?loco=old` で旧挙動に戻る。

## 4. 位相・歩調・歩幅（M2a）

- 標本化の生成物 `gait-table.js`（tools/gait-sample.mjs が作り、生成元と版を先頭に書く）：動作×体格ごとの周期・接地中の足の速さ・左着地の位相・すれ違い位相・骨盤の高さ。手で書き換えない。
- 位相0＝左足の着地にそろえる。歩容の切り替えでは位相を引き継ぐ。待ちから歩き出すときは、足がすれ違う位相から始める。止まるときは、最後の一歩がすれ違う位相に着くよう、止まりの時間を0.12〜0.25秒の中で調整する。
- 速さの比 k＝速さ÷接地速度 を、歩調 kc（再生速度）と歩幅 ks に分ける（kc×ks＝k）。遅い歩きは歩調を優先、走りは歩幅に多く配分する。配分は対数空間で補間して積を保つ。許容は kc 0.8〜1.25・ks 0.75〜1.4。
- 歩幅の伸縮は、骨盤を中心に足の目標を進行方向へ伸縮して作る（腰の水平移動は消えている）。骨の長さは伸ばさない。ks≠1 の間は遊脚を少し高く上げ、骨盤を少し下げる。ks の実現は M2b の脚IKが前提で、M2a では歩調だけを整えて測る。

## 5. 脚のIKと接地（M2b）

- 押し分けの後、刀・握りの前に、足の接地パスを1つ置く（人物の更新を「mixer→…→接地パス→刀→握り」に分ける。骨盤を動かすと刀も動くため、姿勢を決めてから刀と握りを解く）。
- 接地中の足は世界座標に保持し、遊脚へ移るとき滑らかに解放する。足の目標の高さは `terrain.heightAt`、傾きは `normalAt`。骨盤は低い足に届くまで下げ、高い足に合わせて上げない。膝の向きは進行方向の目印（ポール）で決め、届かないときは足を目標へ近づけて解除する。
- 二関節IKは `arm-ik.js` の幾何を脚へ転用する。毎コマの新規確保を避ける（出力を再利用する版）。
- 範囲：主人公と近くの敵・仲間（上限8体）。軽量品質は主人公だけ。費用の目標：主人公1体で0.3ms以内。

## 6. 走りの形（M3）

- 腕振り：自由な腕を、太ももの角度から位相を読む減衰の弱いばねで動かす（周波数は歩調に比例）。鞘・柄の拘束が強い腕は振り幅を弱める。体幹は骨盤と逆向きに回し、頭は視線を安定させる。
- 前傾は速さと加速度から、骨盤の上下は倒立振子の考え方で。加減速で胸と頭を遅らせ、止まった後に小さな息づかい。「動きを減らす」で振り幅を下げる。
- 実行順：mixer の直後・刀と握りの前。前回の補正を戻してから重ねる（二重加算を避ける）。戦闘中は構えと競合しない範囲に限る。

## 7. カメラ（M4）

- 位置・向き・画角をばねで動かし、入力以外で跳ばさない。走りの速さに応じて画角を最大+3度（「画面の揺れ・衝撃」が0なら広げない）。段差・坂の上下はばねでならす。壁寄せは速く、戻りは遅く（既存）。

## 8. 計測と切替（M0）

- `tools/scenarios/smooth-journey.mjs`：要件38.1の台本を固定60Hzで実行し、毎コマ、腰・足・腕・背骨・頭の世界姿勢、論理の位置と速さ、歩容、カメラの位置と向きを記録する。`tools/lib/smooth-metrics.mjs`（純粋・単体試験つき）が指標を計算する。
- 切替名：`speed`・`accel`・`phase`・`stride`・`ik`・`arms`・`camera`。URL の `?smooth=off|<名前>,…` で個別に旧経路へ戻す。基準は同じ版で `off` を撮り直して得る。
- 盲検採点：同じ台本のコマ割り（走り出し・定速・停止・旋回）を、新旧を伏せて両順で別役（Opus）に渡す。

## 9. 採らない案

- 模型だけをばねで遅らせて止まりをなだらかにする：前の担当が試して悪化（走り始め4→8cm）。
- 骨の長さを伸ばして歩幅を作る：変形する。足の目標の伸縮とIKで作る。
- 速い走りの動作の再収録：元データの出所が同梱されていない。IKと歩幅で足りないと分かったときの次の手段。
- 速さの表を本来の速さへ下げるだけ：本人が速度を上げてよいと決めた意図に合わない。

## 10. M1 で決めたこと（2026-11-04・実装 `dist/valley/loco.js`）

- **加減速の曲線**は smootherstep ではなく臨界減衰のばね（速さとその変化の速さを状態に持つ）にした。smootherstep は「始点と終点が決まった1本の曲線」で、鋭い向き変え・Shift の押し離しで目標が毎コマ変わると、毎コマ曲線を引き直して速さがほとんど動かなかった。ばねは始まり・終わりが滑らかなまま、目標の変更に追従する。時間は「差の95%に届く時間」で、上り0.22秒・下り0.18秒。1コマに進む距離はばねの式を厳密に積分するので、30・60・144Hz で止まる距離の差は0.2mm、時間の差は1コマ以内。止まる距離は走り0.38m・通常0.23m（設計の見込み0.45／0.27より少し短い）。
- **逆向きの入力**は目標の速さを0まで下げない（真後ろで2割）。0にすると反転の途中で一度止まり、待ちの動作へ混ぜてから歩き→走りへ混ぜ直して、着いた足が35cm流れた。
- **歩容の扱い（主人公の新しい経路だけ）**：減速の間は下の歩容へ替えない（止まりで走り→小走り→歩きの混ぜが0.3秒に3回重なっていた）。動き出したら目標の速さの歩容へ直接入る。再生の倍率の下限は0（遅いうちはゆっくり回し、着いた足の速さ＝進む速さ）。定速の倍率は0.55を下回らないので、見た目の下限は実質そのまま。
- **歩容の境** Walk→Jog 1.7/1.4・Jog→Run 2.7/2.4 は、速さの表を替えた版だけで使う（`?loco=old`・`?smooth=speed` では旧い境）。通常移動3.0は Run を約1.05倍で回す。
- **切替**：`?loco=old` と `?smooth=off` は表・加減速・歩容の境・波及の値をすべて旧い経路へ戻す（762コマの記録の指紋が main と一致）。`?smooth=speed` は表と境だけ、`?smooth=accel` は加減速と旋回だけを戻す。会話・固定・技の後の硬直・立ち上がりの停止は、新しい経路でも旧いまま（1コマで止まる）。
- **波及**：仲間の歩きは通常移動の0.8倍、追いつく上限は走りの1.04倍以上、前へ出ない判定の見込みの速さも同じ比で。敵の走りは通常移動を下回らない（表 a・b・c では旧い値のまま）。矢の先読みは実際に進んだ速さ。突進・回避・技の踏み込み・combat.js は変えていない。案内の評価間隔（最大30Hz）は、走り5.5m/秒でも1回あたり0.18mなので変えない。
- **止まりの窓の接地のずれ**は M1 では下がらない（位相の掃引12通りで平均 old 24.2→21.7cm、最大 30.8→30.7cm）。減速の間の接地足は1cm未満で止まっているが、速さが0になった後の「走りの姿→待ちの姿」の混ぜで足が18cm以上動く（走りのどの位相からでも、待ちの足の位置まで18cm以上ある。歩きなら5〜7cmの位相がある）。止まりの最後の一歩の位相合わせ（§4・M2a）か脚のIK（M2b）で扱う。止まりは1m/秒を切ったら待ちへ混ぜ始める（0まで走りの姿で回すと、浮いた脚が0.3秒上がったまま止まって見えた。数値は同じ）。
- 捨てた案：止まりきる手前で歩きへ移す（出ていく走りの倍率が混ぜの間止まって、かえって流れた）。旋回の上限を走りだけ9のまま（速さで連続に下げる方が、Shift の押し離しで向きの速さが跳ばない）。
