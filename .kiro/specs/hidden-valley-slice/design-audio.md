# Design: 音（R15）

現行の `audio-valley.js` は、合成のみ・外部素材なし。ここには、足りない所の見立てと、直し方の判断だけを書く。
聴感は人の耳でしか確かめられない。数値は初期案で、本人の試聴で動かす。

## 足りない所の見立て（コードで確かめた）

1. **1音がノイズ1〜2個。** 足音は短いノイズ1発で、「ざくざく」の元になる細かい粒の重なりが無い。
2. **足音は歩いた距離で鳴る**（`actors.js` の `stepDist`）。足が着く瞬間とずれる。接地位相のデータは `anim-data.js` には無いが、`clips.json`（Blender の焼き込み）の `contacts` にあった。実際の骨の動きと照らして、データを物理的な2つの境界の間に収めたものを `anim-contacts.js` に置いた（`reports/audio/`）。
3. **地面は3種（草・土・砂利）。** 落ち葉・泥・石・板・水が同じ音になる。敵と仲間は常に草の音。
4. **同じ音を毎回鳴らす。** 揺らぎはノイズの乱数だけで、高さ・大きさ・粒の並びが変わらない。
5. **環境音が3つ（風・川・焚き火）。** 川と焚き火の距離減衰はあるが、植生・瀬・任務段階で構成が変わらない。

## 判断と、捨てた案

| 判断 | 理由 | 捨てた案 |
|---|---|---|
| 第1段階は合成のみ。足音を「衝撃＋粒＋布」の層で作る | 研究では、固い面は衝撃と共鳴、砂利のような粒状の面は粒の集まりで作る（Nordahl・Turchet）。外部素材のライセンス確認が要らない | 最初から録音素材を大量に足す |
| 録音素材は、第1段階を本人が聴いて足りないときだけ足す（3MiB以内・CC0・1ファイルずつ確認） | 足音の素材は、CC0とCC-BYが混ざっている（OpenGameArtの足音集はCC-BY 3.0）。確認の手間と表記の義務が増える | 出所の確認なしに置く |
| 足音は動作の接地位相で鳴らす。位相は動作ごとに事前に測り、データにする | 歩幅の距離で鳴らすと、足の着く瞬間とずれる。Cookの歩行分析も、歩調・左右差・踵とつま先の接地を測って組む | 実行時に骨の高さで検出する（再生速度の変化に弱く不安定） |
| 何を鳴らすか（面・変種・揺らぎ・連続回避）は純粋関数 `audio-rules.js`、音を作るのは `audio-valley.js` | 選ぶ規則だけをNodeで検査できる。音そのものは耳で確かめる | 全部を `audio-valley.js` に書く（規則を検査できない） |
| 足音の大きさと発見の距離を、同じ表（`config.js`）から出す | 走り＞歩き＞屈みの順が、耳と遊びで一致する | 音と発見を別々に調整する |
| 機械学習の合成は使わない | 依存と容量が増え、再現できない | — |

## 足音の作り（面ごとの表は初期案。試聴で動かす）

一歩 = ①接地の衝撃（短いインパルスを共鳴フィルタに通す）＋ ②素材の粒（極小のバーストを40〜140msに散らす。数・帯域・減衰・ばらつきが面ごと）＋ ③布と装備（低域通過ノイズ。兵は金属の小粒）＋ ④体重（180Hz以下の低い成分）。

| 面 | 衝撃 | 粒 |
|---|---|---|
| 土の道 | 中・低め | 細かく少なめ |
| 草 | 弱い | 湿った擦れ（薄い・2〜5kHz） |
| 砂利と河原 | 弱い | 多く明るい（3〜8kHz）・長め |
| 落ち葉の林床 | 弱い | 疎で大きく乾いた（4〜9kHz）・ぱりぱり |
| 板（縁側・橋） | 強い・空洞の共鳴 | ほぼ無し |
| 石（石段・岩） | 硬く短い | 高域のカチ |
| 浅い水と泥 | 低い水の音 | 泡のような粒 |

面の判定は `surfaceAt`（草・土・岩・河原・泥・落葉）に、建物の足跡（板）・石段の位置・`waterAt`（浅瀬）を足す。
歩き・走り・屈み・着地・転がりで、大きさと密度を変える。左右の足で、高さと粒の並びに差を付ける。
敵・仲間・村人は、役割で重さを変える（軽い鎧・重い鎧・草履）。距離で高域を落として小さくし、定位させ、22m先では鳴らさない。

## 選ぶ規則（`audio-rules.js`・純粋）

`pickStep({surface, gait, role, foot}, rng, last)` → `{recipe, pitch, gain, seed}`。同じ組み合わせを続けて返さない／揺らぎは範囲内（高さ±6%・大きさ±2dB）／
`noiseRadius(gait)` は `config.js` の表（走り11m・歩き5m・屈み1.5m）を返し、`gain` と同じ表から出す。効果音の変種も同じ規則で選ぶ（直前と同じ変種を続けない）。

## 効果音・環境音・ミックス

- **効果音**：刃・命中・受け・弾き・被弾・倒れ・弓・矢を、2層以上（衝撃・響き・体）に作り直し、変種を3種以上。当たった物（鎧・肉・木・岩）で響きを変える。重い一撃は低い成分を足す。上限で止めるときは古い音を短く絞る。
- **環境音**：風は樹冠の葉ずれを木の濃さで足す。川は距離と瀬で。秋の虫は草地の近く、烏は b2、里の生活音（桶・戸）は里の中。ループは粒の位置をずらして継ぎ目を消す。
- **ミックス**：バスを環境・足音・戦闘・UIに分ける。戦闘と会話の間は環境を下げる。設定で効果音と環境音を別にする。リミッターは残す（`regress-audio-levels.mjs` を拡張）。

## 接地通知の契約（未実装）

- charactersは実際のAnimationActionの時刻を、速度変更・ヒットストップ反映後に観測する。
  前回から今回までに通過した接地を `{actor, clip, loop, foot, contactTime}` として通知する。
  左右の位相を記録するだけでなく、周回数を含む単調な時刻で区間の全接地を列挙する。
- 混合中は実効weight最大の移動クリップだけを発音元にする。同率は移行先を選ぶ。
  発音元の変更時は現在の再生時刻を起点にし、過去の接地を追いかけて鳴らさない。
  `(actor, clip, loop, foot)` の通知を一度だけ消費する。停止・空中・非移動中は鳴らさない。
- 休止・再開・時刻の飛び・画面外からの復帰では前回時刻を捨て、遡及発音しない。
  22m内の接地観測は表示の15Hz間引きと分け、60Hzで進める。
- 許容差は可聴開始と表示の接地の差≤33.3ms（2×1/60秒の未測定の設計目標）。
  ブラウザでAction時刻・接地通知・予約時刻を記録し、出力時刻との対応も測る。
  getOutputTimestamp等で出力遅延を対応づけられなければ、同期は未確認とする。
  歩き→走り→屈み、周回、混合、速度変更、ヒットストップ、停止、休止復帰で欠落・二重通知0。
  接地位相と見た目の一致は本人が動画と音で確認する。静的データの一致だけで合格にしない。

## 同時数と解放（未実装）

- 28は一歩・一打など1回のplayが作る「声の束」の数。層や粒は束の子で個別には数えない。
  フェード中も数える。環境ループは別枠で種類ごと1束、R15.7の7種まで。全声ピークには含める。
- 優先順はUI/会話合図＞主人公の戦闘＞他者の戦闘＞主人公の足＞他者の足。
  上限時は同順以下で最古の束を10msで絞り、その終了後に新しい束を開始する。
  対象が無ければ拒否。同順位は古い束を優先して止める。待機枠も28以下で満杯なら拒否する。
  10msは急な切断音を避ける未測定の初期値。成功は実際に予約された開始として数える。
- 最後の子音源のonendedと響きの末尾の完了で束を解放する。全ノードを切り離し、登録を消す。
  停止・ミュート・破棄でも待機予約と全音源を止めて解放。固定1.8秒の壁時計待ちは廃する。
- ブラウザの上限試験：空状態で29束を要求し、他者の足28束の成功とUIの置換成功を確認する。
  active≤28・待機≤28、優先順・古い順を守り、拒否数と成功数と終了後の登録0を照合する。
  UI28束で満杯にして他者の足を要求する試験は、成功28・拒否1。待機満杯の拒否も検査する。
- 全声ピーク試験：試験用に上限だけを外し、全種類Nを2回ずつ開始して成功数=2Nを要求する。
  環境7種も鳴らし、リミッター後の全標本を測る。上限による欠落でピークを低く見せない。

## 検証

- Nodeの規則、OfflineAudioContextの測定窓・seed・RMS・重心・粒数・ピークは design-validation.md。
- 連続回避と音量順の変異で落ちること。聴感は本人が確認する。評価役は実行時の計画で決める。

## 決定（2026-10-27）

- 決定（2026-10-27）：合成から始め、本人が試聴して不足と判断したときだけCC0録音≤3MiB。最初からの録音追加は避け、採用時に容量を再検査する。
- 決定（2026-10-27）：里の生活音は桶と戸。鶏は含めず、暮らしを伝える物音を里の場面で試聴する。

- 7.5決定：予約はミリ秒・単調時刻、待機束への置換はその開始から10ms後へ連鎖する。予約済みの枠は早期解放後も後続開始まで保護する。純粋規則のAPIと初期値はdesign-contracts.md、実音への結線は7.6・7.7。
- 7.5のピーク検査定数は0.98。これは初期の検査上限で、既存合成の出力を測定・変更したものではない。
