`design-locomotion-smooth.md` §7 の続き。要件 R37（カメラ）・R38（計測と盲検）・R39。
実装 `dist/valley/camera-follow.js`（式・純粋）・`camera-rig.js` の `updateSmooth`、物差し `tools/lib/smooth-metrics.mjs` の `cameraView`、回帰 `regress-locomotion-camera.mjs`。
結果と数値は `reports/polish3/locomotion-smooth/m4.md`。

## 1. 先に測って分かったこと（M3 の main・変える前）
- 平地の台本では、カメラはすでにかなり滑らか（L0 で注視点が臨界減衰のばね ω18/12 になっている）。止まりでカメラの減速の最大は約24m/秒²（主人公は47）、回転は視点を回したときしか動かない。
- **一番ぎこちないのは壁際**：家の角を走り抜けると、遮蔽で1コマに1.26m 寄る（加加速度の最大 51万m/秒³・画面の主人公が1コマで大きく動く）。寄せは即時、戻しは1次の遅れ（戻り始めに速さが折れる）。
- 次は**段差**：棚田の段0.55mで、カメラの上下の加速度が31m/秒²（画面全体が上下に揺れる）。土手の斜面では、地面からの下限（0.55m）の `max` が効き始めるコマで上下の加速度が81m/秒²の1コマの折れ。
- 台本の要約の p99（239.8）は、視点を回し終えた直後の3コマの窓（区間名は run3）が決めていた。物差しを直して、外す区間に触れる窓を除く `posJerkP99Clean` を足した（M3 の main で 209.5）。
- 台本の p99 は「上位8コマ目」で、止まりの山（上位10コマほど）の縁にある。1つの値だけで判断せず、止まりの山の最大（287）も並べる。

## 2. 決めたこと
- **見た目のカメラだけを変える**。向き（yaw・pitch）は操作のまま遅らせない（移動の向きは `rig.yaw` から作るので、遅らせると論理の位置が変わる）。狙い固定の向きの寄せ・戦闘中の自動の向き・演出のカメラ（`camOverride`・`applyCine`・オープニング・章末）は触らない。論理（位置・向き・速さ・歩容・接地）は762コマすべて M3 と同じ。
- ① 注視点の水平：ω15 のばね＋ならした速さ（ω8）×0.03秒の先回り。走り5m/秒の遅れは M3 と同じ約0.52m で、止まりの加加速度の山が287→248。
- ② 注視点の上下：ω20 で一度ならしてから ω12。棚田の上下の加速度 31→15m/秒²。
- ③ 遮蔽：今のコマの線に加え、0.4秒先（ならした速さでずらした注視点とカメラ）の線でも当たりを見る。目標を ω30 でならし、寄せは ω20・戻しは ω7 のばね。**今のコマの当たりより外へは出さない**（壁の中は映さない。先回りが外れたときだけ残りを即座に寄せる）。止まっている間は先回りの線を引かない。
- ④ 持ち上げ（壁際で上へ逃げる）も速さの続くばね（上げ ω28・下げ ω6.3）。地面からの下限0.55m は折れ目のない最大（log-sum-exp・幅0.12m）。下限は常に守る。
- ⑤ 画角：ならした速さ 3.2→5.0m/秒で 0→+3度（smoothstep）。上げ ω4・戻し ω3。「画面の揺れ・衝撃」の倍率を掛ける（0なら広げない）。「動きを減らす」・狙い固定では広げない。
- 切替 `?smooth=camera`（`?smooth=off`・`?loco=old` も）で M3 のカメラ（`updateLegacy`。書き換えていない）。記録の指紋 07ae29a12b76ffb9 が main と一致。
- ばねはすべて厳密解・毎コマの新規確保なし（先回りの線の端点は使い回す）。先回りの線は動いている間だけ1本足す（rayClip 1回）。

## 3. 物差し（悪く見える現象そのもの）
- `cameraView`：主人公（論理の位置の1m上）をそのコマのカメラで画面へ写した点の、区間ごとの範囲（流れ）・1コマの最大の動き、カメラの高さの加速度、画角の変化の速さ。**「遅れを増やして滑らかに見せる」逃げ**を、画面の流れが増えないことで止める（M3 の轍：実装の値を測るだけの物差しにしない）。
- 回帰の門番は、実際の手順で不具合を再現してから、わざと戻して失敗することを確かめた：先回りを切る→壁の角で1.18m の跳び、上下を1段に戻す→棚田で上下の加速度31、画角が揺れの設定を読まない→揺れ0で+3度。

## 4. 捨てた案
- 注視点を ω15 だけ（先回りなし）：加加速度は下がるが遅れ0.63m（主人公が画面の奥へ流れる）。ω14＋先回り0.05：差が小さく、先回りが大きいほど止まりで行き過ぎに近づく。
- 2段のばねを水平にも：同じ遅れで加加速度がほとんど下がらない（主人公の加減速そのものが山を作る）。
- 目標がコマの間に一定の速さで動くとして解くばね：30・60・144コマ/秒の遅れの差（約7cm、M3 も同じ）が0になったが、台本の止まりの加加速度が約10%上がった（1コマ分のならしが消える）。コマ速度の差は許容（回帰で0.08m）とした。
- 遮蔽の寄せを1段の ω24：先回りで目標が段で変わる瞬間の加加速度が、2段（ω30→ω20）の約4倍。先回り0.3秒では寄せきる前に今のコマの当たりへ追いつかれることがあった。
- 上下にも速さの先回り：斜面の遅れは少し戻るが、段差で7cm行き過ぎる。
- 地面の下限をばねで追う：下限を守れない（潜る）。折れ目のない最大なら守れる。

## 5. 残る癖と落とし穴
- 上下を2段にした分、段差・斜面で主人公が画面の上下に流れる量が1〜2割増える（棚田 0.18→0.21、土手 0.67→0.77）。画面全体の揺れ（加速度）を半分にする代わり。本人の試遊で見てほしい。
- 土手の斜面の始まりは、M3 から主人公の腰が画面の下端近く（壁際で上へ逃げて頭を見る構図）。今回は滑らかさだけを変え、構図は変えていない。
- 同じページで `?smooth=camera` と切り替えると、画角が0.01度以内の差では投影を更新しないので、前の版の画角が最大0.01度残る（回帰の許容0.02度）。
- 台本の p99 は止まりの山の縁にある（上位8コマ目）。印が1コマずれると値が数十変わるので、山の最大と並べて読む。
