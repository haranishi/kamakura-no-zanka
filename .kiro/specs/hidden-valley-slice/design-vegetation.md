# Design: 草と木（R14）
現行の植生（`vegetation.js`・`scatter.js`）は、形も葉の絵も手続きで作る。ここには、足りない所の見立てと、直し方の判断だけを書く。
数値は設計目標で、tasks.md の7.0で実測してから見直す。
## 足りない所の見立て（コードと測定で確かめた。原因は仮説。固定画角の比較で確かめる）
1. **草が少なく低い。** 候補の格子は0.55mごとで、斑の規則で間引くため、主要3地点の10m以内で1㎡あたり3.6〜5枚。高さ0.13〜0.30mは形の生成値（配置倍率0.8〜1.35）。標準は28〜46mで縮小して消える。足もとに地面の色が見える。
2. **遠景込みは杉87%・広葉1.6%。** 到達格子の645本では杉以外24.96%・広葉13.18%（research.md）。比率だけでは見た目の不足を判定できない。下草は1種。
3. **木が「葉のカードの束」。** canvasで描いた枝先を板に貼る作りで、近づくと樹冠が平らに見える。幹の枝と根張りが弱い。
4. **林床が一様。** 既存の落ち葉層（terrain-height.js・terrain.js）では不足する。立体的な落葉・針葉・岩や岸の苔を足し、道の縁の踏み分けを見せたい。
## 判断と、捨てた案
| 判断 | 理由 | 捨てた案 |
|---|---|---|
| 草は三段：近くは葉を一枚ずつ、中は株のカード、遠くは地面の質感に細部を焼く | 近くの密度だけ上げれば足り、遠くは安く済む | 全域に静的に高密度（100枚/㎡×約6万㎡＝600万枚。配列と生成時間が持たない） |
| 近景はカメラ周りの区画（近景1m角・中景2m角）だけ、区画の番号から決定的に作り、InstancedBufferGeometry を使い回す | 同じ番号は同じ絵になり、固定画角の前後比較が崩れない | 毎フレームGPUで全生成（WebGL2には compute が無い） |
| 区画の生成は、読み込み時に一度作る草の濃さ・高さの格子（1m）を読む。分割生成・行列更新・転送を部分予算内で進める | 数十msという遅延は未測定の見積もり。旧案の8m角は100枚/㎡なら6,400枚なので、一区画でも時間の上限にはならない | 区画に入った瞬間に全部作る |
| 木は樹冠を葉のカードの塊（ドーム）に束ね、頂点に内側ほど暗い「露出」を持たせる | 手本の講評でも、カードの散らしは「平たい紙の束」だった。塊にすると立体に見える | カードを増やすだけ（三角形が増え、平らさは残る） |
| 質感にCC0の写真（Poly Haven・ambientCG）を使ってよい。形は手続きのまま | 樹皮と葉の写真感が出る。出所を台帳に残せばライセンスは単純 | 外部の木モデルをそのまま置く（1本数MBで予算が持たない。他作品の見た目に寄る） |
| 樹種・色づき・空き地・大木は、低い周波数の場で決める | 近くの木が同じ色づきを共有し、群れと空き地ができる（一様乱数は紙吹雪に見える） | 樹種を一本ずつ乱数で振る |
| 後処理（被写界深度など）でごまかさない | 近景の粗さは変わらず、コマ時間だけ増える | — |
## 構成
- **草の葉（近景）**：3〜4節の細いリボン（幅2.2〜4cm、先ほど細く）。根もとの暗さ・先の明るさ・一枚ごとの色と曲がり。真横を向く葉は幅を広げ、画面で線に消えないようにする。
- **株のカード（中景）**：110葉の絵×3板を重ねた星形カード（`alphaToCoverage`）。距離で葉を間引きつつ幅を太くして、被覆を保つ。切り替えは葉ごとのハッシュで溶かし合わせる。
- **下草の種**：短い草・丈の高い株・ススキ（逆光の穂が効く）・シダと笹・花（畦の彼岸花など）。種・丈・空き地は低周波の場（value noise）で決める。
- **木**：杉の三段は残して枝ぶりを足す。広葉を2種足す（楓＝紅、欅＝黄）。若木と灌木を足し、道と里の縁に低い帯を置く。幹は曲線の管＋根張り＋樹皮。LODは3段（葉カードの塊→簡略の塊→一つの塊）を溶かし合わせる。
- **色づき**：広葉の紅葉と黄葉は場の値で段階づけ、近くで同じ段階を共有する。杉の塊は暗くしすぎず、黒い穴にしない（`design-app.md` の罠）。
- **風**：樹冠全体のゆっくりした揺れ＋外側の細かい震え。突風は、時間と位置の低周波ノイズで帯にして草地を渡らせる。向きの共有契約は design-contracts.md「風」。導きの風より先に固定する。
- **逆光の透け**：太陽と視線の内積で、葉と草の縁を明るくする（材質は Lambert のまま、シェーダーを一部差し替える）。
- **林床と道の縁**：落ち葉・針葉の敷きを木の下で濃く、道の縁に踏み分けと草の縁、岩と川岸に苔。地形の質感に重ねる（`terrain.js`）。
## 約束
- 乱数の系列は新しく足す（既存の `world.seed + seed*307` の系列は変えない）。既存の木・岩・稲の配置は、テストで同じであることを守る。
- 既存配置は `scatter.js`、草の場・区画生成は `grass-field.js` に置き、Three.js・DOM・乱数・時計に触れない。`vegetation.js`（view）は形と材質だけ。
- 見た目の調整値は `config.js` に集め、`?lk=` で試せる。

## 7.8 遠景の草地（2026-10-28。本人指定の方式）
- 25mで土の帯が現れるため、草の場から1mセルの被覆を作り、既存の草層の色・法線へ寄せる。配置可かつ密度>0の元値はround(255×clamp(.6+.4×密度/配置可セルの最大密度,0,1))、他は0。3×3平均を一回だけ掛ける。外は0、除数9を維持し、境界へのにじみは1セル。内部の合計はbyte丸め誤差内で保存、外縁では流出する。
- Red/byte・線形補間・clampのDataTextureを後から結線。原点はセル左下なので中心は(i+.5)/size（半セルを二重に足さない）。被覆なしは0、品質切替で共有し、差替えと材質解放で所有テクスチャを解放する。QA meadowCover()はnx/nzと0〜1のmean/maxを返す。
- uMeadow=.85。草w[0]を1へ寄せ、土・砂利・泥・落葉を1−k倍、岩w[2]は変更しない。追加は被覆参照1回、描画呼出・形状・配置・高さ・当たり・セーブは維持。範囲外の被覆は0。軽量でも共通の式とし、既存farMixと法線の品質制御を維持する。
- 同梱grass_c.jpg全画素の線形RGB平均は(.1581,.1191,.0492)、sRGB換算約#6f613f。中景#6b6a35より茶寄りのためuMeadowTint=#6b6a35を採用し、合成済albedoを被覆×.25×smoothstep(20,70,距離)で寄せる。照明前の推定であり、固定画角・GLSL・実機コマ時間は親の確認待ち。新素材は足さない。
