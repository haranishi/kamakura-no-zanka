# Design: 抜刀・納刀（タスク8.2・R18.1）の実測と採用方式

design-combat-presentation.md の「方式の候補」を、2026-10-30の実測で採否した記録と、採った方式の契約。数値の目標は**未測定の設計目標**（実測値は明記）。

## 実測：既存の動作は、腰の鞘と噛み合わない

主人公と兵の両方で、`Katana_Draw_v2`・`Katana_Sheathe`（各2.97秒）を60コマ/秒で再生し、握り（太刀の原点）と腰の鞘の枠の関係を測った（実ブラウザ・`tools/scenarios/measure-draw-sheathe.mjs`・前値は `reports/polish3/baseline/draw-sheathe-before.json`）。

| 項目 | 実測 |
|---|---|
| 握りが鞘の軸の近く（横ずれ5cm未満かつ軸の角度30度未満）にあるコマ | 抜刀 0/179・納刀 0/179（主人公・兵とも） |
| 握りが鞘の原点に最も近づく距離 | 抜刀 0.16m（1.53秒）・納刀 0.19m（1.82秒）。そのとき軸の角度は109〜117度 |
| 抜刀中の両手の間隔 | 1.8秒に0.22m→2.3秒に0.73m。「左手で鞘を持ち、右手で引く」撮り方で、腰に固定した鞘を想定していない |
| 腕の長さ（主人公・身長1.66m） | 上腕0.208m＋前腕0.222m＝0.43m（骨から骨）。右肩から腰の柄まで0.51m、軸の逆向きに0.76m引いた点まで0.78m。右肩と鞘の軸の距離は0.49m |

画像は `reports/polish3/baseline-draw-sheathe/`。抜刀は手を背中側へ回してから腕を前へ伸ばす動きで、刃が鞘口を通るコマが無い。

## 判断と捨てた案

| 判断 | 理由 | 捨てた案 |
|---|---|---|
| 既存動作の手と鞘口で受け渡す案（第一候補）と、1コマの付け替え案は採らない | 0/179コマ。付け替えに足る連続した点も無い（最接近16cm） | 付け替えを光や画面の揺れで隠す案 |
| **実行時の層で、刀を鞘の曲線に沿って滑らせる** | 刃が鞘口を通ることを、定義から保証できる。歩きながらでも重ねられ、入力を待たせない | Blenderで7人分の動作を作り直す案（容量と出所の確認が重い） |
| 右手は腕の二関節IK。届かない分は、鞘を帯の中で後ろへ引く（最大0.22m）・上体のひねり（最大35度）・肩甲骨を前へ出す（最大40度）で補う | 腕が短く、刀身0.72mを引くには、腕だけでは届かない | 腕だけで引く案（届かない） |
| 手の向きは、刃を上へ振る球面の曲線で混ぜ（`swingBlend`）、前のコマの結果に沿って連続させる（memo） | 抜いた直後（刃は後ろ向き）と構え（前上向き）はほぼ反対向きで、最短の弧は、反対向きに近いところで1コマに半回転する。**どんな2つの向きでも連続な混ぜ方は存在しない**ので、短い側と長い側を計算し、前のコマに近いほうを採る（使用範囲の400構成すべてで、memoなしは約90度跳んだ） | 球面線形補間（不連続）、弧の向きを覚えて固定する案（それでも跳んだ） |

## 契約

- **刀は1本の物体**。u=0（納刀）では腰の柄と重なり、u>0では動く刀が柄を兼ねる（腰の柄を隠す）。s=0〜0.74mは鞘の円弧（半径約4.23m・最大約10度回る）に沿って滑り、s≥0.712mで刃が鯉口を抜ける。
- **鞘への収まり**：刃の断面（幅31→22mm・厚み7.5→5.2mm・先端は絞る）が、鞘の管（半径22.5mm）の中に0.5mm以上の余裕で収まる（実測の余裕5.7mm）。中心線の差は、鞘と刃の反りの形の違いで静止時に既に5.9mmあり、滑らせても1.5mm以上は悪くならない（最初に書いた「5mm以下」は、収めた姿勢でも成り立たないので、この2条件へ直した）。
- 握りに対する手首の誤差は、IKの重みが1の間15mm以下。腕の骨の長さは変えない（1mm以下）。
- 時間割（進み具合uの区間は reachEnd 0.30・pullEnd 0.68。実ブラウザで調整した値）：落ち着いた抜刀 0.62秒・納刀 0.70秒。攻撃・受け・闇討ちが先に来たときは、現在の進み具合から**0.15秒以内**（引く区間0.07秒＋振る区間0.07秒。振る区間を縮めすぎると、刃の半回転が2〜3コマに詰まって刀が飛んで見える）に抜き切る。最初の攻撃の予備動作0.17秒に間に合い、攻撃の開始は遅らせない。納刀中の再警戒・攻撃・受けは、納刀を**始めた同じコマでも**取り消して手へ戻す（以前は、u=1のまま拒否して、攻撃しながら納刀を続けた）。
- 左手は、鞘を持つ位置へ。鞘が帯へ戻るまで添える。鞘は、刃を引き始めてから後ろへ引き（u=0.40〜）、刃が鞘の軸を離れ始めるころ（u=0.74〜）から帯へ戻す。先に引くと刀が一度後ろへ戻って見え、戻すのが遅いと、鞘が体から離れて浮いて見える。
- きっかけ：敵が主人公に気づいた時点（`alertedEnemies()>0`で未抜刀）に落ち着いた抜刀。現行の自動納刀の条件を満たしたときに落ち着いた納刀。攻撃・受け・闇討ち・とどめを未抜刀で始めたときは速い抜刀。抜刀の前半（u<0.6）は腕を下げた平時の姿のまま、後半から構え（guard）へ。
- 音は、刃が鞘口を抜ける瞬間（`draw`）と、鍔が鯉口に収まる瞬間（`sheathe`）に出す。音の作り直しは7.7。
- `combat.js`の時間割・ダメージ・入力は変えない。層は見た目と刀の置き場だけを動かす（R18.9）。
- 動作が毎コマ書き直さない骨（手の骨）に後処理が残らないよう、触った骨は次のコマの最初に元へ戻す。死亡・演出中に入ったときは、途中の層を適用し続けず、論理が向かう側（抜く→抜いた、納める→納めた）へ確定する。
- 対象は主人公。敵は最初から抜いた姿で出るので、この層は使わない（敵の刀の形は8.6）。

## 構成

純粋層（Node）：`sword-path.js`（鞘の曲線・刀の姿勢・向きの混ぜ）・`arm-ik.js`（二関節IK）・`sword-layer.js`（進み具合・要求の受理・通知）。見た目の結線：`sword-rig.js`（骨・鞘・刀）。きっかけ：`actors.js` の `HeroActor`。

## 合否と、2026-10-30の実測

1. 純粋層：単体試験と変異試験（33件すべて検出）。向きの混ぜは、実際に使う範囲の2000組で、1コマ（h=0.01）の回転が0.12rad未満。相対回転が180度をまたぐ列でも、memoがあれば連続（memoなしは跳ぶことも試験で確かめる）。
2. 実ブラウザの毎コマ測定（`tools/scenarios/regress-draw-sheathe.mjs`・9場面）：握りの誤差 静止0.0〜2.5mm・歩き中13mm以内、刃の収まり余裕5.7mm、刀・右手の位置と向きの「1コマだけ跳ぶ」は隣の動きの3倍以下、腕の長さの変化0.03mm以下、表示の食い違い0、骨の戻りは1e-7rad以下。
3. 実ゲームの主人公を通す検査（`regress-draw-sheathe-game.mjs`・7場面）：論理と層の食い違い0。納刀を始めるコマの攻撃入力・抜く途中の死亡・やり直しは、過去の実際の不具合を戻すと検出できることを確かめた。
4. 論理（`regress-attack-timing.mjs`）：同じ入力列320コマで、主人公の状態・技と位相・敵の動きが変更前と一致（攻撃の開始は20・83・252コマ目で同じ。入力を捨てる変異は検出する）。層は `combat.js` を呼ばず、`fighter` の状態を書かない。
5. 目：ラボとゲームの前後のコマ割り（`reports/polish3/draw-sheathe/`）。**別のモデルの盲検採点は実施**（新しい版が12の比較すべてで上。ただし7点に届くのは「刃が鞘口を通る読み」だけ）。**本人のプレイでの確認は未実施**（8.2c）。手が柄を握らない（人物の指が開いたまま・Issue #10）ことは、この層では直せない。
