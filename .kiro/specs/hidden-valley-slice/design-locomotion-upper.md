# 走り・歩きの滑らかさ M3「走りの形」の設計（2026-11-04）

`design-locomotion-smooth.md` §6 の続き。実装 `dist/valley/upper-body.js`（式・純粋）・`upper-rig.js`（骨へ当てる）、物差し `tools/lib/upper-metrics.mjs`。
結果と数値は `reports/polish3/locomotion-smooth/m3.md`。要件 R36（走りの形）・R38（盲検）・R39。

## 1. 原因（調べて分かったこと）
- 腕：走り（CMU_Run）の腕は反対側の太ももと既に同期している（相関0.98・位相差0）。それでも上腕は真下より後ろ（−48〜+2度・平均−25度）でしか振れず、肘を深く畳んだ前腕が胸の前に残る（手の前後の行き来20〜25cm）。relaxArms・刀・握りの層は腕を変えていない（最終の姿勢＝mixer の姿勢）。
- 体幹・頭・腰：骨盤が胸と同じ向きに回る（相関+0.57。人は逆向き）。頭は左右7.6度・上下4.6度揺れる。腰の上下8.3cmは、走り5m/秒で歩調を1.72倍にして回すので、同じ弧が約3倍の重さで跳ぶ（弧の高さは周期の2乗に比例）。
- どれも手続きの層で直せる範囲なので、再収録はしない。

## 2. 層の置き方
- 順：mixer → この層 → 脚のIK → 刀 → 握り。骨盤の上下は脚のIKの中で腰だけを動かす（足の目標は動作の足首の高さのまま決めるので、足は浮かない）。
- 効くのは脚のIKを使う人（主人公と24m以内の近い8人。軽量は主人公だけ）の、移動の動作の間だけ。技・回避・受け・抜納刀・両手持ち・屈み歩きでは効きを0へ戻す（25/秒）。刀・弓を持つ腕は0.35倍。敵は構えで左手が武器を握る間は自動で切れる（実測：兵は効き≒0、侍大将は走り出しの一瞬だけ0.8まで入り1秒以内に消える）ので、主な効き先は主人公と味方。
- 前のコマの補正は undo で戻してから重ねる（二重加算の禁止。回帰で、戻した骨と mixer 直後の姿勢の差 2e-16）。毎コマの新規確保をしない。ばねは厳密に解くので、30・60・144コマ/秒で同じ曲線。
- 切替：`?smooth=arms` で M2b。脚のIKの更新の分け方に乗るので `?smooth=ik` でも戻る。「動きを減らす」は振り幅を0.35倍（骨盤の下限は0.8倍）。

## 3. 中身
- 体幹の逆回転：胸を脚の位相から決めた目標（−0.2×（右の太もも−左）/2 度）へ、骨盤を＋0.18×（右−左）/2 度へ寄せる（揺れの成分だけ）。腰を回すときは太もも・背骨を逆に回し、腰の形だけを動かす。
- 頭：進む向きから見た頭の向きを、4/秒でならした向きへ0.8寄せる（揺れを打ち消す）。前傾：速さ（3m/秒を超えた分×1.3度）と加速度（10度×tanh(a/10)）をばねで遅らせる。曲がり：atan(横の加速度/g)×0.2（上限8度）を上体だけで見せる。骨盤の上下：弧を clip/ts² へ縮め、下限6cm。
- 腕（後ろへ引く側だけ）：反対側の太ももが後ろにあるときだけ、gain（0.2→0.3、速さ2→5m/秒）×太ももの角度を、減衰の弱いばね（ζ0.35）で後ろへ足す（`backOnly`）。前へ出る腕と肘は収録のまま。上腕は −48〜+2 → −62〜0度、手の前への出（19cm）と肘の曲がり（77〜125度）は M2b と同じ。
- 手の安全装置（`handBack`・`UPPER.hand`）：肩から見た手が、首の関節−5cmより高く・前へ27cmより出たら、腕を肩の軸まわりに後ろへ戻す（log-sum-exp でなめらかに）。通常の走り・歩きでは効かず（M2b の最高は首−5.9cm・前へ19cm）、はみ出したときだけ抑える。
- 止まりの腕：効きを速さ（1.5m/秒で満）と減速（−20m/秒²で0）でも弱め、ばねの減衰を強く（ζ0.9）、上腕の前への傾きを動作の角込みで24度まで。待ちの姿へ混ぜる間に、動作の腕が前へ上がって水平に突き出たため（撮影で確認）。

## 4. 決め方と捨てた案（盲検＝画像だけの Opus 採点役3人、場面ごとの A/B は伏せて入れ替える）
- 初版（腕を前へも振る：offset 10→17度・gain 0.16→0.30・肘を12度伸ばす）は、振り幅・同期の物差しでは目標を満たした（45→71度・相関0.99）が、盲検で54件中 新3・旧19（総合−0.31点）。前へ出た手が首・顔の高さまで上がる／前腕が立つ／曲がりで腕が頭より高く跳ねる、が3人とも繰り返し指摘された。
- 手の高さに上限を付けて肘を20度伸ばした修正版は54件中 新0・旧20。手のひらを開いて前へ差し出す形が「棒のよう」で、採点役が好んだのは M2b の「肘を畳んで胸の前」。同時に「後ろへの振りが小さい」とも指摘された。
- そこで前へ出る腕は M2b のまま、後ろへ引く側だけ増やした（V1）。V1・「腕は M2b のまま体幹だけ M3」（V3）・旧の3版を横カメラ9場面×3人で採点：27件すべて同点（見分けがつかない）。悪化はなく、良くなった証拠は画像では示せない。
- そのほか捨てた案：胸を「骨盤の回り×−0.45」へ寄せる（動作の骨盤の回りが±4度と小さく偏り、胸がほぼ止まった）。骨盤の上下を層の中で腰を動かして作る（足が一緒に浮いた）。

## 5. 落とし穴
- **振り幅と同期の物差しは、設計どおりに動いた証拠にしかならない**（物差しと実装が同じ定義）。初版は手が顔の高さまで上がっても目標を満たした。見た目は盲検で決め、手の高さ・前への出の物差し（`handPose`）を足した。
- 撮影の上書き（腕のパラメーター）を、ページの準備の前に当てると、準備の再読み込みで消えて全版が同じ絵になる（V1・V3・修正版が画素で同一だった）。準備の後に当て、新旧の画素差が0でないことで効きを確かめる。
- 同じページで台本の直後に測ると、1回目は前の状態を引きずる（頭の揺れが2.6度と1.1度に分かれた）。回帰はどの通りも1回空で流してから測る。mixer.update(0) を当て直して「元の姿勢」を作る比べ方は使えない（移動の切り替えが mixer の後に重みと時刻を替える）。
- 追従カメラ（プレイヤーが普段見る向き）は人物が小さく、腕の差はほとんど見えない。初版の手の跳ね上がりだけは見えた（27件中、旧が良い6件）が、修正版は27件すべて同点だった。V1 の採点は、差が読める横カメラだけにした。
