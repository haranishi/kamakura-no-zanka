# Design: オープニング（約1分・語りと絵のような場面）と燃える鎌倉の場面（S2・S3）

requirements-story.md の R22・R23 を、作れる形に落とす。本人の決定（2026-10-30）：語りと絵のような場面（約1分・字幕・飛ばせる）、最初に作る舞台は燃える鎌倉、語りは古い絵巻の語り口、絵の方向は商業大作寄り、動画でなくゲームの中で動かす。
**語りの文は案（本人の確認前）**。数値は未測定の設計目標。2026-10-30にCodexが草案をコードと突き合わせ、舞台の置き方・語りの表示先・保存の3点を直した。

## 1. 語りに使ってよい史実と、使わない言い方（Codex調査。出典は§8）

使える：①元弘三年五月、新田義貞らの攻撃で鎌倉幕府は滅亡した。②攻防は数日に及び、五月二十二日に決着した。③東勝寺で北条高時ら一族が自害し、寺は焼失した。④幕府の存続は「およそ百五十年」と言える。⑤同年六月、後醍醐天皇の新政が始まった。
使わない：「一日で終わった」（誤り。数日の攻防）。「鎌倉は燃え落ちた・町全体が焼けた」（確認できたのは東勝寺の焼失。発掘成果から、全体の灰燼化には疑問がある）。時行の潜伏先の断定（諏訪市の資料も不明とする）。
→ 場面も、町全体が焼け落ちた姿にしない。燃えるのは寺と数棟の家、逃げ道のまわりだけ。

史実の画面（1〜3）は生成りの字、創作の画面（4〜6）は朱の字にして、創作と分かる形にする（R19.4）。暗い背景で4.5:1以上を測る。

## 4. 場面の設計（R23）

色は朱（炎）・墨（影）・生成り（空の明かりと字）に絞る。ただし材質と光は、本編と同じ商業大作寄りの作り込みにする（平たい絵にしない）。朱の面積は画面の約2割以下（R23.3。未測定の目標）。写実的な傷口・遺体は出さない。
- A 燃える通り：家（farmhouse・naya）3〜4棟のうち2棟が燃える。倒れた無地の旗（旗印は架空。実在の家紋は使わない）。カメラは低く、奥へ約4m、9.5秒でゆっくり前進。
- B 燃える寺：temple.glb を炎が包む。石段の下から見上げる固定。火の粉が上る。寺の名は語りにだけ出す。谷の廃寺と同じ部品なので、「燃えた寺」と「廃寺」が重なって見える（意図した対）。
- C 橋を渡る影：bridge.glb。人物モデルの複製を暗い単色＋縁の光にして歩かせる（子ども・老人・武士）。逆光。横から固定し、わずかにパン。
- D 山道の見返り：景継（hero.glb の複製）の後ろ姿。遠景に煙の筋と赤い空の帯。肩越しにゆっくり寄る。最後に前を向いて歩き出す（顔は見せない）→暗転。

## 5. 実装の方針

- **舞台は、谷とは別の `THREE.Scene` にする**。`post.render(scene, camera, dt)` は任意のシーンを受けるので、オープニング中だけ舞台を描き、谷は描かない。霧・空・影・環境反射を舞台専用に持てる。**捨てた案**：谷から離れた座標（x=2000）に置く案。既存の地形が遠景でも半幅640m、`applyCine` が谷の地形高を足す（(2000,0)で約110m）、影が谷の主人公を追う（±46m）、遠景山が半径1050〜1950m、で衝突するため。
- 資源の持ち主：建物・人物のモデルは、起動時に読み込んだものの複製を使う（`models` が main.js の局所変数なので、舞台へ渡す経路を決める）。舞台専用の資源（炎・煙・火の粉・光・旗）だけを、終わったら dispose する。共有モデルの geometry と material は dispose しない。本物の主人公は動かさず、Dの景継は複製を使う。
- 構成：`opening-data.js`（語り・時間割・カメラ・色。data層）、`opening.js`（進行の状態機械。純粋層。入力は dt と飛ばす操作、出力は画面・字幕・カメラ・暗転・終了）、`opening-stage.js`（舞台・炎・煙・火の粉。view層）。`game.js` の `startIntro()`・`updateIntro()`・`setCine()` に結線し、いまの目覚めを最後の区間として残す。炎・煙・火の粉は、既存の粒子（fx.js）と加算の板で作る。実際の光源は2つまで。
- **語りの表示先**：HUDの外に、専用の枠（`#narration`）を足す。既存の字幕は、HUDの子で、イントロ中は隠れ、字幕の設定がOFFなら描かれない。語りは設定に依らず出す（唯一の説明のため）。
- 飛ばす：E・Space・クリックで、いま以降を飛ばし、0.6秒で暗転→目覚め（開始から0.6秒は効かない。既存と同じ）。
- **`openingSeen`**：進行の保存とは別のキー（例 `kamakura.valley.meta`）に持つ。「はじめから」は進行の保存を作り直すので、同じ保存に入れると消える。オープニングが終わる（または飛ばした）時点で書く。読めない・無いときは初回。
- 設定：「動きを減らす」ではカメラ移動を止め、クロスフェードの静止画にする。炎のちらつきは1秒に3回以下。揺れ0・音なしでも読める。

## 6. 性能・読み込み

新しい素材は使わない（寺・橋・家・人物は谷のモデルの複製）ので、初回の読み込みは増えない（14.9の90MiBを守る）。舞台の間は、標準p95≤20ms・描画呼出≤300・三角形≤150万を目標にする（未測定）。商業大作寄りの作り込みは、近景（A・B）に集め、C・Dの遠景は軽くする。

## 7. 検証

純粋層の単体試験と変異試験：合計45〜75秒、各文が40字以内、飛ばす・短い版・続きからの経路、時計と乱数に依存しない。実ブラウザ：場面A〜Dの固定画角（O1〜O4）、飛ばす経路、短い版、続きから、旧保存、やり直し、字幕OFF、休止からの復帰、再上映。既存のQAの `intro=0` を保つ。新しい純粋モジュールは `tools/check-valley.mjs` の検査対象へ足す。別役（Opus）の盲検採点（R17の画づくり・語りの読み）。最後に本人が通しで見て、長さと飛ばしやすさを確かめる。
