# Design: オープニングの実装（S3・S4）— 実測・採用した方式・捨てた案・契約

design-opening.md（R22・R23）を実装に落とすときに決めたことを残す。数値は特記のない限り、M4 Pro・Chrome（ヘッドレス）・1280×720・DPR1・標準品質の実測。

## 1. 実装の前に測ったこと

- 谷を目覚めの画角で描くと、描画呼出434・三角形315万。遊びに入った直後は707〜710・393万で、1コマ約14.3ms（readPixelsでGPUの完了を待つ測り方）。
- 別の THREE.Scene に寺・農家・主人公の複製を置いた試しは、呼出43・三角形11万・定常1.4ms。ただし最初の1コマに543msかかった（材質の組み立てと画像の送り込み）。
- installFog は霧の断片を差し替えており、霧の色は `fogColor` を使わず、谷の空気遠近の色（青灰と暖色）で決まる。谷が使う霧は FogExp2 だけ。

## 2. 採用した方式

- **進行は純粋層**（`opening.js`）。`stepOpening(state, { dt, skip, reduced })` が新しい状態・見え方・出来事を返し、入力の状態は書き換えない。出来事は skip・cut・seen・wake・getup・done の順に出る。時計と乱数を使わない。
- **データ**（`opening-data.js`）：語り6画面（id・文・史実／創作）、通常版と短い版の区間と語りの時刻、目覚めと飛ばしの時間、暗転と溶け合いの長さ、題名と注記、字と帯の色。文は design-opening.md の案から変えていない。
- **舞台は別シーン**（`opening-stage.js`）。カメラも舞台専用。`game.render` は舞台があれば舞台だけを描き、谷は描かない。場面A〜Dは互いに離れた組に置き、見せるのは1組だけ。光源は鍵の光と炎の光の2つで、場面が替わるたびに置き直す。環境光は空の色から作った反射の絵を使う。
- **温め**：最初の暗転の4コマで、場面B・C・D・Aを1コマずつ描く。材質の組み立てを暗転の下で済ませ、場面の切り替えで止まらないようにする。
- **場面の溶け合い**：`post.js` に「前の1枚を残す」仕組みを足した。仕上げを8bitの絵へ描いてから画面へ写し、場面が替わった瞬間（cut）に直前の1枚を残して、1.0秒かけて薄くする。残した1枚は、画面の大きさが変わっても捨てずに引き伸ばして重ね、溶け終わったら返す。絵を持つのはオープニングの間だけ。
- **霧**：線形の霧（THREE.Fog）は舞台だけが使う。線形のときは `fogColor` の一色にし、谷の霧の帯もかけない。FogExp2（谷）の式は変えていない。
- **語りの枠** `#narration`：HUDの外に置く。重なり順は z-index 28 で、#fade（30）の下。上下に不透明の帯（#05080a）を置き、語りは下の帯の中に出す。字幕の設定（subsOn）は見ない。暗転は枠の中の幕で、不透明度を毎コマJSで書くので、「動きを減らす」でCSSの遷移が止まっても効く。
- **見たかの記録**：`save.js` の別キー `kamakura-valley-meta`（`{schema, version:1, openingSeen}`）。目覚めの区間に入った時点で書く。最後まで見た場合も、飛ばした場合も同じ。無い・壊れた・知らない版・読めない記録は初回として扱う。書けないときは例外を出さずに続ける。
- **目覚め**：既存の `startIntro` の中身を `startWake` へ移し、wake の出来事で呼ぶ。2.7秒で立ち上がり、5.2秒で終わり、入って0.6秒後から飛ばせる。この3つの値はデータへ移したが、動作そのものは変えていない。
- **休止**：Esc（ポインターの解放）・P・画面の切り替えで、オープニング中も休止する。休止画面の「区切りへ戻る」は、オープニング中は隠す（まだ区切りが無い）。

## 3. 捨てた案と理由

- 谷から離れた座標に舞台を置く案：地形・遠景の山・影・大気と衝突する（design-opening.md §5）。
- 場面の切り替えを暗転だけにする案：「動きを減らす」ではクロスフェードと決まっている。場面ごとに暗くすると、9.5秒の場面が細切れに見える。
- 2つの場面を毎コマ描いて混ぜる案：切り替えの1秒だけ描画が倍になる。止めた1枚を重ねれば足りる。
- 2Dキャンバスへ写して重ねる案：preserveDrawingBuffer が無いと、描いた直後にしか写せない。
- 短い版の目覚めを4秒に縮める案（design-opening.md §3）：既存の目覚めの時間割を変えたくない。短い版は約15.7秒になる。
- 語りを既存の字幕（#subtitle）に出す案：HUDの子なのでイントロ中は隠れ、字幕OFFでも消える。
- 見たかを進行の保存に入れる案：「はじめから」の最初の保存で上書きされる。
- 場面の上に半透明の帯を敷いて語りを置く案：比が場面の明るさで変わる。白の上でも4.5:1を保つには帯を約9割の不透明にする必要があり、それなら不透明の帯（映画の上下の黒帯）の方が絵として素直。

## 4. 契約（壊してはいけないこと）

- 通常版は52.2秒（45〜75秒）、短い版は15.7秒（14〜16秒）。各文は40字以内。開始から0.6秒は飛ばせない。飛ばすと0.6秒で暗転し、目覚めへ移る。飛ばしたあとの暗転は、飛ばした瞬間の濃さから単調に濃くなり、予定の暗転より明るくならない。
- 「続きから」「やり直し」では出さない。2回目以降の「はじめから」と、結果からの「もう一度」は短い版。QAの `?intro=0` は今までどおり飛ばす。
- 舞台は、複製したモデルの形と材質（谷と共有）を解放しない。自分で作った形・材質・画像・光の影の絵・反射の絵だけを解放する。
- 解放したあとの谷は、同じ固定カメラで、描画呼出・三角形がオープニング無しと同じ。形と画像の数は増えない（3回上映しても増えない）。
- 字と帯の比：生成り 16.6:1、朱 6.2:1（注記・飛ばしの案内も4.5:1以上）。炎の明るさの揺らぎは1.1Hz以下の正弦だけで作り、1秒に3回以下。

## 5. 検証の入口

- 純粋層：`tests/valley-opening.test.mjs`（18件）。変異試験は `node tools/verify-opening-mutations.mjs`（32件）。
- 実ブラウザ：`tools/scenarios/regress-opening.mjs --intro 1 --strict` で、区間の時刻、語り、飛ばし（E・Space・クリック）、短い版、休止、動きを減らす、続きから、旧保存、やり直し、再上映、記録が書けない場合、解放後の描画を確かめる。

## 6. 二段目（場面A〜D）への引き継ぎ

- 場面の中身は `opening-stage.js` の `SHOTS`（置き場・カメラの道筋・空・霧・光）と、場面ごとの組 `this.groups[id]` に足す。建物の複製は `this.models[key].clone(true)`、人物は `new Character(this.roster, who)` を作って `this.characters` に入れる（dispose で解放される）。
- 炎・煙・火の粉は、`new FX(this.scene)` を `this.fx` に置けば dispose で解放される（`fx.js` に dispose を足した）。`capture-opening.mjs` は粒子の乱数を種で固定して撮る。
- 光は2つ（`this.key`・`this.glow`）を場面ごとに置き直す。`flicker(t, seed)` は1秒3回以下の揺らぎ（試験済み）。
- 暗転の最初の4コマで各場面を1コマずつ描く（`warmQueue`）。場面に足した材質は、このとき組み立てられる。
- 仮の舞台では、オープニング中の1コマは p50 1.9ms・p95 6.9ms・呼出14・三角形974。予算は呼出300・三角形150万・p95 20ms。
- 目覚めの最初の1コマに約0.31秒かかる（人物の材質の組み立て）。変更前にも約0.36秒あり、新しい問題ではない。題名の間（暗転）に谷の材質を `renderer.compileAsync` で組み立てておけば、消せる見込み。
