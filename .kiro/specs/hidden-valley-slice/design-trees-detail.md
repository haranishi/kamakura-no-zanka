# Design: 木の作り込み（タスク8.1a・R17.5・R17.11）の実測と採用方式

本人の評価「まだ木とかの張りぼてっぽい」（2026-10-30）と、絵の方向「商業大作寄り」（R17.11）を受けて、木の描画だけを変えた記録。
配置・LOD境界（48/150m）・当たり・セーブは変えていない。前の判断は design-trees.md（7.9）。数値の目標は**未測定の設計目標**（実測値は明記）。

## 第1周の実測：何が張りぼてに見えたか（変更前、2026-10-30、FIXED_13と標本）

- 近景の杉（L0、0〜56m）：26段×6本の輪生カード（長さ最大3.2m・幅1.3mの板）と、滑らかな芯の円錐。12〜30mでは板の鱗の柱、林道（23）では大きな平面と縞、枝は無く「棒に樹冠」。
- 中景の杉（L1、40〜158m）：同じ形の笠9枚の重ね。見晴らし岩（08）・里の入口でモミ・トウヒの段（「段の針葉樹」）に見えた。
- 広葉：殻の向きだけで照らされ、輪郭が滑らかな「綿の玉」。幹と枝は無地の棒。
- 三角形（Node・実際の配置）：開始地点の木は1パス1,285,672。杉L0は90本（1本1,304〜1,496）、L1は772本。L0だけが影を落とす。

## 第1周の判断と捨てた案

| 判断 | 理由 | 捨てた案と理由 |
|---|---|---|
| **杉L0は、枝の計画（`tree-branches.js`）から作る**：黄金角の螺旋に1本ずつ違う高さの枝（74〜88本）、枝の外側3/4に重なる3枚交差の房（1枝2〜6個、最後は枝先）、長い下枝は3面の木の管（16〜39本） | 輪生と板が段・鱗の原因。房が枝から出ると「枝に付いた葉」に読める | 板の数や向きを増やす（板感は残る）。房を枝先だけに付ける（第1周：棒にまばらな葉）。L0全体を位置で揺らすだけ（板は残る） |
| **杉L0の芯の円錐を外す** | 房の間から滑らかな円錐が見え、張りぼてそのものだった。下からは底の円盤が宙に浮いた（第1周で確認） | 芯を細く・高くする（同じ円盤が残る） |
| **杉L1も同じ房の絵で作る**：螺旋に32〜40個の大きな房（三角形は旧の笠と同じ）、芯は影の緑（旧は黒に近い） | L0と同じ見え方になり、溶かしの帯で様式が変わらない。笠の段が消える | 笠の高さ・傾きを位置でずらすだけ（笠の重なりの段は残る）。黒い芯（房の間が穴に見えた） |
| 杉の房の絵は、杉専用の枝葉2種を1枚の帳（512×256）に描く。縁の透明は針の平均色 | 1回の描画呼出で2種。灰色の縁は遠くで白く抜ける（7.9の雪の罠） | 松の針の絵を共有（杉と松が同じ葉）。写真（出所と容量） |
| 帳の枝葉は、乾いた試し描きで寸法を測り、カードの台形に収まるよう縮めて描く | 絵がカードより広いと、房の脇が直線で切れた | 帳の外を消すだけ（切れ目が直線のまま残る） |
| 杉の房は、表裏で反転しない「樹冠の法線」（幹から外＋上）で照らす。縁から見えるカードは消える | カードごとの明暗の段（板感）を消し、樹冠を一つの塊として照らす | 既定の両面（裏で法線が反転し、カードごとに明暗がばらつく） |
| 杉の段は、個体の位置と高さで向きの変わる傾き（m/m：L0 .05・L1 .14・L2 .16）を、どの段にも掛ける | 隣どうしの木の段が水平にそろわない。全段で同じ向きの式なので、溶かしの帯でも傾く向きはそろう（強さだけ段で違う） | 段ごとの乱数（溶かしで形が跳ねる）。L0も大きく傾ける（影の地図は傾かないので、影がずれる） |
| 広葉は、葉の絵と同じ配置の「詳細の画像」で、葉ごとの向き（法線）と色の揺らぎを持つ。輪郭では葉ごとの値で欠ける。逆光の透けは葉の向きで強弱 | 殻の向きだけの陰影を、葉ごとの陰影にする。綿の玉の輪郭を葉の輪郭にする | 葉カードの追加（7.9で「紙の束」）。凹凸の画像だけ（葉の向きが出ない） |
| 広葉L1に近景と同じ分岐枝（3面の管、+18〜30三角形） | 「棒に玉」を中景でも避ける | 中景で幹を短くする（樹冠と離れ、試験の棒の付け根が崩れる） |
| 樹皮は128×256の手続きの画像（14本の縦の帯と割れ目・法線・平均1の明るさ）を全ての幹と枝で共有し、UVをメートルにそろえる。根元1mを暗く、杉は樹冠の中の幹と枝を影にする。葉の芯はUV(-1,-1)の印で樹皮を付けない | 平均1なので遠景・ミップの最小段で幹の明るさが変わらない。読み込みを増やさない | 写真の樹皮（出所と容量）。材質の`map`に入れる（芯にも樹皮が付き、試験の「芯は無地」を壊す） |
| 杉L0の上限を1,500→2,200三角形（L1・L2は据え置き） | 近景に細部を集め、遠景は軽くする（R17.11）。近景の杉は場面に9〜90本 | 遠景も増やす（約1.2万本で総量が持たない） |

## 第2周の実測（2026-10-31、別役の盲検12組：新が全組で上、平均4.9・どの項目も7未満）

- 遠景（150m以遠）の杉は円錐3〜4段のまま。見晴らしから「段の針葉樹」。開始地点で約35万三角形（木の1パスの26%）。遠景の松は丸い殻。
- 中景の杉（第1周）は、10°の望遠で滑らかな緑の芯の円錐と、3枚交差の房の「星形の紙」に見えた（`reports/polish3/trees-1/README.md`）。
- 広葉は大きな殻10個で「棒の上の球」。若木は殻8個が樹冠の0.22以内に詰まり、林道の斥候の画（set-04）でいちばん張りぼて。
- 杉の枝の高さは一様な層化で、細い家族の枝の間隔の変動係数が.32〜.42（魚の骨）。
- 中景の松は、針の画像の透明部が灰色（190）で、ミップで白っぽい「雪の木」だった（第1周より前から）。
- 太陽（高さ9.8°）は、歩ける全ての位置から尾根（11°以上）の陰（Nodeで地形から計算）。逆光の画は太陽の方位へ低く向け、尾根の上の明るい空を背にする。

## 第2周の判断と捨てた案

| 判断 | 理由 | 捨てた案と理由 |
|---|---|---|
| 遠景の成木（4種13家族）は、起動時と品質の切り替え時に、近景（L0）を8方向から帳（512×1664、色sRGB／法線＋葉の印）へ1回ずつ描いて焼き（`tree-bake.js`）、カメラへ向く板1枚（2三角形）で描く。隣の2枚は刻みの中央50%だけで混ぜる（`tree-impostor.js`） | 遠景の三角形が約1/14、幹の集合が無いので描画呼出も減る。近景から焼くので溶かしの帯の先も同じ木 | 円錐の形を変える（張りぼてのまま）。中景から焼く（房が大きく、遠くで細く透けた。並べて比べた）。1枚128×256（帳が4倍） |
| 法線を帳に焼き、板の右・上・手前で組み直して照らす。幹は aImpWood で個体の明るさ、葉は季節の色 | 回した木でも日向と日陰が太陽の側にそろう。楓の幹が赤くならない | 焼いた時の光のまま（木の向きで光が回る） |

| 焼く時の画像は1.5段鋭いミップで読み、遠くの不透明度はミップの段に応じて足す（mipBoost .5）。焼き先は多重サンプルなし | 小さく焼くと透明部の色がにじむ。遠くで樹冠が細る。4×の多重サンプルは並べて差が見えず、約50MBが残る | 多重サンプル |

## 再発させない落とし穴

1. 芯の円錐は、房の間から滑らかな面として見え（張りぼて）、真下からは底の円盤が宙に浮く。中景でも同じ（第2周）。
2. 房の絵がカードの台形より広いと、房の脇が直線で切れる。描く前に寸法を測って収める。
3. 枝の長さを中景の外周で抑えないと、溶かしの帯で樹冠の大きさが跳ねる（LODの±15%を超える）。房の張り出しも含めて抑える。
4. 段の傾き・樹冠の揺らぎ・風・近くの葉の薄めは影の地図に入らない（影は既定の材質）。近景の傾きは小さく保つ。
5. 帳は2つの枝葉の間と外周に透明の余白を残す。透明部は平均色で埋める（灰色は遠くで白く抜ける：第1周の杉、第2周の松）。
6. 杉の房の材質は表裏で法線を反転させない。反転させると、カードごとに明暗が入れ替わり板に戻る。
7. 焼く時は木を小さく描くので、粗いミップで透明部がにじむ。焼く時だけ鋭いミップで読む。板の向きは個体の回転を外した木の局所の方位で選び、混ぜは刻みの中央だけ（全幅で混ぜると二重像）。
8. 太陽（9.8°）は谷のどこからも尾根の陰。逆光の画に円盤は写らない。
9. 変異検査が途中で止まると、変異したファイルが残る（第2周で `tree-species.js` に `clear = 0.3` が残った）。止まったら `git status` で確かめ、検査どうしを同時に回さない（同じファイルを書き換える）。
10. 近くの葉の薄めを狭く（0.35〜1.3m）すると、1〜2mの房が不透明に戻って緑の壁になる。0.4〜1.8mを保つ。
