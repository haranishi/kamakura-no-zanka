# 設計：鎌倉を歩く（Web 取り込み・W2c）

2026-11-06 ドラフト。[要件](requirements-web.md)（WW1〜WW6）に対する設計。調査は `craft/report/w2c_survey.md`（Codex・事実と提案を分けて記載）。

## 方針

- 一度に全部載せない。**最初の試作は「地形＋歩き＋指操作」だけ**（W2c-1）。歩き心地を先に確かめ、家・木・材質は後から足す。
- 世界の定義だけを新しく作り、歩く・カメラ・入力・当たりの既存部品は再利用する（`dist/valley/` が現在の三人称本体。`docs/02` の庭の説明は古い）。
- 取り込みは `?world=kamakura` で切り替える。切り替えが無いときは、いまのゲームと同じ動作・性能（WW1.1）。
- 国土地理院の標高を加工したデータは、**リポジトリの外**に置く。開発サーバーが環境変数 `KZ_WORLD_DIR` のフォルダだけを `/world-private/` として読み取り専用で配る（未設定なら配らない）。`dist/` と公開物には入れない。

**v0.2（W2c-2a で追加）**：`patch_cells_i32.bin`（升目の NW 頂点の [行,列]・int32・(N,2)）・`patch_h_f32.bin`（float32・(N,25)＝5×5・北→南・西→東）・`patch_axes.json`（七切通ごとの道の軸 `xy_m`・床の高さ `floor_m`・距離 `s_m`・床の幅）。七切通の細密パッチ（K6 の朝夷奈の床を含む。7本・11,878升目・重なり0）。**基本の高さの同じ升目を置き換える**（Blender と同じ。重ねると二重面）。升目の内は 4×4 の細かい升目（約0.97m・双一次）。meta の `patches` に索引。

**v0.3（W2c-2a の直しで追加）**：`patch_paths.json`＝七切通の**道の線**（Blender が道の帯を置いた線。`pass_paths_k6.json` の `s_m`・`xyz_m`）。歩く試験・出発の位置はこちらを使う（`patch_axes.json` の設計の軸は、道の線・実際の床と一致しない所がある＝床の高さの比較に使わない。道の線に沿った高さは提供元と最大0.14m で一致）。

**歩ける勾配の規則（2026-11-06 の実測で決めた）**：勾配は**3.9m の幅（中心差分 ±1.95m）**で測る（パッチの0.97m の升目の尺度では測らない＝層の細かい段で歩けなくなる）。限界は鎌倉モードで **46度**（`collision.js` の上りの限度と同じ）。`?maxslope=40` でいままでの規則（40度未満）に切り替えて比べられる。理由（独立計算・端から端へ通れる最小の限界・3.9m 幅）：朝夷奈11°・巨福呂坂30〜37°・極楽寺坂38〜39°・化粧坂39〜40°・名越41〜43°・亀ヶ谷坂42〜43°・大仏坂43〜44°。**40度では大仏坂・亀ヶ谷坂・名越が通れず、46度で7本とも通れる**。K4 のままの6本は、道の線に沿って測っても局所的に33〜51度の所がある（朝夷奈だけ K6 の床で最大7度）。形そのものの直し（K6 のように床をなだらかに）は別の判断（Blender 側の形の変更）。また、**案Aの外でも、パッチの升目（七切通の道と壁）は歩ける**（案Aは七切通を境にした凸包で、道の外側半分が範囲の外に出るため。外側のつなぎまで歩ける）。

**v0.4（W2c-4 で追加）**：`houses.json`（型の一覧17：index・節の名前・型・三角形・外形 bbox・件数）・`houses_kit.glb`（部品17個。節の名前＝物体名。**単色**の材質＝K7 の目標色×壁と屋根の色味）・`houses_f32.bin`（配置 2,847件×17 float32：[型の番号, 4×4 行列(列優先・glTF 座標＝x東・y上・z南)]。回転と拡大を含む）。高さ（y）は Blender の地形の強調1.8倍を含むので、**Web では提供元の `heightAt(x,z)` に合わせ直して置く**（vscale に従う）。型は0〜4（K5 の5型）・k05〜k13（K6 の9型）・5＝塀・6＝門・k14＝長屋門（家の配置に使うのは14型：塀・門・長屋門は別の配置）。三角形は1型34〜114と軽い。質感は W2c-6（ここは単色）。

**家の接地（W2c-4・斜面の規則）**：部品の原点は地面の基準で、その下に裾（基壇の延長・1.5m×縦の拡大）がある。傾斜地では1点の高さだけでは四隅が合わないので、**家の本体の足跡（基壇底の矩形）を行列で回して 0.5m 間隔で標本にし**、最も低い地面・最も高い地面・平均を出して高さ（y）を決める。①**浮かない（必須）**：裾の底は、最も低い標本より「0.1m＋隣り合う標本の最大差の半分」だけ下に置く（標本の間に低い点があっても隙間を出さない）。②**埋まりは0.5mまで**：丘が壁の根元を覆ってよいのは 0.5m まで。超えるときは家を持ち上げる（裾が長いほど持ち上げられる）。①が②に勝つ。③**収まらない家**（高低差が裾＋0.5m を超える）は、浮かない側を取り、上り側が埋まる＝切り土のように見える。件数は検査で報告する（実寸で46軒）。傾き・回転での合わせ込み、地形の均し（宅地ならし）は今回やらない。**中景の簡易の箱**は粗い地形（LOD2 以上）に載るので、裾をさらに 2.5m 深くして隙間を隠す。

**木（W2c-5）の設計**：K7 の配置（`veg_f32.bin`・11.3万件）は3つの層。**tier 0＝一本ずつの木**（7.2万本・樹冠半径 0.5〜8m）は、ゲーム既存の木の仕組み（杉・欅・松・楓・灌木の形と葉の絵・3段の距離 LOD・遠景の絵の板・風）を再利用し、256m 区画の空間索引で近くの区画だけを詰め直す（毎コマ全件を走査しない）。K7 の種→ゲームの木：杉檜→杉・松→松・落葉広葉樹→欅・**照葉樹→欅の形に暗い常緑色**・灌木→灌木・庭木→楓。家（箱から1m）・道の線（2.5m）・出発点（3m）・水域は読み込み時に一度だけ除外。幹の円は案Aの内側の非灌木だけ当たりへ登録。**tier 1＝林分の塊**（3.6万件・樹冠半径 9〜15m）と **tier 2＝稜線と遠い林の塊**（5.3千件・半径 20〜32m）は「1本の木ではなく森の肌」。K7 は近い所だけ T0 で、中間は T1 の塊・遠景は T2 の塊で森を表す。実機で見ると T0 だけでは山肌の森がまばらなので、**W2c-5b** で、遠くは塊を低ポリの樹冠（楕円体）で1つずつ描き、**近く（約150m 以内）は塊の円の中に、元の番号から決まる固定の乱数で子の木を並べて一本ずつの木へ展開**する（1つの塊あたり 3〜16本・面積÷70m² 目安・種は塊の種・高さは塊の高さの0.75〜1.05倍・除外と接地は T0 と同じ・遠くへ出たら塊へ戻す）。近くの子と遠くの塊の入れ替えはヒステリシスで、ちらつかせない。T2 は遠景の塊だけ。品質を下げるときは `thin_rank` の大きい塊から間引く。**W2c-5c** は草むら（species 5・3.1千件）と近景の草。

**川（W2c-2b）の設計**：K7 の水路27本（`rivers_water.json`・計1.9万点・点の間隔 8〜16m）は、地形が**川底まで彫り込み済み**（中心線で 地形−底 = 0）。水面＝底＋0.5m、水深 0.5〜1.2m の模式的な水路。Web は水面の**リボン**（半幅＝川幅/2＋1.2m・縁は深度で岸に沈んで自然に切れる）を、`water_elev_m × vscale` の高さで張る。海へ出る川は水面が海面（y=0）に達する所で終える。見た目は谷の `water.js`（空を映す・流れの縞・浅い所は淡く・縁は泡）と同系統で、**大気（時刻の `sunDir`・霧）と矛盾しない**。512m 区間ごとに culling・距離の打ち切り（標準 約3.5km・軽量 約2km）・毎コマの CPU は時間の uniform だけ。歩く規則・足音・水しぶきは変えない（川の中は歩ける）。`?water=0` で出さない。

**足元の草（W2c-5c）の設計**：谷の草（`grass-view.js`・近景の密な板8m・中景のまばらな板25m・風・距離で消える）をそのまま使う。谷は「箱全体の1m 密度図を最初に1回作る」作りで鎌倉の全域には使えないので、**プレイヤーの周りの96m 四方・1m 升の窓**だけを作り、約24m 動いたら次の窓を時間の予算で数コマに分けて作って一括で切り替える（準備中は古い窓の描画が壊れない）。升の値は**世界の座標だけ**から決まる関数（窓の位置に依らず同じ升は同じ値＝継ぎ目が出ない。中景の斑の正規化も窓全体の統計でなく固定の範囲）。種類と密度は地表のクラス（v0.9）で決める：草＝背の高い草と低い草（ノイズの斑）・林床＝まばらなシダ（約0.3倍）・砂＝ごくまばらなススキ（約0.15倍）・土＝ごくまばらな低い草（約0.2倍）・岩／石／砂利／泥／田＝置かない・川の岸1〜25m はシダ／ススキへ。除く所：歩けない所・水・急斜面（32°超）・家と施設の箱（+0.4m）・道（七切通）の線2.5m・川と岸1m・幹の円。**出発点の周りは除かない**（草は何も妨げず、除くと主人公の足元に丸い禿げができた）。窓の外周6m は密度を落とす。品質：軽量は密度0.4・距離0.6、自動画質の段階2は密度約0.6倍・段階3は非表示（作り直さない軽い切り替え）。`?grass=0` で出さない・地表データが無ければ草は出さず歩ける。**費用の教訓**：窓の準備の費用は、升ごとの「川までの距離」の問い合わせが大半だった。川の索引は数値キー・32m 升で、しきい値の比較だけが要る呼び出しは `reach` で探索を打ち切る（水の判定は自分の升だけ・草は25m まで）。

**確認用の URL（鎌倉モードだけ）**：`?spawn=<切通の id>&at=0〜1`＝道の線の上から出発・`?pos=<東>,<北>&yaw=<北から時計回りの度>`＝その点（HUD の「東・北」と同じ。m）から出発し、歩けない点なら 40m 以内で最も近い歩ける点へ寄せる・`?houses=0`＝家を出さない・`?vscale=1.8`・`?maxslope=40`・`&debug=1`＝HUD に座標と勾配。いずれも比べる・撮る・試すためで、遊びの設定ではない。

高さの問い合わせは**双一次補間**（標本は升目の中心）。縦の倍率は `vscale`（既定1.0＝実寸。`?vscale=1.8` で Blender と同じ強調。歩く規則は倍率を掛けた後の勾配で判定）。

## ゲーム側の構成（W2c-1）

既存の地形の契約（`terrain-height.js` の `createTerrain()` が返す `heightAt / slopeAt / normalAt / surfaceAt / waterAt / roadInfo / walkable`）を満たす鎌倉の提供元を作り、描画・足・当たり・経路が同じ面を読むようにする。

| 部品（`dist/valley/` の下に新規） | 役割 |
|---|---|
| `world-kamakura.js` | 世界の定義（出発点・範囲・地点・縦の倍率）と、`?world=kamakura` の起動経路 |
| `kamakura-data.js` | `/world-private/meta.json` と bin の読み込み。無ければ分かる文言を出して既存の谷へ戻る |
| `kamakura-terrain.js` | 地形の提供元（高さ・勾配・法線・水・歩ける）。**40度未満を歩ける**（ゲームの規則）・水と案Aの外は歩けない |
| `kamakura-chunks.js` | 地形の描画。64升＝249.4624m 四方のチャンク・LOD は元格子の 1/2/4/8 間隔。LOD の境は標本・高さ・法線を共有し、粗い側へ補間（縫合）。材質は単色（W2c-1）。案Aの外は遠景として粗く残す |
| `touch-input.js` | 指の操作（左半分＝仮想スティックで移動・右半分＝ドラッグで視点・走るボタン）。既存の入力の契約（`axis / look`・押した瞬間・休止時の解除）を保つ |
| `hud-kamakura.js` | 方位（北の印）と、近い地名（150m 以内）。座標の表示は `?debug=1` のとき |

触らない：入力の既存契約・保存・庭 `/`・既存のテスト。歩行の基準（地形 `walkable`＝40度・衝突 `collision.js`＝上り46度・下り56度・段差0.55m）の食い違いは、**実寸の勾配で比べて記録**し、移動の規則は緩めない（調査 B）。

## 写真由来の細部（W2c-10）

- **細部だけを出荷する**：写真の色は使わない。Poly Haven（CC0）の写真から、法線の x・y と「明るさの比」（輝度×AO^0.7÷平均。平均が1）だけを1枚の JPEG（R・G＝法線、B＝√(比/3)、4:4:4）に詰める（`tools/build-kamakura-photo-textures.py`・15枚・約4.1MB）。シェーダーは今のパレットの色にこの比を掛けるので、平均の色は変わらない。写真の色をそのまま貼ると全体が暗く沈む失敗を避ける方式（兄弟作品の CC0 素材の組み込みで確かめた）。
- **共有の読み込み口**：`kamakura-photo-tex.js` が15枚を一度に読み、全部そろってから同時に差し替え、共通の `photoBlendUniform` を1.2秒で上げる。失敗したら手続きの見た目のまま。各担当は `photoSampler(key)` の uniform を自分のシェーダーへ渡すだけで、`world-kamakura.js` は触らない。
- **繰り返しの消し方**：広い面（地面・屋根）は `kzPhotoHex`＝三角格子の3頂点が乱数の位置と回転を選び、重みは L2 正規化でコントラストを保って混ぜる。向きのある素材（板・茅・瓦）は回転しない。小さい面（壁）は1回の読みの `kzPhoto`。
- **法線**：`kzPerturbNormal`（画面空間の微分から接線を作るので、頂点に接線は要らない）。
- **切り戻し**：`&photo=0` で全体を切る。自動段階2は強さ0.6、段階3は0。
