## 実際のChromeで見て直したこと

以下は依頼時に受け取った実Chromeの所見。今回の実装後に自分で見た結果ではない。

1. 南の6割が一枚の黄色い田だったため、負の段番号も別の帯として扱った。
2. 稲がレモン色の丸い株に見えたため、遠景の金を暗く低彩度にし、株を低く平らにした。
3. 石帯が青灰色の水路に見えたため、灰茶の壁・下の影・明るい草の畦へ変えた。
4. 東と南の縁が直線だったため、外縁をメートル単位で揺らし、草の土手と崩れ石を添えた。
5. 刈田が北だけにあったため、北・中央・南へ2〜4枚の塊で散らした。

前回の「負の段に石積みを置かない」という判断は維持した。区画だけは段番号で分ける。
0.5mの高さ補間だけでは、境のそばで隣の段を選ぶ点と、田面の高低差が5cmを超える点があった。
所属段と栽培可能な高さは元の読み取り関数でも確認し、等値線と条は共有の標本格子から作る。
面積0の法面だけの切れ端を除いた。20種類のseedで、1帯1〜3区画と面積上限を確認した。
旧試験の0への段番号統合・陰70%以上・影も壁の高さ内という条件は、新しい要件へ置き換えた。
高さの指紋、田面被覆80%以上、道路・任務・巡回の余白、曲線・交差なし、予算の検査は保った。

## 実際のChromeで確かめる手順

1. `/valley/index.html?qa=1&autostart=new&intro=0&cam=concept`を開く。同条件の`&paddy=0`と比較する。
2. `&paddydebug=1`では段番号ごとに7色が循環する。0赤・1黄・2緑・3青緑・4青・5紫・6桃。負の段も循環する。
3. 法面は同色の暗色、畦は緑、石は灰、稲架は赤。南も帯で仕切られ、道を塞がないことを確認する。
4. 通常色で南北の刈田、熟れた金の地色、条と風を見る。「明るい畦→灰茶の壁→影→下の田」の順を確認する。
5. `__valley.paddyStats()`の`terraces=15`、`raisedBoundaries=6`、`flatBoundaries=8`、`plots=31`、`maxPlotArea=325.5`を照合する。
6. `__valley.camera(null)`後に`__valley.teleport(-10,49)`と`(-55,62)`。接地、近景の稲と石、40mの切替を歩いて確認する。
7. 標準・`__valley.quality('light')`・自動品質段階0〜3を比べ、150m以遠の壁と東・南の縁を見る。
8. `tools/scenarios/capture-concept.mjs`の11枚を前後同条件で撮り、移動中のちらつきも確認する。

## 見た目を詰める定数（paddy.js先頭）

| 定数 | 今の値 | 上げるとどうなるか |
|---|---|---|
| `farGain / farDesaturate / farWarmth` | .88 / .12 / .90 | 日なたが明るく／彩度が下がる／黄色へ戻る |

| `rockGain / rockSoil / stoneBandWidth` | .66 / .50 / 1.4m | 石が明るく／土色へ寄る／壁が太くなる |

| `bundWidth / bundHeight / bundCrownGain` | .65 / .19m / 1.7 | 畦が太く／高く／壁上の畦が明るくなる |

実際の Chrome で確かめた結果：見渡しで、等高線に沿ってうねる帯が 10 本以上読める。レモン色と丸い株は、消えた。
壁の上の畦が、歩く視点で蛍光の黄緑に見えたので、明るさを下げた（`bundCrownGain` 1.7 → 1.25）。
残っている点：石の帯は、日陰で青みがかった灰色に見える。FPS・Safari・Firefox は、確かめていない。
初期生成と更新時の候補数は増えた。実機で重ければ、まず草と切り株の距離を詰める。
