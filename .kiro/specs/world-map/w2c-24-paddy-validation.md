# 棚田の段と遠景の検証（2026-11-12）

区画・石積み・畦を実地形の段へ合わせた。高さは変更前とビット単位で一致する。
ただし、実在する踏み面は7段だった。「8本以上が見渡しで読める」は未達・未確認として残す。
次は実際のChromeで固定画角を撮り、石帯と稲の色を詰める。

## 採った方法と地形の制約

元の地形は段を作った後、峰の高さと比較する。その比較には範囲外の0mも含まれる。
そのため、負の段は0mへ持ち上がり、南側は広い平場になる。
例：座標(0,80)の段情報は負だが、最終的な高さは変更前から0mである。
負の段へ石積みを足す案は、平場に偽の段を描くため採らなかった。
地形の高さを変えて段を増やす案も、足元の高さを守る制約に反するため採らない。

| 要求 | 結果 |
|---|---|
| P1 段から区画を作る | 実装。0.5mの標本から同じ段の踏み面を判別し、各段を1〜3枚へ分割 |
| P1 刈る順・外縁・範囲 | 実装。北から刈り、途中の境も等高線に沿う。外縁は雑音で崩す。木・下草の除外は維持 |

| P2 8本以上の視認 | 見送り。実在する踏み面は7段。画面で数える検証も未実施 |

これらを、同一段・高さ幅・被覆・曲がり・交差なし・条内間隔の検査へ置き換えた。
道・任務・巡回の余白、切り戻し、近遠混合、描画予算、停止中の転送0は引き続き検査した。

## 実際のChromeで確かめる手順

1. `/valley/index.html?qa=1&autostart=new&intro=0&cam=concept`を開く。同条件で`&paddy=0`も撮る。
2. `&paddydebug=1`で段を確認する。高さ0段から順に赤・黄・緑・青緑・青・紫・桃。法面は同色の暗色。
3. 畦は緑、石は灰、稲架は赤。通常色へ戻し、石帯のうねりと稲の柔らかさ、南の平場を確認する。
4. `__valley.paddyStats()`で`terraces`・`plots`・`contourLength`・`stoneBandVertices`を照合する。
5. `__valley.camera(null)`、`__valley.teleport(-10,49)`と`(-55,62)`で歩く。道の余白、接地、40mの切替を見る。
6. 標準と`__valley.quality('light')`、自動品質段階0〜3を比べる。150m以遠でも石帯が消えないかを見る。
7. `tools/scenarios/capture-concept.mjs`の11枚を前後同条件で撮り、移動中のちらつきと風も確認する。

調整値はすべて`paddy.js`先頭。値を上げると右欄の効果が増す。

| 定数 | 現在値 | 上げた場合 |
|---|---|---|
| `stoneBandWidth` | 0.95m | 石帯が太くなる |
| `rock / rockGain / stoneShadow` | #d2d2c8 / .95 / .42 | 石色の各成分／全体／下端が明るくなる |
| `bundWidth / bundHeight` | .75 / .19m | 畦が太く／高くなる |
| `rowPeriod / rowStrength / cutRowStrength` | 1.05m / .06 / .10 | 条が広く／立稲・刈田の筋が強くなる |
| `groundWavePeriod / groundWaveStrength / groundWaveSpeed` | 16m / .08 / .18rad毎秒 | 風の模様が大きく／明暗が強く／速くなる |
| `soil / cutRiceMix / cutGain` | #967850 / .65 / 1.38 | 土色の各成分／藁の金色の割合／刈田の明度が増す |
| `farShadeFloor / farRoot / tip` | .72 / (.5,.5,.22) / (.84,.64,.27) | 房の日陰／根元／穂先が明るくなる |
| `rowJitter / splitJitter` | .35 / .6m | 条内の株の揺れ／南北畦の蛇行が増す |

Chromeの撮影・見た目の合格・FPS・Safari・Firefoxは未確認。
