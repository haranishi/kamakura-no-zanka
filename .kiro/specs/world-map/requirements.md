# 要件：全体マップ（実地形を土台にした世界地図）

2026-11-04。本人の依頼（鎌倉の全体像と全体のマップを、実際の鎌倉や物語に出てくる山や谷まで含めて、Blenderで作り込んでいく。隠れ谷だけではない）を受けた仕様の初版。
正本の構想は企画書 v0.1 の「4 全体マップ」（Google Drive `70_Web・開発・技術/残火の鎌倉/01_企画書/`）と構想図（同 `02_マップ・コンセプト/`）。
EARS（条件・出来事・応答をそろえる書式）で記す。主体はゲームと制作手順。数値は受け入れ目標で、実測の記録ではない。

## 前提と決定

- 企画書の決定（再掲）：全体マップは模式図で、日本全土の連続再現は目指さない。地域ごとに探索できる連結型で、地域内は歩いて探索し、地域間は街道の出口や作戦画面で移動する。読み込みは峠・門・宿営で自然につなぎ、全地域を一度に常駐させない。
- 本人の依頼（2026-11-04）：実在の鎌倉と、物語に出てくる山や谷まで含めて、全体のマップを作り込む。
- 決定：実際の標高を土台にして、ゲーム用に圧縮・編集する。編集した所は記録する。隠れ谷は架空（企画書）なので、実標高を使わない。
- 決定：既存の里（`WORLD`・約250m四方・`dist/valley/world-data.js`）は、隠れ谷の地図の一部として残し、座標を変えない。
- 決定：制作は Blender（5.2 LTS・手元にあり）。作業ファイル（.blend）は Google Drive、スクリプトと小さな書き出しはリポジトリに置く。

## WM1 全体像

1.1 常に、全体マップは諏訪〜武蔵〜鎌倉を実標高の上に示し、章の舞台（隠れ谷・諏訪周辺・女影原・小手指原・府中・井出沢・鎌倉）を置く。
1.2 1333年の逃避と1335年の進軍は別の線で示し、どちらも模式（実際の経路は不詳・未確定）と画面に書く。
1.3 全体マップは、確認用の画像と、Blender の立体（俯瞰・斜め）の両方で見られる。

## WM2 地域の地図

2.1 地域は企画書の表のとおりとする：鎌倉の外縁、隠れ谷、諏訪周辺、信濃から武蔵への移動区間、女影原と小手指原、府中と井出沢、鎌倉。
2.2 実在の地域（鎌倉・諏訪・武蔵の原野と川）は、実標高を土台にして作る。ゲーム用に圧縮・平坦化・移動した箇所は、地域ごとの記録に残す。
2.3 隠れ谷は架空の地形として作る（約1.2km四方。清瀬川・烏峰・北稜・里山・西の山壁・脱出の峠。標高は構想図の仮設定）。実在の地形に見せない。
2.4 信濃から武蔵への移動区間は、行程図と短い峠・宿営の地図で圧縮する。正確な経路を断定しない。

## WM3 座標・縮尺・接続

3.1 すべての地域は共通の座標系（東が +x・北が −z・単位はm・標高は海抜m）を持ち、実在の地域は原点の緯度経度を記録する。
3.2 地域ごとの大きさと解像度を決めて記録する（設計の表）。
3.3 地域間の接続点（峠・門・宿営）は、位置・標高・向き・接続先をデータにし、接続の両側で標高が合う。
3.4 既存の里の座標・衝突・遮蔽・経路の値を変えない。

## WM4 時代考証

4.1 鎌倉の切通し・寺院・海岸線・川筋・建物を実名で置くとき、1333〜1335年時点の存在・姿・役割を調べ、根拠（出典）を地点ごとに記録する。
4.2 現代の観光地の配置・建物・道路を、そのまま中世の地図に載せない。確認できないものは「未確認」と印を付け、断定した見た目にしない。
4.3 史実の骨格・諸説・創作を、地図の上でも区別して示す（企画書の区分表と同じ）。

## WM5 データの出どころと権利

5.1 標高などの元データは、出典・取得日・ズームと範囲・加工の内容・利用条件を、地域ごとに記録（provenance）する。
5.2 公開するリポジトリへ入れるデータは、利用条件を確認できたものに限る。国土地理院の標高を加工して公開してよいか（測量法に基づく承認の要否）が確認できるまで、そのデータはリポジトリへ入れず、作業用の Drive に置く。必要なら、利用条件がはっきりした別の標高データに替える。
5.3 外部ゲームのコード・シェーダー・数値・素材・生成データを持ち込まない（手本は手法だけを借りる）。AI生成の画像は構想用で、ゲームとリポジトリに入れない。
5.4 出典の記載（「地理院タイル（標高タイル（基盤地図情報数値標高モデル））を加工して作成」など）を、画像・文書・ゲーム内の表示に付ける。

## WM6 作り方と置き場

6.1 地形の作り方はスクリプト化し、取得 → 高さ地図 → Blender → 書き出し → 画像、を再実行できる。
6.2 .blend と大きな画像は Drive（`残火の鎌倉/02_マップ・コンセプト/`）、スクリプト・設計・小さな書き出しはリポジトリに置く。置き場所は Obsidian に残す。
6.3 手元で足す依存（Python の numpy・Pillow・scipy）は制作の道具だけで、ゲームの実行には要らない。README に書く。

## WM7 ゲームへの取り込み（後の段階）

7.1 書き出しは地域ごとの高さ地図または glTF で、追加の容量は合計10MB以内を目標にする（現在のモデルは60.9MB・予算115MB）。
7.2 取り込むまで、ゲームの既定の動作・性能・戦闘の論理は変わらない。取り込みは切替（例 `?world=on`）で入れる。
7.3 地図画面（全体マップを見せる画面）は別の単位とし、見せ方（模式風か実地形か）は本人と決める。

## WM8 確認

8.1 実在の地域は、元の標高と作った地形の高さの差、主要地点（諏訪湖・鶴岡八幡宮・由比ヶ浜・富士山など）の位置の差を測って記録する。
8.2 地域ごとに、固定の画角（俯瞰・斜め）の画像を企画書の模式図と並べ、画像だけを見る別役（Opus）が「同じ場所と分かるか」「模式であることが分かるか」を採点する。
8.3 各地域の終わりに、本人が画像と立体を見て確かめる関門を置く。
