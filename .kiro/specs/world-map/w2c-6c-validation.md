# W2c-6c 音の実装引き渡し

BRIEF-W2C6C.md の確定済み設計を引き継いだ。実装とNode検証が担当範囲。
施設・飛行の既存変更を保持し、commit・push・他worktreeへの書き込みは行っていない。
ブラウザ・音の聴感・固定画角撮影は親の実機確認として残す。

## 目的・判断

- 谷の合成音を再利用し、歩く場所と川への接近が音で分かるようにする。
- 地表の最近傍格子と川の256m索引は純粋な層。歩行・衝突・LOD・保存の規則は変更しない。
- 任意のv0.9地表ファイルは名前とサイズを限定。欠落・不正・読込失敗では従来の土へ戻す。
- 川の帯は中心線から川幅の半分。描画の余白1.2mは足元の水判定へ足さない。
- HeroActorの接地処理を使い、必要なworld.buildings等は無害な代役で補う。
- 解錠・休止・ミュート・環境音は既存ValleyAudio。合成音の4ファイルは変更していない。
- 音ボタンは休止の隣。ミュート保存不可でも続行。audio=0は音のインスタンスを作らない。
- 環境音の位置は歩行中は主人公、飛行中はカメラ。約10Hz、復帰時も更新をまとめて発火しない。
- 破棄はイベント解除・音源停止・Contextのclose。未完了の解錠から復活させない。

設計の補完：iOSでresumeをユーザー操作の同期処理内に置くため、Context未生成の段階で
休止意図をfalseにする。操作時にunlockし、完了後に最新の休止状態を反映する。
clickも解錠対象に追加した。最初の操作で全解錠リスナーをまとめて解除する。

## 数値とデータ保護

- 合成3×3格子：0〜7・255を各1升。砂と石砂利→gravel、湿砂泥と田→water、
  草→grass、林床→leaves、土と255→dirt、岩→stone。既存classifySurfaceの規則どおり。
- 私有データのクラス別件数・升目値・座標は記録しない。v0.9の長さ・既知クラス・
  格子の方向と最近傍を検査。データ本体をソース・fixture・生成物・provenanceへ入れない。
- v0.9川索引：256m、170区画、18,694線分、19,510参照。
- 距離計測：Node v24.22.1、1,000地点×10巡、平均0.021ms/回（単独実行）。
  GPUやブラウザの性能ではない。索引と総当たり、川中心の0を検査した。
- 環境音更新：60Hzで10秒進め100回。足音同時上限28を維持。

## 親が実機で確かめる手順

1. リポジトリ外のexport_web_w2c_v9をKZ_WORLD_DIRへ指定し、npm start -- --port 8095。
2. http://127.0.0.1:8095/valley/index.html?world=kamakura&debug=1 を開く。
   操作前は「音：未解錠」、最初のキー／タップで「解錠済」。歩いて足音累計が増えるかを見る。
3. 草・林床・土・浜・岩・田と川の中を歩き、音を聞き比べる。川近くで環境音onを確認し、
   接近による川音の変化は耳でも確認する（onは環境音全体の状態）。
4. 音ボタンで切替、再読込でミュート保存、&mute=1、&audio=0、P／Esc／休止ボタン、
   blurとタブ切替の停止を確認。Fで飛行中は足音累計が増えず、Gで降りると再び増えるかを見る。
5. 軽量と品質段階3、飛行時の川への接近、タッチ、Safari、世界の破棄・再生成を確認する。
   谷（worldなし）と庭、施設、段葛の既定非表示も確認し、HUDの前後画像を残す。

未確認：実ブラウザ・聴感・Safari/iOS・スマホ・GPU・長時間メモリ・固定画角画像。
既知の新規不具合はNode試験では未検出。実機の不具合の有無は未判定。

## 親の実機確認（メイン・2026-11-07・実Chrome・画面なし・1280×720・`KZ_WORLD_DIR=…/export_web_w2c_v9`）

- 全体の試験を親が再実行：私有データなしで1012成功・10省略、v0.9指定で1022成功・省略0、`npm run check`・`npm run smoke` 成功、v0.9指定の `check-kamakura` 成功（FAIL 0）。※途中で1回だけ、負荷の高いときに私有データの試験が1件落ちたが、その後の4回の再実行は全件成功（偶発）。
- 音は headless では聞けないので、HUD の「音」の行（`?debug=1`）の数字で確かめた：起動直後 `未解錠・環境音off` → 最初のクリックで `解錠済・環境音on`。出発点で5秒歩くと `足音14`・4秒走ると `足音32`（走るほど増える）。川の中 4秒で `足音11`・杉林 4秒で `足音11`。`P`（休止）で `休止・環境音off`・再開で戻る。「音」ボタンで `ミュート⇄解錠済`。`&audio=0` は `音：無効`（ボタンの表示も「音：無効」）・`&mute=1` は `ミュート`で始まる。コンソールは空。
- **直したこと（メイン）**：6c で川の水深を `Math.max(0.46, -高さ)`（海と同じ「深い水」）にしていたため、`collision.js` の「水深>0.45m は進めない」で**川の中で主人公が1歩も動けなくなった**（町は川で分断される）。川は膝までの浅い水（K7 の水面＝底＋0.5m・模式）なので、川の `waterAt` を **0.4（0.45未満）**にした（`RIVER_WADE_DEPTH`）。足音は水（`waterAt>0.05`）のまま・海は従来どおり進めない（≥0.46）。**実際の衝突の規則（`moveActor`）で、川を歩けて海は止まる**ことを試験に足した（`kamakura-surface.test.mjs`）。再測定：川の中で5秒歩いて14.9m 進み、足音14。教訓：6c の試験は `walkable` と `movementBlockedAt` が変わらないことだけを見ていて、`collision.js` が `waterAt` を直接読む経路を見ていなかった。
- 聞き比べ（音色・音量・川の音の距離感）は未確認（本人）。iOS Safari の解錠も未確認（実機）。
