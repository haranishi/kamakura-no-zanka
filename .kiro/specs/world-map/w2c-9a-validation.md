# W2c-9a：海の音と岸距離を追加

鎌倉専用の波音と、後続の水際描画が共有できる岸距離の配列を実装した。
Nodeで16m格子の作成は32.68〜37.88ms。聴感・ブラウザの性能は親の実機確認が残る。

## 採った設計

- `kamakura-terrain.js` に既存の海判定を `isSea` として公開。川の浅瀬は含めない。
- `kamakura-shore.js` は純粋な3–4距離変換。16m格子を2回走査し、双一次補間する。
- `terrain.shoreField` に `cell/x0/z0/w/h/data`、`terrain.seaDistanceAt` に問い合わせを公開。
- `x0/z0` は先頭の標本中心。最後の標本は範囲を覆うよう切り上げる。範囲外の問い合わせは地形の端へ固定する。
- 配列はGPUへ渡せる有限のFloat32Array。3000mを上限の番兵値とし、問い合わせは上限以上をInfinityへ変換する。
- 海の中は直接の判定で0。海の標本がない地図は問い合わせがInfinityになる。
- 単独のNode測定で60ms以内なので、同期生成を採用した。
- `KamakuraAudio extends ValleyAudio` に、500Hzのうねり・1800Hzハイパス＋3400Hzバンドパスの白波・低いとどろきを追加。
- 種1333の波包絡は6.8〜9.8秒、3波ごとのセットで強弱を付ける。白波は0.9秒遅らせて山を鋭くする。
- 距離利得は `0.14/(1+(d/45)^1.6)`、600m超で0。更新10Hz・時定数0.25秒。
- `sea` を環境音Mapで管理し、休止・ミュート・破棄で全ノードを停止／切断する。
- `&sea=0` は海音だけ無効。`audio=0`／`mute=1` は従来どおり。軽量・自動画質でも音源を作り直さない。
- 谷の音源・庭・保存・足音・描画は変更していない。新素材・依存・通信・Git操作なし。

## 数値と試験

測定環境はNode v24.22.1。私有v0.9を環境変数から読み、座標や細かな件数は保存していない。
作成時間5回は37.88／32.68／33.10／34.22／33.38ms。起動時の地形込みの初回測定は46.42msだった。
問い合わせ10万回は平均0.137µs。これはNodeの値であり、ブラウザの1コマ増分ではない。
海の標本は全体の13.8%。砂の標本の95.7%が海から64m未満。出発点は海から600m超だった。

## 親が実機で確かめる手順

1. `KZ_WORLD_DIR=…/export_web_w2c_v9 npm start` で私有データを指定する。
2. `/valley/index.html?world=kamakura&pos=-1057.2,-1801.4&yaw=180&debug=1` を開く（依頼書指定の浜・海まで約12m）。
3. 最初にクリックして解錠する。「海 Nm」「波on」を確認し、海から離れる／近づくと距離利得が上表の方向へ変わることを確認する。
4. 利得の数字はDevToolsで `kamakura-audio-view.js` の `updateListener` 直後に停止し、ローカル変数 `audio.seaGain` を読む。これは包絡を掛ける前の距離利得。
5. 同じURLに `&sea=0` を足して聞き比べる。`&audio=0`、`&mute=1`、休止・再開・音ボタンも確認する。
6. `&q=light` と自動画質段階3でも波音が継続すること、海音あり／なしのコマ時間を測る。

ブラウザは依頼の制約により使っていない。聴感、実機Safariの解錠、標準で+0.5ms以内・CPU6倍でp50+3ms以内かは未確認。
9aで確認した実装不具合はない。全体回帰には上記の担当外の失敗が残る。距離は16m格子の近似で、細い入り江は標本に入らない場合がある。
設計からの具体化は、セットを範囲内の3波に固定した点と、GPU配列の上限を有限値にした点。
