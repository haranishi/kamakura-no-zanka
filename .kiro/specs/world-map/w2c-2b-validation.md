# W2c-2b 川の水面の実装・検証

BRIEF-W2C2B.mdと委譲元design-web.md・tasks-web.mdの承認済み設計を適用した。
実装とNode検証を担当。画面・性能・指操作の受け入れは親が実機で行う。
commit・push・他worktreeへの書き込み・ブラウザ操作は行っていない。

## 実装

- schema 0.7を許可し、0.1〜0.6を維持。meta.riversなしは川なしで続行する。
- 任意のrivers.jsonだけを読み、外部URL・リダイレクトを拒否する。
  形式不正・取得失敗・件数不一致は川なしに戻し、HUDへ案内する。
- 純粋層kamakura-rivers.jsが27本・配列長・有限値・正の幅と深さ・水面＞底を検査する。
- 帯の半幅は川幅/2＋1.2m、高さは水面×vscale、UVは横±1・縦は累積距離。
  連続する同一点を除き、120度超の折れと反転・退化する区間の面を除外する。
- 海へ出る川は海面で切り、交差点の位置・幅・距離を線形補間する。
  海面以下から始まる場合は、水面が正になるまで帯を作らない。
- 約512mごとにMeshを分け、視錐台カリングを有効にする。
  境界の左右2頂点を複製し、接続とUVを維持する。未使用の頂点は区間へ持ち込まない。
- 標準3500m・軽量2000mの距離制限はfragment shaderで判定する。
  手前128mで滑らかに透かし、制限以遠はdiscardする。
  CPU側の区間走査や距離判定は行わず、毎コマは時間uniformだけを更新する。
  距離制限だけでは描画呼出しを減らさない。GPU負荷は親の測定を待つ。
- 谷water.jsの材質・反射・流れ・浅い色・泡の式を鎌倉viewへ写した。
  大気のsunDirを渡し、標準材質のfog chunkで6bの霞を受ける。
  透明・depthWrite=false・renderOrder=2。谷のwater.jsと6b設定は変更していない。
- water=0は川だけを非生成。海・地形・歩行・音・保存は変更していない。
  鎌倉の破棄経路から全区間の形状と共有材質を一度だけ解放する。

## 検査

- 開始時：npm testは960成功・6省略。npm run checkは成功。
  npm run smokeはlisten EPERMで失敗。環境がHTTP待受けを許可していない。
- 合成川で不正入力、北向き、幅、縦倍率、UVの距離、上向きの面、退化除外、海面補間を検査。
- 区間分割で全三角形と使用頂点の保存、境界複製数、属性の一致を検査。
- 旧meta、川なし、取得失敗、不正なファイル指定、water=0と元の谷への入口を検査。
- 同梱ThreeをNodeで使用。形状・境界球・uniform・sunDir・霧の断片・距離の式を確認。
  再生成・二重破棄で形状と材質のdispose回数を確認する。
  GPU描画・GLSLコンパイル・実機メモリの確認ではない。
- 私有データ検査はKZ_WORLD_DIRからだけ読む。未設定・旧metaは理由付きで省略する。
  全中心点の分布・割合・外れた川id・隠れる点・海での打ち切り数を標準出力へ返す。
  vscale=1.8の許容帯も1.8倍し、実寸へ戻した差で0.5m±0.15mを判定する。
  数値の詳細表・地形・座標・派生素材はリポジトリへ保存しない。
- 最終コマンドの結果は以下に追記する。

## 親の実機確認

KZ_WORLD_DIRにリポジトリ外のexport_web_w2c_v7を指定し、npm start -- --port 8095。
http://127.0.0.1:8095/valley/index.html?world=kamakura&debug=1 を開く。

- 市街・谷の川で水の色と流れ、岸の切れ方、縁の泡、海との境を見る。
- 同じ画角でwater=0と比較し、遠くの川が消える境界を往復する。
- vscale=1.8、q=light、time=morning・evening、atmos=0を比較する。
- 鋭い折れと反転区間の除外による隙間を確認する。
- データなし・川ファイルなし・world未指定の谷・庭も操作する。
- PCとタッチ端末でコマ時間・長時間歩行のメモリ・破棄後の再生成を確かめる。

未確認：実画面、GPU、GLSL、性能、指操作、固定画角の前後画像。
既知の環境制約：HTTP待受け拒否。見た目の既知の不具合は未判定。
設計の具体化：120度の折れ判定、GPUの距離制限と128mの透かし帯。
次の最小ステップは、親による同じ画角での水あり／なし比較と受け入れ判定。
