鎌倉専用の植生に VG4〜VG7 を実装した。Node の全体試験は合格した。
実 Chrome の画質・GL 警告・性能は未確認。次は親側で固定画角を撮り比べる。

| 要求 | 実装と減る量・制約 |
|---|---|
| VG4 | 複製形状にカード識別位置と球面寄せ法線を追加。明るさ±12%、黄青の色ずらし±0.03、法線の球面寄せ0.6と最大25度の傾け。高さ勾配は面積平均1に補正。 |
| VG5 | 世界座標1.1mの低周波ノイズで縁の内側を抜く。合成円盤の可視面積は5.609〜9.083%減少。実画の減少量は未測定。影の材質・頂点・カード数は減らさない。 |
| VG6 | 新しい透過光は日なた・太陽方向のみ、成分上限0.08。太陽反対向きの旧透過光は最大0.035から0へ減る。読み込み前・段階3ではveg5の式に戻る。 |

## 依頼書から引き継いだ設計

参照した4文書は BRIEF-W2C10-COMMON、BRIEF-W2C11-COMMON、BRIEF-W2C11-VEG、
CRITIC-R4B-REPORT。基準画像01・02・03・08・09・12の用意後の画を閲覧した。
このチェックアウトの requirements-web.md は WW7 まで、tasks-web.md は W2c-10 までだった。
WW8 と W2c-11 は存在しないため、今回の明示依頼書 VG4〜VG7 を実装仕様として引き継いだ。
要件・設計・実装境界は上表と依頼書のとおり。tasks*.md は指示に従い更新していない。

杉の既存法線は tree-branches.js の crownNormal で外向き65%へ寄せてある。
この法線へさらに寄せると二重になるため、カード面の法線から60%で作り直した。
交差カードは中心が一致するため、面と辺の方向で小さくずらした位置を識別値にした。
`aKzCard` は世界座標を得るための vec3 属性で、カード内で一定。複製順・窓・時計には依存しない。
広葉樹の独立した三角面も1枚として扱う。共有頂点の遠景殻は空間の値を補間する。
焼いた遠景板も色と高さのみで、法線と抜けは追加しない。

追加する外部素材、通信、依存、毎フレームのCPU処理はない。
共用の木、配置、当たり、庭・谷、保存は変更していない。

## 親の実機確認（実Chrome・同じコードの `&veg6=0` と比較・2026-11-08）

- 最初の実機で、**樹冠の頂点シェーダーが GL でコンパイルできなかった**（`position.y--0.013…`：負の定数をそのまま式へ差したため `--` になった。Node の試験は緑・GPU だけが報告）。定数を括弧で包んで直し、`balanced()` に「`--` 数字／`++` 数字を含まない」検査を足した。直した後は console の警告・エラー 0 件（7画角）。
- 見えること：03 の杉・広葉樹の塊の内側に房の明暗が出て、輪郭に空の抜けが見える。13 の茂みと大きな木の冠に葉の房の明暗と暖色の縁が見える。12・01 の遠い木は差が小さい（意図どおり遠くは絞る）。
- 画面全体の数値（無→有）：明るさ 01 0%・02 0%・03 −4.1%・08 −2.5%・09 0%・12 0%・13 0%、彩度 ±2.5% 以内、暖かさ ±2%。speck は 13 で 48→80（葉の縁の暖色の透け＝意図した明部）。
- 速度（垂直同期を外した相対比較・停止時の中央値）：森 5.7→6.3ms（**+0.6**・測定のばらつき ±0.2）・公園（13 の画角）5.3→5.5ms（+0.2）。スマホ相当（CPU 6倍）：森 32.9→32.9ms（±0）。
