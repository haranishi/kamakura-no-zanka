# W2c-9c 草の二層・環境差・踏み分け
承認済みの9c依頼書を引き継ぎ、鎌倉だけの草の設定と起動時の同期生成を実装した。
Nodeで形状・分布・品質切替・資源解放を検証した。画面・GLSL実コンパイル・GPU性能は親の実機確認が残る。
commit・push・依存追加・外部通信は行っていない。
## 採った設計と理由
- 共用buildGrassの任意lookに、鎌倉側のパック・材質・品質の処理を渡す。省略時の経路を維持する。
  変更前の合成入力で取得したSHA256を6通り固定し、全送信バイト・形状・枚数・完成シェーダー文字列の同一性を検査。
- 近景は3節から6節へ。先細り・弓なり・幅と曲がりの個体差、中央の筋の明暗を加える。
  4〜12cmの芝と背の高い葉を同じ材質・区画へ混ぜる。芝は約6m、花は約12mまで。
  芝は送信時も6.5m以内へ絞り、外側でなだらかに縮める。新しい描画命令は増やさない。
- 花は白・黄・青紫の控えめな頭と緑の茎。1m升につき最大1個、23m尺度の場で群れる。
  近景の有効升に限るので2,000個以下。穂は葉の約8%の上部を茶色の形へ変えて表す。
  古い谷用の高い根を持つ花・ススキ株はlook内で置き換え、短くした葉の上に浮くのを防ぐ。
- 分布は21mと95m、乾き・湿り・日陰・手入れの場から決める。窓内の正規化はしない。
  川15mは緑・高め・密、海40mの近くと高所は枯れ色、家9mと道は短く疎。
  木・家の生きた衝突格子を参照し、日陰を暗く疎にする。道の2.5〜5mは滑らかに密度を上げる。
- 葉ごとの色相と明度、塊の乾き色を混ぜる。根は9bと同じ地面色uniformへつなぐ。
  根のAOを強め、look.normalBlend=0.78で法線を地形の差分法線へ寄せ、透けとごく弱い鏡面の項を加える。
- uHeroは同じVector4を毎コマ更新。半径は歩き0.72m〜走り0.96m、力も速度で変える。
  4個の足跡を固定配列に保持し、臨界減衰ばねの戻りで約0.8秒まで残す。飛行中は全反応を消す。
  押す式は中心と半径外で0、半径の1/3で最大1。その前後をそれぞれ単調とする。
  両端が0なので全区間を単調にはできず、この解釈をJSの試験で固定した。
- 軽量は芝なし・花の候補確率を半分。段階2は芝と花を送信せず、既存の密度0.6・3節のindex範囲へ。
  段階3は既存の全体非表示。uniform・送信・drawRangeだけを替え、geometry/materialは作り直さない。
  glook=0は9bの葉・分布・材質へ戻す。grass=0は従来どおり草全体を止める。
- 最初の窓と近景・中景の区画をwarmで同期生成する。歩行カメラの初期位置も先に確定する。
  以後の32m移動は既存の予算分割。静止して待ち行列が空なら計画処理を省く。

## 検証と数値

測定環境はNode v24.22.1、同梱Three、canvasの描画APIのみ代役。GPU描画は含まない。
私有データはKZ_WORLD_DIRから読み、座標・加工配列を保存せず、3地点の範囲だけを集計する。

- 合成格子：環境の単調性、道の帯、窓の再利用と冷間生成の一致、花の疎密と相関、反応式と戻り。
- 同梱Three：二層と花・穂、段階2での送信停止、粗いindex、移動後のプール、各資源1回のdispose。
  uHeroと足跡配列の同一参照、走り・飛行、A/B、最初のwarm後のpending=false・queue=0を検査。
- 最大寄りの合成草地（全升密・花確率1、間引き・視錐台・shaderの距離減衰前）：

| 層 | インスタンス | 三角形 |
| --- | ---: | ---: |
| 芝 | 16,588 | 199,056 |
| 背の高い葉・穂 | 45,000 | 540,000 |
| 花 | 360 | 4,320 |
| 中景（1株3板） | 47,568 | 285,408 |
| 合計 | 109,516 | 1,028,784 |

この表は私有の実際の密度ではない。送信数の上限寄りの負荷を確認するための合成条件。
段階2では芝・花0、残る葉は6三角形、密度約0.6。中景は従来の6三角形を維持する。
実測時間・最終の全体結果は末尾へ追記する。

## 親が実機で確かめる手順

KZ_WORLD_DIRに私有v0.9を指定してnpm start。基点は
`http://127.0.0.1:8080/valley/index.html?world=kamakura&debug=1`。

1. 草地 `&pos=-200.7,-192.9&yaw=300`、浜 `&pos=-992.0,-1818.3&yaw=0`、
   林床 `&spawn=asaina_pass&at=.95`、川岸 `&pos=-521.0,-2.5&yaw=45` を同じ画角で撮る。
2. 同じURLのglook=0有無と、time=eveningを比較する。根と地面、中景との継ぎ目、筋のちらつきを見る。
3. 草地でカメラを足元へ寄せ、低い層・穂・花の群れを見る。白・黄・青紫は場所により少ない。
4. 歩行・走行・停止で草が外へ倒れ滑らかに戻るか、飛行で反応が消えるかを確認する。
5. q=light、autoscale=0&adaptstep=2、同3と復帰で、芝・花・草全体と反応を確かめる。
6. 初回に草が揃うこと、移動時の窓更新、休止／再開、庭とworldなしの谷も確認する。
7. 同じ画角と経路で標準とglook=0を比較し、GPU込み増分+0.3ms目標、CPU6倍390×844のp50増分+3msを測る。

## 未確認・具体化した点

ブラウザは依頼の制約で使用していない。固定画角の前後画像、GLSL実コンパイル、GPU時間、実スマホは未確認。
地形の差分法線を近景の空き属性へ詰める。木の樹冠と家の実投影影は衝突格子からの日陰の推定で近似する。
芝・花・穂は同じ細分リボンの輪郭で表し、花弁やクローバーの三葉を別メッシュにはしていない。
私有データの初回CPU6倍はNode時間の単純6倍であり、ブラウザの実測値ではない。
三角形数は増えるためGPUの予算達成をNodeだけで断定できない。軽量・段階2/3・glook=0で比較できる。
次は親が上記の固定画角と踏み分け、GPU費用を確認し、受け入れを判定する。

## 最終の測定・コマンドと結果

- 私有3地点の初回warmは108.91〜247.27ms（うち窓80.57〜212.63ms）、旧9bは93.37〜148.12ms。
  CPU6倍の単純見積もりは約0.65〜1.48秒。最初の描画後に分割完了を待つ方式から変更した。
- 定常CPUは1,000回×5組の中央値をA/B比較し、差は−0.023〜−0.017ms/コマ。
  静止時の計画省略が効く。5m/s相当・600コマ・50m移動の平均増分は+0.066〜+0.144ms/コマ。
  CPU6倍の単純見積もりでは+0.40〜+0.86ms。GPU・実時間のp50・GCの上限は含まない。
- 私有3地点の送信三角形は74,106〜163,050。大半の芝・花は距離でも消すので、画面の描画数とは異なる。
  同時作業の全体試験中はwarmが約998msに達した測定もあった。上記は全体試験を止めた担当単独の値。
- 開始時：npm testは1,055成功・15省略、check成功、smokeはlisten EPERM。
- 最終全体：npm testは1,076成功・18省略、KZ_WORLD_DIR指定のnpm testは1,094成功・省略なし。
  npm run checkは私有指定なし／ありとも成功（422構文・谷101モジュール）。
  smokeは終了時もlisten EPERM。HTTP待受けが禁止された環境のため実ブラウザ確認はできない。
- 途中の全体回帰では担当外の施設ftexと家のDeltaEの2件が失敗した。1分以上後の全体再検査では両方成功。
- 最終の小変更（送信時の葉ごとのsubarray確保を廃止）後も9c試験12件と既存の草18件が成功、私有1件省略。
- git diff --check成功。文書lintはsudachipy未導入で起動できず、natural-japaneseの手動チェックで確認した。
- 新規：kamakura-grass-look.js／kamakura-grass-look-view.js、9c試験と私有検証helper、この記録。
  更新：grass-view.js、kamakura-grass-field.js／view.js、world-kamakura.jsの草の配線、既存の草試験、tasks.md、FILES_SHA256.json。
