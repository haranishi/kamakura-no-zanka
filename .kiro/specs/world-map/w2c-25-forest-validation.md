# 森の密度と紅葉の検証

密林・疎林・開地を分け、木を18.64%減らした。機械検証は通った。画面の改善は未判定。
次は実際のChromeで、開地が草と岩に見えるか、杉の塊と紅葉が帯や水玉に見えないかを確かめる。

## 要求への対応

|要求|結果|
|---|---|
|F1 密度のむら|実装。大きなむらと細かな輪郭を共有し、尾根と谷の両肩へ密林を寄せる|
|F2 群れの丈と色|実装。中心ほど高く、疎林は低くする。紅葉と松を疎林へ寄せ、遠景の板にも同じ倍率と色を渡す|
|F3 里の紅葉|色を実装。5段の色を位置雑音で選び、近い順の経路で3本同色の連続を防ぐ|
|保護域の樹冠だけの拡縮|見送り。遠景の板は幹と樹冠が一体のため、幹を変えず全LODでそろえられる色を優先|
|切替と確認の入口|実装。forest3=0で従来の配置・色へ戻し、forest3debug=1とtreeStatsで確認|
|Chromeの前後撮影・性能|未実施。今回はブラウザを使わない指定。見た目・FPS・GPU時間は未確認|

WW18と木の既存設計を引き継いだ。既存の保護木を先に確定し、その外だけ植え直した。
雑音の低い領域をそのまま開地にする試作は、幅456mの開地につながったため不採用。
中心をずらした領域を大小の位置雑音で歪める方式にし、開地を分離した。
稲の配置・木の材質と焼き込み・霧・棚田・規則・セーブは変更していない。素材・依存・新規モジュールの追加なし。

## 構成と保護の実測

- 面積の母数はXZが1280m四方の8m格子から保護域を除いた24,799点。画面の占有率ではない。
- 密林48.56%、疎林32.60%、開地18.84%。8m格子で連結した開地131か所（領域端で切れるものも含む）。
- 4m格子で境界に切られない開地96か所の幅は44〜80m。縦横比と輪郭が変わり、円形の複製ではない。
- 成木15,717→12,787本（2,930本減、18.64%減）。開地の幹0本。見通しと砦の除外範囲を維持。
- 密林の幹6,707→9,288本、疎林4,961→2,620本。面積密度から換算した密林の間隔は従来の0.8498倍、疎林は本数の52.81%。
- 密林の杉の丈は中心平均1.2918倍、縁平均0.8156倍、中心÷縁1.584。疎林の丈は0.55〜0.9倍。
- 杉以外の割合は密林20.36%、疎林61.60%。外側の杉8,403・欅1,297・松897・楓1,311本。
- 保護域の1m格子71,264点のheightAtとforestDensityは、変更前に採取した固定ハッシュと完全一致。
- 保護木879本の位置・種類・大きさ・向き・季節段階も固定ハッシュと一致。幹の当たり・遮蔽の入力を保った。
- 保護域は樹冠も拡縮していない。軽量の遠景間引きも従来の採否を保持。幹の描画行列と色が従来と一致。
- 保護域の広葉は5色を使用。forest2=0では従来の色と行列。forest3=0の全配置と派生種も従来の固定ハッシュと一致。
- 同一入力の再生成、配列順の反転、標準・軽量の色、外側のLOD重複帯の色と倍率が一致した。

## Chromeでの次の確認

1. `/valley/index.html?qa=1&autostart=new&intro=0&cam=concept&q=standard` と、末尾に `&forest3=0` を足した画面を比較する。
2. `&forest3debug=1`：密林＝濃緑、疎林＝黄緑、開地＝黄、急な岩肌＝灰。地面と木の分類がそろうかを見る。
3. `__valley.treeStats().stats.forest3` でarea・before/after・openings・workを読む。面積の母数もareaHalf/areaStep/areaSamplesで確認する。
4. 里の紅葉で5段の色を見比べる。`&forest2=0` で従来の色へ戻ることを確認する。
5. `&q=light` と自動品質の低下を試し、群れの主色が残り、遠くの木の数が減るかを見る。近づく動画でLODの跳びと影も確認する。
6. `tools/scenarios/capture-concept.mjs` で同条件の前後を撮る。開地の縁の地図補間、尾根の輪郭、里の紅葉が帯や水玉に見えないかを優先する。
