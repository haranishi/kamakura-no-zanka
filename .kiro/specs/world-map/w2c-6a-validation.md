# W2c-6a 地面の色の実装と検証

依頼書 BRIEF-W2C6A.md と、委譲元の design-web.md・tasks-web.md の W2c-6a を適用した。
実装とNode検証は完了。見た目の受け入れは親の実機確認を待つ。
他の作業場所と私有データは読み取りのみ。commit・push・ブラウザ操作は行っていない。

## 実装

- schema 0.5 を追加し、0.1〜0.4 を維持した。
- ground_rgb.bin を私有マウントから読む。ファイル名を固定し、リダイレクトを拒否する。
- データなし・長さ違い・読込失敗は単色で続行し、HUDへ案内を出す。
- groundColorAt は格子中心を基準に、sRGBを線形光へ変換してから双一次補間する。
  範囲外は端へ固定する。縦倍率・LOD・パッチの高さには依存しない。
- 基本格子・細密パッチ・縫合用頂点が同じ問い合わせを使い、Float32のRGB属性を持つ。
- 頂点色ありの材質は白を掛ける。ground=0 とデータなしは従来の単色材質を使う。
- 形状・法線・縫合・LOD・生成予算は維持した。world指定のない入口は変更していない。
- 新素材・外部通信・ビルド・npm依存の追加なし。色の元データや固定標本は保存していない。

- FILES_SHA256.json は git ls-files -co --exclude-standard の全ファイルを再計算。
  manifest自身を除くpath・size・sha256を照合する。

## メモリの概算

色属性は1頂点12バイト。CPU属性とGPU転送先をそれぞれ同量と見積もる。
私有v0.5を使い、出発点の既存LOD計画で形状を生成し、属性のbyteLengthを集計した。

- 最寄りの近景チャンク：8,509頂点・102,108バイト（約99.7KiB、CPU側）。
- 近景LOD1のチャンク：102,108〜437,304バイト。細密パッチの量で変わる。
- 出発点の半径420m内：911,904バイト（約0.87MiB）。
- 出発点で距離3300m未満の生成が一巡したとき：547チャンク・15,558,636バイト（約14.84MiB）。
- GPU側も同量とした合計は約29.68MiB。ドライバー管理分・生成中の一時配列は含まない。
  元のRGB格子の保持領域は頂点色属性とは別。実機のメモリやコマ時間は未測定。
