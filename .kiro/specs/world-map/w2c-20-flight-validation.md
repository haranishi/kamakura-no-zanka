# 道を上る人と浜の人：検証記録

山道の組と浜の人を実装した。人は、道を上っていく。

実 Chrome（設計した鎌倉・夕方）で、道の上を歩く視点から見た。笠をかぶり荷を背負った 4 人の組が、坂を上る。足は地面に付き、主人公を避ける。コンソールのエラーは 0。直す所が 1 つある。近くの人の笠・荷・杖が、1 色の円錐と箱と棒で、確認用の形に見える。次の直しで、形と色を作り込む。描く時間（GPU）と、見渡す構図での見え方は、退路の地形ができてから確かめる。

設計した鎌倉では、舟6組のそばに12人を配置し、南の見渡しでも12人が描画対象になった。

## 判断と残した制約

- 仕様はWW16・WW17と既存の人影の検証記録を引き継いだ。新しい外部素材・依存・モジュールは追加していない。
- 近景と遠景は同じ場面の時計・同じ式で位置を求める。主人公のすぐそばでは既存の避け方を優先するため、位置の一致の対象から外れる。
- 飛行中は道の人をすべて人形にする。水平距離で近景へ替えると、真下の人が消えたり、骨の上限を使い切ったりするため。
- 従来の人物は元のアニメーション時計を保ち、道の組だけ場面の時計を使う。切り戻しで会話やお辞儀のタイミングを変えないため。
- 歩くときは最大6人を近景に優先し、残りを人形で残す。近景全体の上限10人は維持する。
- 動く組だけを毎コマ更新する。静止した町の人影は従来どおり、視点が動かなければ選択・転送を増やさない。
- 浜の人は、港と同じ舟の配置を使う。沖の探索は省き、町の密度とは別に先に席を取る。後から配列を削ると、途中まで読んだ遠景の層と食い違うため。
- 旗は `flight=0` と `shorepeople=0`。後者は追加した浜の人だけを切る。`harbor=0` でも追加分を切る。
- 既存テストの緩和・削除はしていない。既存モジュール内の変更なので検査一覧の追加は不要。

## 実Chromeで確かめる手順

1. 配信する地図の `meta.json` に `"flight":{"road":"pass","groups":6,"size":[2,4],"speed":0.8}` を追加する。`roads.json` のキーが `pass` であることを確認する。
2. `/valley/index.html?world=kamakura&fly=1&cam=overlook&debug=1` を開く。脱出場面の見渡しで、道の5組以上が列として読めるかを見る。
3. `&flightdebug=1` で道の人を橙の柱にする。`__kzFlight()` の `groups`・`drawn`・`nearest`・`triangles`・`shadowTriangles`・`draws`・`work` を確認する。
4. `&crowddebug=1` は遠景全体の役の色。水色＝歩行、桃＝会話、黄＝座る、緑＝農作業、紫＝参拝、橙＝子／道の組、白＝浜。影を見るときは確認色を外す。
5. `fly=1` を外し道へ近づく。`&peopledebug=1` と `__kzPeople()` で近景の道の人が最大6人・全員で最大10人か、入れ替わり・坂の足・主人公回避を確認する。
6. 始点と終点で12mの消失を見る。午前・昼・夕方前・夕方・夕暮れに替えても組が出るかを確認する。
7. 帰還場面の南の見渡しで浜の白い印を見つけ、近づいて舟の脇と干し場に立つかを見る。`__kzCrowd().byRole.shore` と照合する。
8. `&flight=0&shorepeople=0`、`&q=light`、`&adaptstep=3&autoscale=0`、休止・再開を比べる。前後の固定画角を保存する。
