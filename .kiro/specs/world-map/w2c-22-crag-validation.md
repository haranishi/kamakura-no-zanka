# 切通しの岩壁：形状生成は検証済み、見た目は実 Chrome で確認する

角のある塊と水平の層を追加した。輪郭の埋まり方・高さ・面の向き・予算・切替は Node で確認した。
実 Chrome は動かしていない。95m先・55m上からの見え方、近景の地形の露出、夕暮れの陰影は未判定。
既存の設計した地図へ例の2範囲を重ねると、標準4,337・軽量3,557三角形、描画は各1回だった。
次は、下の例を検証用の世界に足し、同じ画角で無効・通常・確認色の3枚を撮る。

## 要件・設計・作業の境界

- WW16・WW17と、岩の塊に関するC1〜C5を引き継いだ。新しい地形や当たり判定は作らない。
- 順序は、入力検査 → 凸領域の割付 → 高さと色 → 三角形 → 表示配線 → 試験。
- 小さすぎる領域は単に消すと穴になるので、その点を外して分割し直し、隣へ面積を戻す方式を選んだ。
- 任意データがない世界の登録一覧を保つため、岩の範囲がある場合だけ、作り物の直後に層を登録する。
  最初の全体試験は、固定された登録一覧の期待値と衝突して1件失敗した。既存テストは変更していない。
- 適応品質の形は開始時に4段階を準備する。切替で再生成しない代わりに、準備時間と保持メモリは増える。
- 指定された3つの新規ソース・試験、作り物の読込、層登録、配布検査、この記録だけを変更した。
  読込結果は既に共通contextへ渡っていたため、データ読込元と世界の本体への追加配線は不要だった。

## 実 Chrome での確認手順

1. 下の例を検証用の `works.json` に足す。`meta.works.file` は `works.json` にする。
2. `/valley/index.html?world=kamakura&debug=1&fly=1&cam=overlook&time=dusk` を開く。
   切通しを約95m先・約55m上から見る既定カメラの世界を使う。
3. 同じ位置で `&crag=0` と比較する。なだらかな円錐から、垂直の面・棚・角のある輪郭に変わるか見る。
4. `&cragdebug=1` を足す。水色＝岩の頂、緑＝土と草の頂、黄＝面取り、桃＝壁と層の棚。
   `__kzCrag()` で数・倍率・最も高い壁・最近の塊の距離と方位を読む。
5. 歩く視点で壁から2〜10mまで寄り、継ぎ目や面取りから地形が突き出ないか見る。
   通常色へ戻して、日なたと日陰の差、霧と影を確認する。軽量品質と適応段階でも繰り返す。

## 残る制約

- 実Chromeの画像・FPS・操作感は未確認。見渡しで「岩」に読めることは、Nodeの数だけでは保証できない。
- 旧版の設計した地図で例を測った。現在の退路の地形での画は未確認。配布データは変更していない。
- 100mを超える高低差が複数ある極端な合成入力では、塊を粗くしても壁の層数が減らず、予算超過の例外になった。
  通常の切通しを対象とし、このような入力を自動で別形状へ置き換える対応は見送った。
- 地面色のない世界で岩の範囲を指定すると、色の不足を例外で知らせる。架空の代替色は追加しない。
