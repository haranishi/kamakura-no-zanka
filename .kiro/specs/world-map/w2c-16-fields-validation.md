# W2c-16h：色の野の実装と検証

指定されたファイル内で、5種類の野・株・区画管理・共有風への追従を実装した。
Nodeで地図と資源上限を検査した。実Chromeの描画・見え方・性能は親担当の確認待ち。
基準は WW13.8、design-web-r10.md と COMMON → FIELDS の依頼書。既存の草は変更していない。

| 要求 | 状態・判断 |
|---|---|
| C1 野の地図 | 実装。種・300m単位の種類・8mの縁・場所の重み・禁止領域を使用。 |
| C2 株の形 | 実装。5種類の近景と十字2枚の遠景。花数・穂数・高さ・向き・色に個体差。 |

## 設計で選んだ方法

- 近景5プールと共通遠景1プールで6描画に収めた。遠景の色は近景の面積加重平均。Lambertの霧・影・色空間処理を継承する。
- 固定バッファの上限は14,100インスタンス・134,880三角形。うち遠景は12,000株。
- 近景の枠が満杯の株は十字の代役を維持する。上限を守るための変更で、密な野の近景品質は実機で判断する。
- 遠い区画を後に作り、枠が不足する場合は遠い区画を優先して減らす。
- 株の候補生成と転送を分割する。1更新は384作業単位以下・完成4区画以下、時計の予算は1.5ms。
- 作りかけは頂点の大きさ0。完成区画だけを公開する。60〜70m（軽量35〜45m）で大きさを滑らかに変える。
- 24〜28mで近景を縮め、28〜32mで遠景を広げる。両方を同時表示しない。
- OSの動きを減らす設定では揺れと押し分けを40%にする。品質段階2は45m・密度60%、段階3は非表示。
- 明るさは線形値0.85以下。1.2画素未満の特徴は輝度0.30を目安に抑え、透過光の加算を切る。
- 画像・音・モデルの追加、外部通信、依存追加、私有地形の値の転記は行っていない。

## Nodeで測った値（合成世界）

- 一様な草原3km四方を5m間隔で標本化：野の被覆20.5522%、内部の強さ1が69.24%。
- 同じ標本の断面で連続した野は最大75m。種の変更で配置が変わり、同じ種なら一致する。
- 100㎡の桔梗：通常787本、強さ半分388本、密度2倍1,600本。禁止領域には配置しない。
- 近景の三角形はススキ54・桔梗48・女郎花36・山百合46・浜昼顔20、遠景は各4。
- 2,000コマの歩行・走行・旋回で最大12,450インスタンス・69,600三角形。資源上限とバッファ同一性、転送範囲の有界性、各資源の1回解放を検査。
- 近遠の面積加重平均色の差は最大3.47e-18、高さの差は最大0.00368m。
- これらは描画なしのNodeの値。Chromeの+0.6ms／野のない場所+0.05ms／生成時4ms以下は未測定。

## 親担当が実Chromeで確かめる手順

1. `/valley/index.html?world=kamakura&debug=1&fields=1&fieldseed=1618` を開く。
2. 静止して `__kzFields().nearest` を読む。探索は20m間隔・周囲±400m、約211コマで1巡する近似。
   `bearing` は北0・東が正のラジアン。現在の東／北に `distance*sin(bearing)`／`distance*cos(bearing)` を足し、`&pos=東,北` で移動する。
3. 必要に応じて `&fieldseed=<整数>` を変え、`&fieldsdebug=1` で種類のまとまりと場所との一致を見る。
4. 野の中・縁・遠景を同じ画角で撮影。`&fields=0` と比較し、既存の草の出力に戻ることを確かめる。
5. 10秒録画し、突風の波・穂と花の透過光・半径0.9mの押し分けを見る。道・建物・水際は空ける。
6. 70mから走って近づき、外周と24〜32mの切替で突然生えたり色が跳ねたりしないかを見る。
   `&fields=2`／`3`、軽量、自動段階2／3、動きを減らす、休止復帰も確認する。
7. `__kzFields()` で株40,000以下・三角形150,000以下・描画6以下を確認。
   同じ野で無効時とのコマ時間を比較し、標準+0.6ms・野なし+0.05ms・生成コマ4ms以下を測る。

未確認：実機の見分けやすさ、GLSLコンパイル、LOD時の見え方、全5種の実地形での出現、GPU性能。
次の最小の一歩は、親担当がススキの野で無効時との固定画角比較と10秒録画を行うこと。
