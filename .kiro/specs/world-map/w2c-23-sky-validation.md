# 谷の夕景：橙・桃・紫の空と、見渡しで読める霧

2026-11-12。WW18.7〜18.9。空の色の上書きと夕焼けの計算を修正した。
実際の Chrome で、見渡しと歩く視点を撮った。空の低い所が金色になり、日なたが暖かい色になった。エラーは 0。
霧は、濃くした最初の値では白い板に見えたので、薄くした（下の「実際の Chrome で見て直したこと」）。日の円盤は、まだ画面に出ていない。
配置・任務・規則・セーブ・鎌倉の実装は変更していない。

## 判断の理由と落とし穴

色の上書きは材質生成より先に届いていた。時刻や読み込み順の問題ではなかった。
旧式の低い空はhorizonではなくhazeCool/hazeWarmから作り、最後にも霞の色を重ねていた。
mid/zenithも使っていたが、淡い既定色と強い円盤・散乱で差が弱かった。
谷の空を専用の色帯へ替え、材質生成時にATMOSの4色を読む。鎌倉の旧式はそのまま残す。
円盤だけ強くしても、山や木による遮蔽は直らない。高度15.5度と影の向きは保った。
霧の濃さだけ増やしても、垂直な帯は俯瞰で細くなる。近い帯を奥行きのある低い弧へ替えた。
段間の霧にも日の鞍部を反映する。これを省くと山のくぼみを横切る幕になる。
里の平場を保護するので、今回の帯の霧は戦闘域の足元にかからない。

## 実Chromeで次に確かめること

1. `/valley/index.html?qa=1&autostart=new&intro=0&cam=concept&w=1280&h=720`。
   同じ時刻・画角で通常色と切り戻しを撮る。空の低い所の橙、上の桃と紫、雲下面の暖色を見る。
2. `&sky2=0&mist2=0&sun=old&ridges2=0`で従来と比較。個別の旗も比較する。
3. `&sky2debug=1`は橙＝雲・紫＝空。`&mist2debug=1`は水色＝帯。
   `&ridges2debug=1`は手前から緑・青・橙・紫。通常色でも霧を4本以上数える。
4. `__valley.game.atmosphere.stats()`で量を読む。`__valley.quality('light')`でも確かめる。
5. 里・棚田・橋・林内を歩き、白い板、山と霧の重なり、敵と足元の明るさを見る。
   円盤は地形と木で隠れる場合がある。木の輪郭の背後のにじみと、ブルームの白い塊を点検する。
6. `&lk=horc:ff9050,midc:d59a9c,zenc:4d568c,sunc:ffca85`で4色を試す。
   効き目を強く比べる例は`&lk=horc:ff5020,midc:ef8294,zenc:303c80,sunc:ffb050`。

## 実際の Chrome で見て直したこと

- **川面が白く飛んだ。** 北東への逆光で反射のにじみが橋を覆った。`water.js`の`WATER_GLINT`で上限を付けた。
- **日の側で4段の稜線が同じ高さに集まった。** 日を上げても鞍部が光線より58m高いままだった。`RIDGES.notchOffset`を−40mへ直した。
- **稜線の試験が古い構図を使っていた。** `shots.js`のconcept（俯角約13.5度・画角62度）を直接使うように直した。
- **霧が、白い半透明の板と、こぶに見えた。** 濃さ 0.48・最低密度 0.55・縁の幅 25% の帯は、棚田の上に大きな白い膜として掛かり、木立の上に白い丘のように盛り上がった。濃さを 0.36 に下げ、帯の上下と左右の全体をなだらかに薄め、60m より近くでは描かず、厚さを 16 → 11m にした。
- **日なたが、くすんだ黄土色だった。** 日を動かしただけでは、金色の夕方に見えなかった。仕上げの色調を、露出 1.08・暖色 1.1・彩度 1.05 にした（`SKY.grade`。`&sun=old` では使わない。番地の `?lk=` が、あとから勝つ）。歩く視点で、地面と主人公は白く飛ばない。
