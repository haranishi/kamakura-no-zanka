# 谷の夕景：日を北東へ動かし、空・山並み・霧を作り直した

2026-11-12。WW18.7〜18.9を対象とする。配置・規則・セーブは変更していない。
実際の Chrome で、見渡しと歩く視点を撮った。夕方の光になった。木と家の長い影が手前へ伸び、空には紫の雲がかかり、奥には青い山並みが 3〜4 段に重なって見える。色の段々は出ない。エラーは 0。
日の高さは、はじめ 7.5 度だった。ところが、北東の山の縁は、見渡しの位置から見て 14.65 度の高さにある。日は、谷のどこからも見えなかった。そこで、縁のすぐ上の 15.5 度へ上げた。それでも円盤は画面に出ない。縁に生えた木に隠れるためである（下の「残る確認」）。

|要求|結果と残件|
|---|---|
|S1 夕日と明るさ|北東55度・高度15.5度、橙色と補助光を実装。歩く視点の里は、主人公と地面が読める明るさを保つ（実際の画面で確認）|
|S2 空と雲|暖色の縁・紫の雲・緩やかな流れ・出力の階調雑音を実装。山の端の円盤は未完了|
|S3 山並み|標準4段、軽量2段。地形と投影を含め、conceptの方位15・20・30度で3稜線を数値確認|
|S4 谷の霧|川とくぼ地8本、山の段間3本。接近時に薄くし、旧い水平帯へ戻す旗を実装|

山の高さは全周を一律に増やさず、奥の稜線の角度を分けた。
霧は遠くの斜面に色を塗る方式から、地形に位置を合わせた帯へ替えた。
透明な帯が交差する場所の重なり順と、歩く高さでの端の見え方は実画面で判断する。
鎌倉側が空の設定を共有していたため、3つの参照元は旧設定を読むように分けた。
関連する6つの試験も旧設定を明示する形へ変更し、数値の期待値は弱めていない。

## 実Chromeで次に確かめること

1. `/valley/index.html?qa=1&autostart=new&intro=0&cam=concept&w=1280&h=720`を開く。
   conceptの配線は別の変更に依存する。無ければ既存のQA口で同じ画角を指定する。
   `__valley.camera([-50,40,110],[12,5,-80],50); __valley.step(1)`。
2. `&sun=old&sky2=0&ridges2=0&mist2=0`と既定を、同じ時刻・画角で撮る。
3. `&sky2debug=1`は橙＝雲、紫＝空。`&ridges2debug=1`は手前から緑・青・橙・紫。
   `&mist2debug=1`は水色＝霧の帯。通常色も必ず撮り、色だけで山の数を判定しない。
4. `__valley.game.atmosphere.stats()`で数を読む。`__valley.quality('light')`でも数える。
   自動段階は実際の解像度倍率から追従する。固定撮影は倍率を固定する。
5. start-thirdperson・forest-road-scout・village-fight-wideで人物と足元を新旧比較する。
   主人公と地面の同じ領域の輝度が旧版の0.8倍を割らないかを測る。
6. 川岸と林内のくぼ地に近づき、白い板・水平線・透明の重なりを点検する。

## 実際の Chrome で見て直したこと

- **川面が白く飛んだ。** 日を北東へ動かすと、見渡しのカメラが日を正面に見る。水面の鏡面反射が強く、にじみが橋まで覆った。水面から出る光に上限を付けた（`water.js` の `WATER_GLINT`）。
- **日の側で、4 段の稜線が同じ高さに集まった。** 稜線のくぼみを「日の光線より 58m 高い」ままにして日を上げたためである。くぼみを、光線より 40m 低くした（`RIDGES.notchOffset`）。
- **稜線の試験が、手で写した古い構図を使っていた。** 4 段目が、その構図の上の端にちょうど乗っていて、日の高さを変えただけで落ちた。決めた見渡しの構図そのもの（`shots.js` の `concept`）を使うように直した。
