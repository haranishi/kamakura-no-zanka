# W2c-9r3 shore：川の色・泡・海の汀線

川の青緑と透ける浅瀬、不規則で明るさに上限のある泡、広い濡れ砂を実装した。
Nodeで泡幅の変動係数0.54、断片長1.34を確認。画像の合否は親の実機確認へ渡す。

## 継承と設計判断

- world-mapのWeb要件・設計、R1/R2水際仕様、今回のCOMMON/SHORE依頼を継承した。
  共有タスクとFILES_SHA256.json、谷・庭・保存、他担当の実装は変更していない。
- R2で川の反射強度が0.95から1.65へ増え、浅瀬が暗い灰緑に変わったことを確認。
  灰色化の原因と推測し、反射を0.95へ戻して岸距離と深さから青緑・砂色・透明度を出す。
  彩度・B−RのR1比と雲の映り込みは未測定。
- 泡の幅は2段階のノイズ、実際の曲がり、左右別の岸勾配から決める。
  長い欠けと短い断片を別スケールで混ぜ、R3では2列目の平行な泡を出さない。
  半透明の水面上で泡を65%以下で混ぜ、表示変換と霧の後にもRGB各成分を0.85以下へ制限。
  後段の画面効果を含めた最大輝度は実機で確認する。
- 離れた輪には魚の跳躍を出どころとする経路がある（kamakura-fish.js）。
  足の接触・脚の周囲・飛沫着水にも発生源があり、任意座標の自動発生は見つからなかった。
  魚の跳躍と輪は維持。講評画像の輪そのものとの対応は未確認。
- 海の薄さは、R2で近景の濡れ幅を0.6〜1.5mへ狭めたことと、距離場完成まで
  泡も濡れ砂も出ない分岐を確認。実画像でどちらが支配的だったかは未確認。
- 近景の濡れ砂は1.5〜4m、泡は幅0.3〜1mの3本で寄せ引き・欠けを持つ。
  遠景は濡れ砂の半強度幅12pxを狙い、世界幅120mで上限を設ける。
  幅の境目は2スケールのノイズでずらす。極端に浅い視線では上限により保証外となる。
- 初回は最大65×65の粗い符号付き距離場を用意し、海と地面で同じテクスチャを使う。
  細かい距離場は既存の時間予算で作り、別のテクスチャへ切り替える。GPU画像の寸法は変えない。
  粗い場の一括準備は有限の小格子に限定。切替時の位置差は残る可能性がある。
- `shore3=0`でR2、`shore2=0`で従来経路。軽量/段階2は川泡55%・海1本、段階3はR3を切る。
  R2の交点平滑化、隣接変位制限、三角形の細長さ制限を維持した。

## 検証の証拠

全試験・check・smokeにNODE_OPTIONS=--max-old-space-size=1536とtimeout 300を付けた。

- 開始時：npm testは1,255成功/27省略。npm run check成功。
- 泡幅CV=0.544、断片長CV=1.344。幅/長さを均一にした破壊版は同じ検査で失敗する。
- 合成の浅瀬は透明度0.32、深部は0.85。深部の色は青緑で、変化は連続・単調。
- 画素幅0.001〜5mで、濡れ砂の半強度幅10px以上。
  高さ720/844px・FOV54/65/72°・視点高1.7m・距離25〜100mの合成投影でも10px以上。
  05の実際の地形・遮蔽・視角を含む測定ではない。
- GLSLそのものの幅式をJSで評価して一致を検査。狭くした破壊版は失敗する。
- 同梱Threeで、初回の海/陸の符号、地面とのuniform共有、寸法固定のテクスチャ切替、
  品質往復、安定したバッファ、dispose各1回、生成shaderの括弧・条件・予約語を検査。
- 終了時：npm testは1,261成功/27省略、KZ_WORLD_DIR指定のnpm testは1,288成功/省略なし。
  npm run checkとgit diff --checkも成功。最終の関連59試験は51成功/私有データなし8省略。
- 私有データで水面の定常CPU更新は約0.000091ms/回、準備中の最大更新44.74ms。
  全試験2本の同時実行下のNode値で、GPUや通常フレームの増分を表すものではない。
- 日本語文書lintはsudachipy未導入で失敗。追加導入せず、クイック工程の観点で手動通読した。
- 初回の全試験でNode用モジュール読み込みの相対パス解決が1件失敗。
  既存shore公開口を再利用して修正し、関連試験で成功を確認した。
- smokeは開始時・終了時とも127.0.0.1のlisten EPERMで失敗。
- git addはworktree管理領域のindex.lock作成がOperation not permittedで失敗。
  commit未作成、変更を未ステージで保持。push・PR・マージはしていない。
