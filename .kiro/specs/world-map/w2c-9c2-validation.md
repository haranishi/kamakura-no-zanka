# W2c-9c2 中景の株を戻し、尾根の浮く板を抑える

依頼書9c2を仕様として引き継ぎ、草の担当ファイルだけを修正した。
Nodeで分布・接地・色の契約・GLSLの構造を検証する。実画面とGPU性能は親の実機確認が必要。

## 採った設計

- 中景専用の密度を近景の密度から分離した。21m・95mの場を共用し、家・施設・塀の
  衝突箱、木の衝突円、川15m、斜面の傾きに応じて株を増やす。道2.5〜5mでは疎にする。
  斜面の変わり目は傾きの帯で近似する。地形の曲率や壁の専用地図は追加しない。
- 近景の二層・花・穂・主人公への反応式は変更しない。中景の高さは0.35〜0.70m、
  幅0.65〜1.30m、傾き±0.08rad。色相・高さ・幅・傾きは世界座標から決定する。
- 株の色を陰側の緑へ暗くし、線形地面色の平均×0.68へ最大40%混ぜる。
  色と混色先には線形RGB各成分0.035の下限を設ける。これは照明前の下限であり、
  夕方の最終画素の黒つぶれをGPUで保証する数値ではない。
- 12〜60mは株を残し、60〜95mで12%へ間引き、102〜120mで消す。
  中景は一括送信してCPU負荷を抑える。軽量は既存の距離倍率0.6、段階2は密度0.6、段階3は非表示。
- lookありだけ窓を256→352mへ拡大。176−32−120−6=18mの余裕を持つ。
  同期warmと毎コマの準備予算2ms（軽量1.5ms）は維持する。
  glook=0は従来の256m窓・70m中景・60%混色と親の×0.68の暫定色を保持する。
- セルの32°除外を保ち、中景生成でも四隅から36°超を除外する任意引数を追加。
  根元は四隅の双線形補間−0.12m。傾いた各板の実法線と視線の内積が0.04〜0.16で
  形を縮め、真横に見える板を消す。乾いた茶色も陰側の緑へ寄せる。
- 共用grass-field/viewは省略時に元の経路を使う任意設定だけを追加。
  谷の6通りの出力SHA（送信バイト・形状・枚数・シェーダー文字列）は既存試験で維持する。
  world-kamakura.jsの変更、依存追加、外部素材、通信、commit/pushは行わない。

## 合成草地の比較

全升が草の256m四方、種1333、合成の代表点A/B。同じ世界座標で比較した。
9b前はreach省略（25m）、混色先#6b6a35。現在は環境の場とlookあり、120m。
12〜60mで送信済みかつ距離で残る株を数えた。1株は交差3板・6三角形。
色差は線形地面色(0.25,0.32,0.13)と代表的な中性灰テクスチャ値0.62から計算した
照明前のCIE76 ΔE。GPUのテクスチャ・光・霧・視錐台・真横の板の判定を含まない。

## 検証

- 合成：混色定数の範囲、暗い地面の下限、家・木・水辺・道の密度の単調性、
  窓の再利用と冷間生成の一致、四隅の急斜面、根元の埋め、株数と寸法とΔE。
- 同梱Three：near/mid、標準/軽量、lookあり/なしについてonBeforeCompileを実行。
  全includeを展開した文字列の波括弧・丸括弧・角括弧・#if/#ifdef/#ifndef/#endifを検査。
  不正な括弧、孤立した#endif、閉じない#ifdefを検査が拒否することも確認する。
  これはGPUコンパイル試験ではない。
- 既存の資源解放、品質切替、A/B、二層、花、反応、谷の出力一致の試験を維持。
  中景120m化に合わせ、ストリーム完了を待つ試験の上限を250→1,000回に変更した。
  起動時に既に失敗していた旧地面色の期待値を、新しい×0.68の契約へ更新した。
- 中景を一括コピーし、lookありの再計画間隔を0.25→1mへ変更。
  芝のCPU受付を7mへ広げ、1m動いても既存の6mの描画範囲を覆う。GPUの近景の式は維持する。

## 親が実機で確かめる手順・未確認

基点は `/valley/index.html?world=kamakura&debug=1`。

1. `&pos=-200.7,-192.9&yaw=120` と `&yaw=300` で塀沿い・家の前の12〜60mの株を見る。
2. `&spawn=asaina_pass&at=.95` で右の尾根を見て、空に茶色い板が浮かないか確かめる。
3. 同じ画角に `&time=evening` を付け、株が暗い一面にならず根元が地面につながるか比べる。
4. `&glook=0`、`&q=light`、`&autoscale=0&adaptstep=2`、同3と復帰を比べる。
5. 同じ経路を歩き、窓の切替、芝・花・反応、1m再計画による欠けや変化を確かめる。
6. GPUコンパイルログ・固定画角の前後画像・1コマ増分+0.2ms以内、
   CPU6倍390×844のp50増分+3ms以内を実測する。

ブラウザを使えない契約のため、画像・実GPUコンパイル・性能予算達成・夕方の最終画素は未確認。
次の最小ステップは、親が上記の画角と性能を測り、受け入れを判断すること。
