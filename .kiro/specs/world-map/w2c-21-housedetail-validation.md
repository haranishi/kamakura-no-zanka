# 遠くの家の作り込み：検証記録

設計した鎌倉で、作り込み対象の98軒を見渡す位置から描けた。82,458三角形・24描画命令で、目安の60万三角形・120命令を下回る。実 Chrome の見た目とちらつきは未確認。次は同じ構図の前後を撮って比べる。

## 要件と判断

|要求|結果|
|---|---|
|H1 地図ごとの距離・軒数とURL上書き|実装。範囲外を断り、設定なしの60〜75m・90軒を維持|
|H2 遠景の形と細部のちらつき|実装。形・質感・色は継承。細い装飾だけ別群にし、距離と画素数でディザ消去。画の合否は未判定|
|H3 分割構築・品質・予算|実装。近い候補の型から構築。未完成の家は元の形を表示。軽量品質と品質段階2以上では従来どおり作り込みなし|
|H4 確認の口|実装。現在の方針、品質、作業量と描画量を確認できる|

近景と遠景の家を別々に作り直す方式は、切替時の形や明るさが変わるため採らなかった。元の面をそのまま構造と装飾に分け、屋根・棟・軒・柱・戸口を構造側に残す。細い部品の上限は一律に緩めず、画角と描画画素数に合わせて短くする。

変更は家の構築・表示・材質・規則の4ファイル、データ検査の配線、家の試験2ファイルと本記録だけ。新しいモジュール・依存・素材は追加していない。元データや模型は変更せず、commitもしていない。

## Nodeでの計測

指定された設計世界の控えを、町の家を補う処理まで実ゲームと同じ読み込み口で読む。検査時だけメモリ上のmetaに `house_policy={full_m:700,swap_m:760,cap:200}` を追加。`cam=overlook`、1672×940画素、標準品質。GPUによる実描画の計測ではない。

|対象|軒数|三角形|描画命令|完成までの更新|
|---|---:|---:|---:|---:|
|家の作り込み|98|82,458|24|250|
|元の形の提出分（ディザで隠れる面を含む）|—|5,748|34|—|
|両者の提出合計|—|88,206|58|—|

構築は426段階、1更新あたり最大2段階・新しい描画群1個。構築中の更新は250回。単独測定の最大構築片は約1.7ms。時間と完了回数は機械の負荷で変わるので固定値の合否にはしない。合成世界200軒でも完成し、遠景は174,088三角形、14更新だった。

## 検証コマンド

`PRIVATE_WORLD_DIR` と `DESIGNED_WORLD_DIR` は、それぞれ指定された読み取り専用データと設計世界の控えを指す環境変数。

|コマンド|結果|
|---|---|
|着手時 `npm test`|1,993成功・0失敗・63スキップ|
|着手時 `npm run check`|成功|
|着手時・終了時 `npm run smoke`|各1失敗。いずれも環境の `listen EPERM`|
|`NODE_OPTIONS=--max-old-space-size=1536 timeout 600 npm test`|1,999成功・0失敗・65スキップ|

既存試験を弱めず、GLSLコンパイルの対象を増やした。既存のディザを通したシェーダー文字列はHEADとの8比較ですべて同一。通常・確認色・質感なし、構造・細部・元の形、影を含む288段階が成功。近景の面・法線・UV・色の係数が分割前と同じこと、3次元の距離、近い順と上限、画素数による消去、作業量、切替と解放を検査する。

## 実 Chrome で確かめる手順

1. 設計世界を既存の方法で読み込ませ、標準品質・1672×940で `/valley/index.html?world=kamakura&fly=1&cam=overlook&debug=1&housefull=700&houseswap=760&housecap=200` を開く。
2. 同じURLに `&house2=0` を付けた画と固定画角で比べる。遠くの屋根の質感・色むら・棟・軒・柱・戸口が読めるか見る。明るさの段差を朝・昼・夕方でも確認する。
3. `&house2debug=1` を追加。青＝屋根、赤＝柱、黒＝開口、シアン＝軒・垂木、黄＝基壇・縁、緑＝庭の物、灰＝壁。150〜450mの家に垂木・格子・石の細かな点滅が残らないか見る。
4. 家へ近づき、細部の消える境目を往復する。画角・画面サイズを変えても消去が滑らかか見る。700〜760mの元の形との入替も往復する。
5. コンソールの `__kzHouse2()` で距離・cap・shown・triangles・draws・buildFrames・maxBuildStages・nearestを見る。軽量品質（`&q=light`）でも開き、作り込みが切れることを確認する。

## 見た目を詰める定数

`HOUSE_DETAIL` は家の構築モジュール、`HOUSE_POLICY` は家の規則モジュールの先頭。色は既存の `HOUSE2` と共通パレットを継承している。

|名前|現在の値|上げたとき|
|---|---|---|
|地図のfull_m / swap_m / cap|計測は700m / 760m / 200軒|描く範囲・入替帯・軒数が増える|
|HOUSE_POLICY.full / swap / cap|60m / 75m / 90軒|設定のない地図にも作り込みが広がる|
|HOUSE_DETAIL.end / parts各end|75m|細部の提出上限が遠くなる。両方の値を整合させる|
|HOUSE_DETAIL.pixels|1.5画素|細部が早く消える|
|HOUSE_DETAIL.fade|10m|細部の消える帯が広がる|
|parts.rafter.width|0.10m|垂木が遠くまで残る|
|parts.lattice.width|0.022m|格子・竹・壁の細かな欠けが遠くまで残る|
|parts.stone.width|0.06m|屋根石・柱の足石が遠くまで残る|
|parts.batten.width|0.05m|押さえ木・棟竹・破風が遠くまで残る|
|parts.yard.width|0.022m|桶・梯子・干し縄が遠くまで残る|
|referenceHeight / referenceFov|720画素 / 50度|初回描画前だけ、細部が遠くまで／近くまで残る|
|triangles / draws|600,000 / 120|許容負荷が増える。見た目の調整では上げない|
|stages / HOUSE2.sliceMs|2段階 / 2ms|構築が速くなるが、1更新の仕事が増える|

各種の実効上限は `min(75m, width×拡大率×画面の焦点距離÷1.5)`。720画素・縦画角50度・等倍では、垂木51.5m、格子11.3m、石30.9m、押さえ木25.7m、庭11.3m。画面が変われば変わり、75mより先ではどれも提出しない。

## 未確認・制約

実 Chrome の撮影・前後比較・ちらつき・昼夕の明るさ・体感性能は未実施。文書lintは既存環境にSudachiPyがなく実行できず、目で通読した。描画命令は家の色のパスの提出数で、影の再描画やゲーム全体を含まない。細部の幅は安全側の代表値なので、大きな桶なども早めに消える。目視で消え方を確認してから値を詰める。
