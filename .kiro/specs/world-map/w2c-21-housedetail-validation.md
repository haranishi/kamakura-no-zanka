# 家の細部と遠景の色：検証記録

細部の属性をまとめ、通常17枠・確認色18枠だった頂点属性を11枠・12枠へ減らした。遠景では、元の屋根・壁の平均色を基準に補正する。設計世界の見渡しは98軒・82,458三角形・24描画命令。実 Chrome（設計した鎌倉の見渡し・浜の上の低い空・路地・大通り）で、描画プログラムのエラーが消え、屋根と壁の明るさが元の形と合うことを確かめた。

## 要求ごとの結果

|要求|結果|
|---|---|
|N1 属性を16枠以内にする|実装。元の模型・構造・細部・確認色・影を全材質と形の組で検査|
|N2 遠景の屋根・壁の平均色|実装。元材質の面積平均と既存パレットを基準に、RGBの比率で補正。実機の見渡しで、町の明るさが元の形と変わらない|
|H1 地図方針・URL・3次元距離|継承。既定60〜75m・90軒、指定値の検査、飛行カメラの高さと近い順の選択は合格|
|H2 細部のちらつき抑制|継承。面・法線・UV・色むら、庭の有無、相補ディザを維持。静止画では、細い部品は遠くに写らない。動かしたときのちらつきは未確認|
|H3 分割構築・予算と品質|継承。最大2段階／更新、近い型から構築、未完成は元の模型。軽量品質・品質段階2以上で作り込みなし|
|H4 確認の口|継承。`__kzHouse2()`で方針・描く量・構築量・最寄りの家を読める|

`house2=0`は元の表示状態・当たり・面・材質シェーダー文字列との一致試験に合格した。既存試験は統合後の属性名だけを置き換え、合否条件は弱めていない。

変更は家の構築・材質・表示、家の試験3本、本記録だけ。新しい依存・素材・モジュールはない。模型・データ・谷・庭のコードは変更せず、commitもしていない。

## 属性の数え方と修正前後

同梱Three.js r180のWebGLProgramそのものに、実際の材質・形・定義を渡し、GPUへ送る直前の頂点シェーダーを取り出した。GLSLの前処理後に全属性宣言を数え、`mat4 instanceMatrix`は4枠とする。Nodeだけの前処理で常に上限を検査する。コンパイラがある環境では前処理結果の一致も検査し、glslcの最適化後の入力をSPIR-Vから数える。GPUでリンクした結果ではないため、合否には未使用宣言も含む安全側の数を使う。

位置・法線・UV、頂点色、instanceColor、自前属性に加え、Three.jsの定義で増えるuv1・uv2・uv3・tangentも対象。影と霧の定義も有効にするが、それら独自の追加属性は0枠。修正前はGitの元ファイルから同じ経路で取得した。型・両variant・元材質ごとに検査し、同じ数となる組を以下にまとめた。

|材質と形の組（全型・両variant）|宣言枠：前→後|最適化後の頂点入力：前→後|
|---|---:|---:|
|Standard／構造、従来距離の全形|13→10|13→10|
|Standard／細部|17→11|17→11|
|Basic確認色／構造、従来距離の全形|14→11|14→11|
|Basic確認色／細部|18→12|18→12|
|Depth／構造、従来距離の全形|11→10|8→7|
|Distance／構造、従来距離の全形|11→10|8→7|
|Depth／細部|15→11|12→8|
|Distance／細部|15→11|12→8|
|Standard／元の模型|12→12|11→11|
|Depth・Distance／元の模型|9→9|6→6|
|質感なしStandard・Depth・Distance／元の模型|8→8|7・6→7・6|

合成世界270組、設計世界894組を検査。修正後の固有の頂点プログラムは各31・73本。検査用に確認色の細部へuv1・uv2・uv3・tangentをすべて足した場合も16枠。私有データでは、例外0・16枠超過0だけを確認し、固有の件数や寸法を記録しない。

統合した属性は、頂点ごとの`house2SurfaceData.xyz`＝面の種類・明暗係数・部品の役割、細部の`house2Part.xy`＝幅m・上限距離m、個体ごとの`house2State.xyzw`＝溶かす割合・庭の有無・3次元距離m・拡大率。元の個別属性は形から除去した。元の模型は従来のhouse2Fadeを維持する。

## 遠景の色を合わせる判断

一律の明るさ倍率は色みの違いを残すので採らなかった。屋根・壁の元材質を面積で平均し、材質ごとの描画範囲も考慮する。既存の土壁／木壁の選択、茅葺きの色、家ごとの色相と明暗を基準色に戻し、作り込み側の平均明暗係数を正規化する。質感・色むらは乗算の比率として残す。60〜75mで滑らかに補正を入れ、75m以遠は全量、60m以内は補正0。強度は`HOUSE2.farMeanMatch=1`だけで調整し、0なら色補正を切れる。床・庭・確認色には適用しない。

合成の5系統×2variant×3seedで、屋根・壁それぞれの正規化した面積平均RGBの誤差は1e-6未満（質感・汚れ・照明なし）。近距離と強度0で補正0、材質群の描画範囲と面積の重みも検査した。汚れ・苔・写真のミップ・実際の照明を含む画素平均は、この数値試験の対象外。

## Nodeでの描画量と作業量

設計世界の控えを実ゲームの読み込み口から読み、メモリ上だけで`house_policy={full_m:700,swap_m:760,cap:200}`を指定。見渡すカメラ、標準品質、1672×940。GPUの実描画値ではない。

|対象|軒数|三角形|色の描画命令|
|---|---:|---:|---:|
|作り込み|98|82,458|24|
|元の模型の提出分（隠れる面を含む）|—|5,748|34|
|合計|—|88,206|58|

構築426段階、最大2段階／更新・新しい描画群1個／更新。完成は単独測定250更新、並行検証中253更新。最大構築片はそれぞれ約1.57ms・71.96msで、混雑時は8msの時間目標を超えた。時間予算によって変わるので固定の合否にはしない。三角形と描画命令は前回と同じ。影の再描画・ゲーム全体・FPSは含まない。

## 実Chromeで確かめる手順と定数

1. 設計世界を既存の方法で読み込み、標準品質・1672×940で`/valley/index.html?world=kamakura&fly=1&cam=overlook&debug=1&housefull=700&houseswap=760&housecap=200`を開く。浜の上の高さ28mから、町が40〜250m先になる画角も撮る。web_04_0・web_11_0を含む家で、属性超過と無効なプログラムのエラーが0か確認する。
2. 同じ時刻・画角で`&house2=0`と比較し、150〜450mの屋根・壁の明るさと色み、棟・軒・柱・戸口の読みやすさを見る。60〜75mと700〜760mを往復して段差を見る。朝・昼・夕方・夕暮れでも比べる。
3. `&house2debug=1`を足す。青＝屋根、赤＝柱、黒＝開口、シアン＝軒・垂木、黄＝基壇・縁、緑＝庭、灰＝壁。細部が残る低い画角でもエラー0と庭の表示を確かめる。
4. `__kzHouse2()`でshown・triangles・draws・buildFrames・maxBuildStages・nearestを見る。`&q=light`、品質段階0〜3、旗切替と解放も確認する。

|定数（先頭の凍結オブジェクト）|現在値|上げたとき|
|---|---|---|
|HOUSE2.farMeanMatch|1|元の模型の平均色へ近づく。範囲0〜1|
|HOUSE2.full / swap|60m / 75m|近景の補正なし範囲／補正完了距離が遠くなる。既存の標準描画距離も兼ねる|
|HOUSE_DETAIL.end・parts各end|75m|細部が遠くまで提出される|
|HOUSE_DETAIL.pixels / fade|1.5画素 / 10m|細部が早く消える／消える帯が広がる|
|partsのwidth：rafter / lattice / stone / batten / yard|0.1 / 0.022 / 0.06 / 0.05 / 0.022m|各部品が遠くまで残る|
