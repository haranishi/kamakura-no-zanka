# W2c-16 HERO 検証記録

呼吸・見回し・重心移動、風と移動になびく布、Cのゆっくり歩きを実装した。
Nodeの検証結果は下記。実機の見え方・描画負荷は親担当の確認が残る。

## 範囲と設計判断

- 正本はWW13.3、design-web-r10.md、共通依頼書、HERO依頼書。指定の7ファイルだけを変更する。
- 純粋な計算→人物の後処理と布→操作案内→試験の順で実装。既存の移動・走り・握りは再実装しない。
- `cinePose` が走りの補正を抑えるため、自分の関数だけは既存の脚処理中に空として返す。
  `finishPose` が脚処理の旗を下げてから、呼吸の関数を返す。外部の演出の関数は維持する。
- 層一覧をNodeで読めるよう、Threeとactorsは有効な工場内で遅延読み込みする。
- 布は8節点×4本、固定1/120秒・最大12刻み。生成りの帯と結び目を1つの材質と形状にまとめた。
- 額の帯は依頼書の指定どおり見送り。追加素材・依存・ビルド・外部通信はない。

## Nodeで確認した数値（合成の世界・骨組み）

- 600コマの補正の復元誤差0。既存HeroActorの位置・速度1,800成分が無効時と完全一致。
- 既存UpperRigの走行中の重みは有効/無効とも0.9999999737694177。
- 呼吸は平常±0.8度・0.22Hz、走った後8秒で振幅0.8211度・0.22606Hzへ回復。
- 60Hzで見回しの最大変化0.8815度/コマ、重心移動0.00505度/コマ。
- 静止・風・移動の600コマで布の最大伸び1.1361%。風下の先端変位0.2659m、移動時の遅れ0.3798m。
- 0.1秒のコマ・反復10回でも最大伸び0.6810%、NaNなし。1m以上の跳びで真下へ再配置。
- 布は68頂点・58三角形・1メッシュ・1材質。形状と材質を各1回解放、配列を再利用。
- 速度切替は60Hzで最大0.26366m/秒の変化/コマ、位置の瞬間的な跳びなし。
- 描画命令+1は構造上の予定。実Chromeの測定値や+0.15msの達成値ではない。

## 親担当の実機確認

1. `/valley/index.html?world=kamakura&debug=1` を実Chromeで開く。
   平坦な道の同じ場所・同じ画角で、`&herolife=0` の前画と既定の後画を撮る。
2. 停止10秒と、Shiftで6秒走る→停止8秒を録画。胸の息、控えめな重心移動、首/頭の見回しと回復を確認。
3. 停止→移動→走り→旋回→停止を録画。布が後ろへ流れ、止まると垂れ、草と同じ突風でなびくことを確認。
   刀・握り・足と走りの形、布の根元の浮きと頭/胴への食い込みをコマ送りで見る。
4. `&cloth=0`、`&cloth=band`、`&cloth=sash`、`&herodebug=1` で部位を分離する。
   `__kzHeroLife()` の `cloth.nan === false`、`maxStretch <= .03` を移動中も確認。
5. Cで1.35m/秒の歩きと案内、再度Cで元の移動、Shiftは従来の走りを確認。飛行中のCは下降のまま。
6. `&q=light`、自動段階2/3、OSの動きを減らす設定、休止/再開、位置の再指定を確認。
7. デバッグ線なしで `&herolife=0` と比較し、描画命令+1・CPU+0.15ms以内の目安を実Chromeで測る。

未確認は実モデルの装着位置・目視の振幅・前後画像・実Chromeの性能。Nodeで既知の失敗は残っていない。
依頼書との機能差はない。次の最小の一歩は親担当による固定画角の10秒録画とHERO_CLOTHの装着位置の調整。
