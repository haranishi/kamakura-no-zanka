# W2c-9r1 shore：実装と検証

依頼書の水際改善をこの枝で実装する。実画面・GPU・性能は親の実機確認に残す。

## 要件・設計・作業順

- 既存world-map仕様と今回の依頼書を継承。谷・庭・保存・魚・共有タスクを変更しない。
- 岸距離から濡れ、泡、浅瀬色、寄せ波を出す。周期・間隔・幅・途切れを変える。
- 川岸は地形の描画三角形へ帯をクリップし、双一次の地表との交差を避ける。
  合成の鞍型地表で再現・検査し、反転・ゼロ面積を除外する。
- 川岸の小石・草は距離と傾き、座標ハッシュで決める。
- 足の接地通知に加え、水中の停止中にも弱い波紋を出す。既存プールを再利用する。
- shore2=0で旧、bankwet=0・fx=0を維持。軽量/段階2で減らし段階3で新効果を切る。
- 順に原因の回帰検査、実装、担当Node試験、全体試験/check、私有試験、記録を行う。

## 実装

- `kamakura-shore.js`：共通距離の滑らかな濡れ/深さ係数、岸寄り3帯の泡、配置の純粋計算。
  泡は帯の両側で単調に減衰する。複数帯なので全距離に対する単調性は要求しない。
- `kamakura-sea-view.js`：岸の砂色から沖の既存パレットへ補間。泡の3帯を異なる波位相で動かし、
  幅・位置・途切れをノイズで変える。泡に連動する法線で寄せ波の段を補う。
  地面へ渡す既存uniformから濡れを共有するため、地面担当ファイルの変更は不要。
- `kamakura-bank-wet.js`：旧双一次地表への貼り付けを、近景地形の描画面とのクリップへ変更。
  両岸の外向き法線・Float32の巻き方向・面積を検査し、ゼロ面積を描かない。
  元区画の周辺/細分化の条件を保った最大3×3セルだけを生成し、256セルまでキャッシュする。
  準備は1セル/更新、遠い候補の走査も128個/更新。定常時は新しい配列等を確保しない。
- `kamakura-shore-props.js`：川岸の距離・30度未満の傾き・座標ハッシュから小石と3本房の草を配置。
  既存の近傍プールと描画上限を再利用する。
- `kamakura-water-view.js`：川幅から岸距離をmで補間し、砂が透ける色と途切れる岸泡へ。
- `kamakura-fx.js`・`kamakura-fx-view.js`：足の接地によるしぶきを維持し、水中の停止中も
  0.65秒間隔の弱い波紋を足す。停止時間・乾地・無効化では追加しない。既存プールを再利用。
- `world-kamakura.js`：川へsearch/qualityと品質段階を渡す2行だけを変更。
- `tests/kamakura-shore-r1.test.mjs`を追加。既存`kamakura-rivers.test.mjs`は
  新しい純粋モジュールのimportをNodeで解決する行だけを更新し、既存の判定は維持。
- `shore2=0`は旧規則・旧川岸へ。`bankwet=0`・`fx=0`を維持。
  軽量/段階2は海泡1帯・川泡1帯、段階3は新しい泡と川岸/小物/波紋を切る。

## 検証と数値

- 開始時：`npm test`は1,128成功/21省略、`npm run check`成功。
- 合成の鞍型地形で旧帯と描画地表の最大ずれ約0.320mを再現。
  新帯の最大誤差は約0.00000321m（地面+15mmからの誤差）、292面で反転0。
  曲がり・強い折り返し・外向き配置・細分化地形・区画継ぎ目も検査。
- 泡3帯の半幅0.695〜2.297m、帯間隔3.771〜7.555m。幅・間隔とも分散あり。
  濡れ/深さの範囲・連続性・単調性、泡の途切れと各側の連続減衰を検査。
- 同梱Threeでシェーダーを取得し、括弧・条件の対応と予約語を検査。
  品質往復、URL切替、定常バッファの同一性、各資源のdisposeが1回であることを検査。
- 最終：`npm test`は1,133成功/22省略、私有データ指定の`npm test`は1,155成功/省略0。
  `npm run check`・`git diff --check`も成功。追加6試験は私有ありですべて成功。
- 私有データ指定の担当試験を単独測定：川岸の準備コマ最大1.368ms、
  準備後10,000更新の平均0.0000413ms/更新。全試験の並行実行中には準備最大50.27ms。
  GCや競合を含むため、1セルの分割は時間の厳密な上限ではない。GPU予算の証拠にはしない。
- `npm run smoke`は開始/終了とも`listen EPERM`（127.0.0.1）で失敗。
  ブラウザ・サーバーは依頼の制約に従い起動しなかった。依存・外部素材・外部通信の追加なし。

## 親の実機確認と残件

1. 基点`/valley/index.html?world=kamakura&debug=1`。準備後、同じ時刻・位置・画角で
   既定と`&shore2=0`を比較し、04_beach_sea・05_beach_wide・06_river_inside・
   07_spawn_town・10_beach_eveningを前後撮影する。寄せ引きは20秒以上の動画でも確認する。
2. 07で`&bankwet=0`も比較。左岸の暗い三角形が濡れ帯由来か、実機で確定する。
   Nodeでは発生構造を再現できたが、講評画像の原因と同一だとは未確認。
3. 06で水に入り、歩く/走る/止まる/岸へ上がる。足元の輪と接地時のしぶき、乾地で止まること。
   `&fx=0`、`&q=light`、`&autoscale=0&adaptstep=2`・同3・同0も撮り比べる。
4. GPUコンパイルと描画増分+0.5ms、CPU6倍/390×844のp50増分+3msを実測する。
   依頼の`tools/shader_errors.mjs`はこのworktreeに無い。親の実機側の道具で確認する。

未確認：実画面の改善、GPUコンパイル、性能、前後画像。
既知の制約：新帯は近景LOD1の描画面を前提とする。細い曲がりでは帯同士の重なりや短い隙間が
残る可能性があり、07の移動と品質往復で確認する。8mの海岸距離格子の精度は既存のまま。
仕様の変更なし。旧帯はshore2=0と格子を持たない合成地形の互換用に残した。
次の最小ステップは親の5画角比較とGPU/性能の測定。
