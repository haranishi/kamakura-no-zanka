# 低い雲の細い帯を、厚さと切れ間のある層へ直した

低い雲を、厚さが方位で変わり、切れ間で消える層にした。下の面は鋭く、上の面は細かく崩してある。
実際の Chrome（序幕・夕暮れ）で見た。定規で引いたような細い帯が、暗い紫の厚い雲の塊に変わり、その下に明るい桃色の空の帯が残る。エラーは 0。
Nodeの31,500標本で、半分以上の濃さの被覆は48.74%。
対象はWW17.5の低い雲だけ。海の光の道・遠景・霧・時刻の設定は変更していない。

## 要求と判断

| 要求 | 結果 |
|---|---|
| F2 厚さと切れ間 | 実装。0.25〜1.9倍。各層の180度内で2〜3か所の完全な切れ間を確認 |
| F2 下面と上面 | 実装。下面は鋭い縁、上面には3.2度の尺度で凹凸。中心は±0.7度のうねり |
| F2 水平線 | 実装。0.55度以下は全方位で被覆0。雲どうしが部分的に重なる |
| F2 色 | 実装。既存の空・霧・日の色を使用。日から40度以内の下側の縁だけ暖かくする |
| 旗・品質・確認 | 維持。clouds2=0で既存の空。標準4層・軽量2層・最軽量1層。確認色は青の単色 |
| 実 Chrome での確認 | 実施。山の上からの見渡しと町の望遠を、直す前とあとで撮り比べた |

固定した空白の高さを残すと、雲が平行な線のままになる。旧試験の「1.8・3.6度はほぼ空白」は外した。
代わりに、層の重なり、方位ごとの完全な切れ間、上下の形の差を検査する。40〜50%の被覆条件は維持。
厚さと形、被覆と下側の縁は、同じ式からCPU関数とGLSLを作り、両方を実行して照合した。
北の継ぎ目をなくすため、雑音への入力は方位を円に写したもの。時間の流れも方位の移動で表す。

360度を2度刻み、高さ0.3〜9度を0.05度刻みで調べた31,500標本中、被覆0.5超は48.74%。
360方位のうち80方位で低い2層が重なる。方位0度と360度、および北の前後は連続。
既存の空の2,208三角形へ差し込むため、追加の三角形0・描画命令0・画像取得0・毎コマの形状転送0。
形の計算はGPU側。標準の最悪条件では1画素あたり雑音48回、軽量24回、最軽量12回の式になる。
GPUの実行時間やコンパイラーによる共通計算の整理は未測定。

## 実際の Chrome で見た結果

以前の序幕の見渡しと山道では、紫灰色の雲、1つの日、遠い山並みと岬・島が見え、エラー0だった。
その後の講評では、雲が定規で引いた水平の細い線に見えると指摘された。今回の修正はこの指摘への対応。
今回の版：見渡しの空（水平線の上 0〜3.6 度）の左から中央に、暗い紫の厚い雲の塊が載り、所々で切れる。水平線のすぐ上には、明るい桃色の帯が残る。日の側は、橙のまま開いている。雲の下の面の暖かい色は、この画角では控えめに見える。
以前から、谷の霧には青白い丸いにじみに見える所がある。今回はその層を変更していない。

## 実Chromeで確かめる手順

1. 序幕の設計した世界を配信し、`/valley/index.html?world=kamakura&time=dusk&fly=1&cam=overlook&debug=1`を開く。
2. 俯角21度・縦画角50度の見渡しで、0〜3.6度の空にも厚い塊と切れ間があり、横一直線に見えないか確認する。
3. `&clouds2debug=1`は青の濃さが雲の被覆。切れ間は青くならない。`__kzClouds2()`で層数と追加描画0を確認する。
4. 通常の色で、日の近くの下面だけ桃〜橙、上面と日から遠い側は暗い紫灰色かを見る。
5. 水平線から0.55度まで明るい空が残るか、60秒ほど待って動きと北の継ぎ目を確認する。
6. `&clouds2=0`、`&time=evening`、`&q=light`、`&adaptstep=3&autoscale=0`を同じ画角で比較する。前版と今回を撮影する。

## 残る確認

GPU の負荷は測っていない。雲の下の面の暖かい色を、もう少し強くするかは、歩く視点（空が広く写る）で見て決める。
