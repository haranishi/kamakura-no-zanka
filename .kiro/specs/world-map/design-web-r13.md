# 設計メモ：設計した鎌倉（W2c-19・WW16）

構想の絵の配置どおりの鎌倉を、標高データを使わずに作る。ゲームのコードは、実寸の鎌倉と共通。違うのはデータだけ。

## なぜ、道具で作るか

設計図（数字と式）を書き、道具がそこから世界データ一式を作る。この形を選んだ理由は 3 つある。

- **直しが速い**。絵と並べて「浜が狭い」と分かれば、数字を 1 つ変えて作り直す。
- **同じ結果になる**。同じ設計図からは、同じバイトのデータができる。差分は、設計図の差分として読める。
- **公開できる形になる**。標高データを使わないので、設計図と道具はリポジトリに置ける。

捨てた案は 3 つ。

- **実寸を約 3 分の 1 に詰める**：本人が選ばなかった。距離は合うが、絵の並び（大仏が浜の近く・港が河口の横）にはならない。
- **Blender で手作りの地形を作る**：直すたびに手作業になる。何を変えたかが、差分で読めない。
- **実寸のデータを書き換える**：歩ける実寸の鎌倉が壊れる。実寸は、別のデータとして残す（WW16）。

## データの流れ

```
設計図（tools/worlds/）→ 道具（tools/make-designed-world.mjs）→ 世界データ一式（リポジトリの外）
                                    ↑ 家と施設の模型（--kits。無ければ代わりの箱）
```

できたフォルダを `KZ_WORLD_DIR` に指定して、今までと同じ `?world=kamakura` で開く。道具は、上から見た図（高さ・地面の種類・道や家の重ね図・断面）も書き出す。実 Chrome の前に、図で配置を確かめる。

## 地図ごとに変える値は、データに書く

実寸の鎌倉に合わせた定数が、設計した鎌倉では合わない所がある。コードに分岐を足さず、データ（`meta.json`）の任意の値で上書きする。値が無ければ、今までと同じに動く。

- `meta.town_fill`：町の区画の間口・奥行き・路地の間隔・範囲・状態の割合。絵の家は大きく、数は約 200 軒。実寸の値のままだと、約 1,200 軒の小さい区画になる。
- `meta.overlook`：見渡す構図の距離・高さ・俯角・画角。町が小さいので、近く低くなる。

上書きできる名前は、白い一覧で決める。型と範囲を検査する。

## 今ある層は、そのまま使う

町を埋める処理・町の物・近くの家の作り込み・橋と岩・露座の大仏・松並木と鳥居・浜の舟・遠くまで届く影・人。どれも、位置を持たずにデータ（大通りの線・区画・川と道の交わり・施設の箱・地面の種類）から決める作りなので、新しい地形でも動くはず。動かない所は、実寸の大きさを前提にした定数が原因と見て、上と同じやり方で直す。

## 絵に合わせて足す物（本人の希望の 4 つ）

- **光と色**：夕方前の暖かい光を強め、日陰を青みのある暗さにする。色の仕上げは、設計した鎌倉の見渡す構図と歩く視点で、絵と並べて詰める。
- **森と木**：町が小さくなると、丘は 700〜1,400m 先に来る。一本ずつの木を、その距離まで軽い形で描く（今の丸い塊への引き継ぎを、遠くへ送る）。
- **浜・海・港**：砂浜と堤の形は地形で作る。堤の石・桟橋・港の舟・白波は、層で足す。
- **町の暮らし**：柵で囲まれた屋敷を増やす。人・天幕・煙を、見渡す構図でも読める数と大きさにする。

## 確かめ方

1. 道具の図で、配置を確かめる（浜の幅・段の平らさ・川の形・港の輪・丘の囲み）。
2. 実 Chrome で、見渡す構図と歩く視点（出発点・社殿・大仏・橋・港）を撮る。
3. 絵と並べる。別の役が講評する（最大 3 周）。
4. 本人が見て、よければ次のマップへ。

## 公開について

設計図と道具は公開する。できたデータと模型は、本人が決めるまでリポジトリに入れない。模型は、手続きで作った自作の形で、外から持ち込んだ形は無い。質感は、出どころを `provenance/` に書いた CC0 の写真だけを使っている。
