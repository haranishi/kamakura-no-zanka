# W2c-5b 林分の実装とNode検証

本記録は初回実装の履歴。現行の色・形・接地は[修正記録](w2c-5b-fix-validation.md)を参照。

BRIEF-W2C5B.md と委譲元の design-web.md・tasks-web.md の設計を引き継いだ。
実装とNode検証を担当し、実機の画面・性能・指操作の受け入れは親へ残す。
commit・push・ブラウザ操作・他worktreeへの書き込みは行っていない。

## 実装した範囲

- kamakura-stands.js に純粋な方針・子の生成・区画計画・縮み率を追加。
- tier 1・2を種別×tier×1km区画で分割し、48三角形の楕円体を静的に配置する。
  葉色は5aの対応と同じ線形色に0.85を掛ける。照葉樹の暗い常緑色も引き継ぐ。
- 樹冠の下端は高さの0.5倍、中心は0.75倍、上端は1倍。地形へ接地した位置が基準。
- GPUのsmoothstepで水平距離に応じて縮める。tier 1は100〜180m、tier 2は500〜800m。
  案A外のtier 1は展開しないため、近くでも塊を保つ。
- 遠景の距離制限は通常5km／8km、軽量3km／5km。視錐台判定はThreeへ任せる。
  毎コマはカメラuniformを更新し、5m移動時だけ大区画の距離判定を更新する。
  遠景のinstanceMatrixは構築後に書き換えない。
- 子は元の番号による整数PRNGと、揺らした三角格子から決める。
  個数は面積÷70を3〜16本へ制限し、格子の最小間隔は5m以上。
  高さ・向き・傾き・明暗・variant・風位相も決定的にする。
- 家・道・出発点・水域の除外は5aの同じ関数を使う。除外索引は一度だけ構築する。
  案A内の子だけをheightAtへ接地し、同じ幹の半径式で当たりへ追加する。
- 子は256m区画ごとに生成する。180mの切替帯へ入る前に間に合わせるため、
  準備距離を200m（樹冠半径と移動の余裕を含む）とした。1フレーム2区画まで。
  区画端から450mを超えたら子と幹の円を破棄する。
- 子の描画には5aの集合を共有プールとして再利用する。
  LOD・遠景板・風・容量制限は同じ。区画ごとの材質や遠景板の再生成はしない。
- lightはtier 1のrank<0.5だけを残し、子は約半数（最小3本）にする。
- stands=0で遠景と展開だけを切り、trees=0で木全体を切る。データなしの経路も維持。
- collision.jsには円の追加と一括解除の補助関数だけを追加。既存の当たりの規則は維持。
  TreeField・TREES・vegetation.js・保存・庭と谷の入口は変更していない。

## 検査と証拠

- 開始時：npm test は942成功・5省略、npm run check は成功。
  npm run smoke はlisten EPERMで失敗。この環境はHTTP待受けを許可していない。
- 合成試験で子の決定性・個数・円内・間隔・除外・接地・区画の保持と破棄・再生成を検査。
- 縮み率の単調性と境界、軽量化、案A外とtier 2の非展開を検査。
- 動的な幹へmoveActorで向かい、追加時に止まり、解除後に通れることを検査。
  同じ格子内の既存円の保持、不正な入力の原子的拒否、二重解除も検査。
- 同梱ThreeをNodeで使用。樹冠・属性・uniform・子の集合・段階生成・破棄を検査。
  GPU描画・GLSLコンパイル・実機のメモリ検査ではない。
- KZ_WORLD_DIR未設定の私有データ試験は、理由を表示して省略する。
  指定時はtier別件数・展開対象・子の個数概算・出発点の描画量・森の標本・円の登録時間・
  区画の最大同時数を標準出力へ返す。私有データや派生数値表はリポジトリに保存しない。
- 三角形は大区画の距離判定だけを使う概算で、視錐台とGPUの除外は含まない。
  子の個数概算は除外前。出発点が市街地で子0の場合も、そのまま報告する。
- 最終結果は下記の完了記録へ残す。

## 親の実機確認（メイン・2026-11-06・実Chrome・画面なし・1280×720・`KZ_WORLD_DIR=…/export_web_w2c_v6`）

1回目（Codex の実装）と、直し（`BRIEF-W2C5B-FIX.md`）の後の2回に分けて確認した。

- 1回目の見た目：**不合格**。朝夷奈の東の端（`&spawn=asaina_pass&at=.95`）から見ると、遠景の塊が水色・灰白色の平たい円盤に見えた。原因は①色を `TREES.palette`（葉の絵に掛ける色味）から取っていた②扁平な楕円体だった。試験・読み込み・コマ時間（制限解除で+0.2〜0.4ms）は問題なし。
- 直しの後：塊が暗い緑の縦長のドームになり、遠くの山腹の森の塊に見える（色は実機で測った杉(42,69,35)・松(14,33,13)・落葉(50,61,26)・照葉樹(34,48,24)を基準）。同じ画角の `&stands=0` と比べ、斜面に浮きは見えない。コンソールは空。
- コマ時間（制限解除・M4 Pro・ヘッドレス）：出発点 塊あり487fps／なし527fps・朝夷奈の端 540／573・杉林 458／548。1コマあたり約0.15〜0.35msの増加。最大約20msの瞬間的な伸びは塊なしでも同じ（地形の区画の作り直し）。
- 全体の試験を親が再実行：私有データなしで952成功・6省略、v0.6指定で958成功・省略0、`npm run check`・`npm run smoke` 成功。
- **事実（塊の位置）**：tier 1（3.6万件）は歩ける範囲（案A）の外側に偏る。案Aの内側は593件・0〜200m の帯に880件・200m〜500m に2,855件・500m〜1km に7,919件・1〜2km に14,127件・2〜4km に9,299件。出発点から最も近いものでも約1.9km・半数は3.5km以上。tier 2（5.3千件）はすべて2km以上外。このため、出発点や市街からは塊が小さく見え、**歩く範囲の森の密度はほとんど変わらない**（高い所＝朝夷奈の端などから見渡すと効く）。K7 は樹冠が重ならない配置なので、歩く範囲の森は元からまばら。密度は草・低木（W2c-5c）と、必要なら補植で別に扱う。
