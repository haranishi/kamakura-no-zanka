# W2c-18j 木の橋・川の岩・白波：検証記録

道が川を渡る所に、木の橋を架けた。岸と流れの中には岩を置き、岩の下流に白波を出す。橋は歩いて渡れる。

- 旗：`&bridges=0`・`&rocks=0`。確認用：`&riverlifedebug=1`（床＝黄・欄干の当たり＝赤・杭＝橙・岩＝赤紫・白波＝水色）・`?debug=1` の `__kzRiverlife()`。
- 調整する定数は、`kamakura-bridges.js` の `BRIDGES`・`kamakura-river-rocks.js` の `RIVER_ROCKS`・`kamakura-riverlife-kit.js` の `RIVERLIFE_ART`。

## 判断と、捨てた案

- **橋は、岸の上から岸の上へ、道の高さで架ける**。最初は「水際から水際」で探した。それだと、岸が高い川では 1 本しか架からなかった。
- **場所は、データの「道が川を渡る場所」（`roads.json` の `crossings`）を先に使う**。古いデータには無いので、そのときは道と川の線の交わりから探す。
- 橋の床は、移動・カメラ・足音・足元の水しぶきにだけ渡す（「床の入った地形」）。景色の地形は変えない。橋の無い区画は、判定 1 回で元の高さへ戻る。
- **橋の下は、くぐれない**。高さの違う 2 つの通り道を、いまの水平の当たり判定では表せないため。欄干の当たりは川底まで届く。だから、川の側から床へ跳ね上がることも無い。
- 人の層は変えていない（人は、まだ橋を知らない）。
- 白波は、今ある川の流れの速さと泡の色から作る。描画命令は 1 つ。

## 私有データの側で直したこと（リポジトリには入らない）

実 Chrome で見ると、付け替えた本流が「黒い溝」に見えた。岸が幅 3〜5m の急な壁で、色も暗い土だった。そこで、岸の幅を高さに合わせて広げ、草の色にした。急な石積みは、橋のたもとだけに残す。東の小川 2 本は外した（流れの計算の名残で、直線の溝に見えたため）。川の線の点の間隔もそろえたので、帯は途切れない。コードは、川の本数と橋の場所をデータから読む。

## 実 Chrome で確かめたこと（夕方前）

| 見た所 | 結果 |
|---|---|
| 橋の数 | 道が川を渡る所の全部に架かった（大通りが河口の近くで渡る所を含む） |
| 上から見た川 | 草の岸の間を、なめらかに曲がって流れる。岸に木が並ぶ |
| 歩く視点のコマ時間 | 第 3 段の全部を入れて 9.5ms（切ると 8.6ms。うち影が 0.6ms） |

## 試験

- `tests/kamakura-bridges.test.mjs`：道と川の交わりから橋を導く・幅と長さ・重なり・上限・岸の上の高さ・床と水面のあき・坂の傾き・端のつながり・両側の箱。道から歩いて渡れること、川の側から床へ上がれないことを、実際の移動の関数で確かめる。
- `tests/kamakura-river-rocks.test.mjs`・`tests/kamakura-riverlife.test.mjs`：岩の置き方（岸・流れ・急な所ほど多い・河口と橋脚のまわりは置かない）・白波の向きと長さ・層の解放。
- CI 用の人工の世界にも、道と川の交わりを作った（橋が 1 本できる）。

## 残っていること

- 橋を歩いて往復する確認は、まだしていない（試験の中の移動だけ）。岩と白波を近くで見る確認も、まだ。
- 上流には、岸が急で暗い所が残っている（データを直したのは、合流点から 600m まで）。
- 橋の下をくぐるには、当たり判定に高さの区別が要る（別の作業）。
