# 炎を家に結び付け、煙の大小を分けた

炎を棟と開口部の交差板にし、屋根の燠と戸口・窓の光を追加した。
強さ0.45の煙は、強さ1に対して幅0.499倍・高さ0.594倍。8火元の合成世界は896枚・1,792三角形・描画4回。
実 Chrome（序幕・夕暮れ）で、山の上からの見渡しと拡大、町の上の低い空から見た。炎は、屋根の棟に沿って並び、屋根の上に燠が光る。煙の根元は、火の色に照らされる。コンソールのエラーは 0。
前回の実Chromeでは黒い煙・橙のにじみ・屋根の照りは良好だった。一方、炎は板に見え、煙の大小と根元の橙が不足していた。

## 要求と判断

| 要求 | 結果 |
|---|---|
| G1 屋根・開口部の交差炎 | 実装。舌ごとに2〜3枚、60度または90度の交差。棟の大小と時々高い炎、埋めた根元、透明な側辺と先端 |
| G1 燃える家の赤さ | 実装。屋根の両斜面にまだらな燠、正面の戸口と窓に内側からの光。家の模型は変更しない |
| G2 強さで変わる煙 | 実装。太さ・高さの比を検査。火元別の傾き・うねりを維持し、上では広く扁平にする |
| G2 根元の橙・上端の消失 | 実装。下4分の1の内側を炎色へ寄せる。高さと房の寿命の両方で滑らかに消す |
| 900枚・描画5回以内・品質段階 | 実装。地面の面も予算に含む。1,536構成で最大900枚、実際の形と報告値も照合 |
| 従来の火の粉・にじみ・照り返し・旗・確認の口・解放 | 維持。回帰試験で確認。実画面でも維持 |
| 実Chromeでの見た目・前後撮影 | 見送り。今回の作業環境ではブラウザを動かさないという条件による |

燠と戸口・窓は炎と同じ描画にまとめた。窓の間の壁は光らせない。
各火元が6軒を燃やす構成では、標準の煙は通常32枚、7火元で25枚、8火元で27枚。交差板と家の発光面を残す予算配分を優先した。
強さによる高さの差を広げるため、弱い火の基準を90mから60mへ変更。強さ1の高さ上限160mは維持した。
細くした煙の根元と上端に房を残し、低品質でも上下が途切れないようにした。上端の照合だけはFloat32の丸めに1e-5mの許容を設けた。
屋根と開口部は、既存の家の箱から近似する。戸口・窓は既存の家の明かりと同じ正面配置を用いる。

## 実Chromeで確かめる手順

1. 設計した世界の控えを複製し、`meta.json`に`"fires":[{"x":0,"y":-100,"radius_m":18,"strength":0.45},{"x":60,"y":-140,"radius_m":24,"strength":1}]`を足すだけで動く。
2. 複製を`KZ_WORLD_DIR`として配信し、`/valley/index.html?world=kamakura&time=dusk&fly=1&cam=-200,100,65,135,12,50&debug=1`を開く。統合した場面では`cam=overlook`も使う。
3. 200〜450mから、炎が家並みの中で燃える塊か、煙の大小が違うか、下4分の1が橙で上が暗い灰紫かを見る。40秒以上見て上端の急な消失を探す。
4. 屋根近くの低い空と歩く高さで、交差板の薄さ・直線の縁・燠の浮き・戸口と窓のずれを確認する。家を一周して見る。
5. `&firedebug=1`は炎=赤、燠=橙、開口部=緑、にじみ=黄、地面=桃、煙=紫、火の粉=水色。`__kzFire()`で数・三角形・描画・距離・方位・作業量を見る。
6. `&time=evening`と`&time=noon`、`&q=light`、`&adaptstep=3&autoscale=0`、停止・再開・退出も確認する。同じ画角で`&fire=0`と前版を撮り、橙のにじみと照りを比べる。コンソールエラー0も確認する。

## 限界と次の確認

町追加処理の2秒上限検査は初回失敗・再実行成功。時間の変動の原因は未特定。
山の上から見ると、煙の柱が細い縄のように見えたので、根元の太さを 5.2 → 7.6m に上げた。GPU 時間と実 FPS は未測定。
屋根は箱からの切妻近似。複雑な棟・寄棟・庇では燠の浮きや埋まりがあり得る。開口部も詳細模型の各穴とは一致しない場合がある。
家の裏の減光は選んだ家の平面形だけを見る。地形やほかの家の影、急斜面での地面の浮きは従来の制約として残る。
次の最小作業は、上の固定画角を前版と撮り比べ、屋根と壁への付着、根元の橙、煙の大小を確認し、表の定数で詰めること。
