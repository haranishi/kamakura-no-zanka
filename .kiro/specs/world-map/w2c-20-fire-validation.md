# 火と煙の修正：検証記録

煙を太く暗い柱にし、火の粉の列と地面の一様な照り返しを直した。
Nodeの8火元構成は696枚・1,392三角形・描画4回。今回の実Chrome確認は未実施。
前回の実Chromeでは炎と橙の光は良好だったが、煙は雨の筋に見え、火の粉に列があった。

## 要求と判断

| 要求 | 結果 |
|---|---|
| S1 黒い煙・太り方・風・火元差・上端の消失 | 実装。通常32枚、柱の半径は上端で根元の4.4倍。画面の読みやすさは未確認 |
| S1 房の上昇・縁・重なり | 実装。四辺で透明、通常の重ね合わせ、深度を書かない。根元の房は屋根上に残し、上端では房全体も消す |
| S2 屋根の面から散る火の粉 | 実装。屋根の傾斜は箱からの近似。位置・上昇速度・渦・またたきを粒別に変える |
| S3 なめらかな減衰・遅い揺らぎ・家の裏 | 実装。0.55Hz、火元別の位相。選んだ最大6軒の箱で地面の光を弱める |
| F1〜F4 データ・無効化・上限・品質・確認の口・解放 | 維持。回帰試験で確認 |

炎とにじみの色・寸法は引き継いだ。7〜8火元で予算が足りないときは舌を減らす。8火元の最大構成は各家7枚から4枚に抑える。
煙32枚と火の粉20個以上を残し、700枚の上限を守るため。通常の3〜6火元は従来の舌数を保つ。
煙は既存のすす・炎・場面の霧の色から作る。画像・模型・依存を追加していない。
GLSLの整数検査は、正当なuniform配列の長さだけを除外した。型の不一致はコンパイルでも拒否する。

## 検証結果

- 開始時の全体試験：2,047成功・失敗0・64省略。`npm run check`成功。
- 開始時と終了時の`npm run smoke`：`listen EPERM`で失敗各1回。HTTPとブラウザは確認できない。
- 対象：`node --test tests/kamakura-fire.test.mjs tests/kamakura-layers.test.mjs`は28成功・失敗0・1省略。同じ対象を私有データ指定で実行すると29成功・失敗0・省略0。
- 終了時：`NODE_OPTIONS=--max-old-space-size=1536 timeout 600 npm test`は2,051成功・失敗0・64省略。
- 終了時：上のコマンドに実寸世界の`KZ_WORLD_DIR`を指定した全体試験は2,113成功・失敗1・1省略。
  既存の町追加処理の2秒上限に抵触。直前の同じ検査も600秒で中断したため、全体試験は未完了として止める。原因は未特定。
- 終了時の`npm run check`：160モジュール・純粋層98件・構文675件、成功。
- 文書lintは既存のPython環境で成功。文長の警告1件は、数値と手順をまとめた短い検証記録として残した。
- `glslc`で4段をコンパイル。未宣言の名前と数値型の不一致を入れると拒否。差し込み印は使っていない。
- CPUとGLSLの煙の式を高さ・強さ・風向・位相・時間を変えて照合。傾きは高さの0.34〜0.54倍。
- 上端で房を巻き戻すときの急な消失を防ぐため、板全体にも寿命による減衰を掛け、両端で0になることを検査。
- 回した合成屋根の60点に同一直線上の3点なし。同じ入力で同じ配置。全品質で房の上下の重なりを検査。

## Nodeの測定（合成世界：8火元、各6軒、強さ1）

| 品質 | 段階0：枚／三角形 | 段階1 | 段階2 | 段階3 |
|---|---|---|---|---|
| 標準 | 696／1,392 | 576／1,152 | 320／640 | 184／368 |
| 軽量 | 576／1,152 | 320／640 | 184／368 | 184／368 |

全段階で描画4回、煙は別の1回。点光源は0〜1個、影なし。
初期化は家の検査384回・地形128点、転送は標準664／軽量544インスタンス。
60コマで再転送0・地形の再取得0・板ごとのCPU更新0。歩行中の火元検査480回。
300m・縦941画素・画角50度の中腹の外形幅は、計算上133〜161画素。描いた画素幅ではない。
火元数・家数・強さ・段階を変えた960構成の最大は700枚。上限内で段階ごとに減った。
地面の光は1画素につき最大6軒の箱を検査する。GPU時間・FPSは測っていない。

## 実Chromeで次に確かめること

1. 設計した世界の控えを複製し、`meta.json`に`"fires":[{"x":0,"y":-100,"radius_m":18,"strength":0.8}]`を追加するだけで動く。
2. その複製を`KZ_WORLD_DIR`として配信。`/valley/index.html?world=kamakura&time=dusk&fly=1&cam=-200,100,65,135,12,50&debug=1`を開く。
3. 場面統合後は`cam=overlook`でも撮る。縦941画素・画角50度・町から約300mで、中腹の黒い部分が25画素以上か測る。
4. 40秒以上見る。房の上昇、風下への傾き、火元ごとの差、上の広がり、縁と継ぎ目、煙どうしの穴を確認する。
5. `&firedebug=1`：炎は赤、にじみは黄、地面は桃、煙は紫、火の粉は水色。`__kzFire()`で描画数・距離・方位・作業量を見る。
6. 屋根近くでは火の粉の列がないか、屋根から浮かないかを見る。家の手前と裏で地面の光を比較し、外縁に段がないか見る。
7. `&time=noon`でも煙が空より暗いか確認。`&q=light`、`&adaptstep=3&autoscale=0`、停止・再開・退出も確認する。
8. 同じ画角の`&fire=0`と前版を撮り比べ、炎と橙の光の良さを保ったか、コンソールエラーがないか確認する。

## 限界と残件

私有データ付き全体試験の町区画検査は未完了。対象外のコードや時間上限は変更していない。
固定画角の前後画像、実Chrome、GPU時間、実FPS、煙の実画素幅は未確認。見た目の達成は断定しない。
屋根は模型の実面を読まず箱から近似する。寄棟や複雑な屋根で火の粉の浮き・埋まりを実画面で確かめる必要がある。
家の裏の減光は選んだ家の平面形だけを見る。地形・ほかの家の影は未対応。地面の粗い面は急斜面で浮く可能性が残る。
