# 要件：描画まで確かめる CI（GL スモーク）

2026-11-09・本人の依頼（「PR をマージするときに、テストはちゃんとやっているか。競合しない・コードが正しく書けているかを CI で確かめてほしい。必要なら作る」）。

## 今の事実
- 公開リポジトリ。GitHub Actions は何回でも使える。`.github/workflows/verify.yml` は、Node 22・24 で `npm test`・`npm run check`・`npm run smoke` を走らせる。
- **`npm run smoke` は「ファイルが配られるか」しか見ていない**（描画しない）。鎌倉（`?world=kamakura`）は非公開データが要るので、CI では一度も起動していない。
- GLSL のコンパイルエラー（`position.y--0.013`・`0mix(` など）が、Node の試験を通ったまま実機（本物の Chrome）で初めて見つかった事例が3回ある。
- main の保護は、強制 push と削除の禁止だけ。**「CI が通らないとマージ不可」は有効でない。**

## 要求
CI1 合成の鎌倉データ：`tools/make-synthetic-world.mjs <出力先>` が、完全に人工の鎌倉データ（スキーマ `kz-world-web/0.9`）を**決定的**に作る（同じ入力→同じバイト列）。合計 8MB 以下・20 秒以内。実データの値・座標を含まない。ローダー（`dist/valley/kamakura-data.js`）が受け付け、**主要な描画経路が全部動く**：地面（全分類）・川・海岸・家（部品つき）・施設（堂の内部つき）・木（針葉・広葉）・林分・草地・道。
CI2 GL スモーク：`tools/gl-smoke.mjs` が、ヘッドレス Chrome（ソフトウェア描画）で `?world=kamakura&debug=1&autoscale=0` を開き、固定の2〜3画角で、**GL・シェーダーのエラー、コンソールの error・warning、ページの例外が 0 件**であることを確かめる。画面を PNG で保存する。新しい依存を足さない。3 分で時間切れ＝失敗。
CI3 CI のジョブ：`verify.yml` に `gl-smoke` を追加する（既存の Node 22・24 は変えない）。失敗時は画面とログを artifact に残す。
CI4 検出力の確認：わざと壊した GLSL を入れた版で、スモークが**失敗する**ことを、CI の中で毎回確かめる（検査が空振りしていないことの証拠）。
CI5 main の保護：必須の検査（Node 22・Node 24・GL スモーク）と「最新の main に追いついていること」を、`docs/` の手順で設定できる。**新しい検査が3回続けて成功してから**有効にする。競合する PR は、検査が走らず、マージできない。
CI6 速度と保守：ジョブは 5 分以内。ログは短い。合成データの作り方と、スモークの読み方を `tools/README-ci.md` に書く（100 行以内）。

## やらないこと
画質の評価（画像の比較）・非公開データの試験・性能の測定（ソフトウェア描画では意味がない）。これらは今までどおり、手元の実 Chrome で行う。
