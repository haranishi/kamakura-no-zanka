# 現在のコードと拡張ポイント

## 構成

ビルドなしのES Modules。`dist/index.html` のimport mapが同梱Three.jsへ解決します。`dist/` を直接編集し、HTTPで配信します。

| ファイル | 現在の責務 |
|---|---|
| `dist/app.js` | WebGL初期化、GLB読込、ライト、メッシュ最適化、フレーム更新、移動・入力、カメラ、QAフック |
| `dist/collision.js` | `groundAt`、`checkPosition`、`movePlayer`。DOMから独立した地形・簡易衝突処理 |
| `dist/ui.js` | `WalkUI`、タイトル／playing／paused／error、設定保存、入力解除用コールバック |
| `dist/index.html` / `style.css` | 意味のあるHTML、native dialog、控えめなHUD、狭い画面対応 |
| `dist/assets/collision.json` | 地面高さの0.2mグリッド、外周、家・井戸、水域の制限 |
| `tests/*.test.mjs` | Node標準assertによる既存16件 |

`qa` クエリがある場合（例：`?qa=1`）にだけ表示する開発用パネルと `window.__walktest` があります。通常URLには出ません。これをプレイヤー向けUIへ流用せず、QA専用のまま保ちます。

## 拡張の推奨単位

以下は提案であって既存ファイルではありません。

- `gameplay.js`：状態と純粋な遷移関数、所持・進行の整合性。
- `interactions.js`：対象の選択、距離・向き・遮蔽、同一操作の入口。
- `save.js`：JSON・版・型・状態の検証、読み書き、復帰。
- `audio.js`：ユーザー操作後の開始、ミュート、pause対応。
- `assets/interactions.json`：安定ID、対象ノード、アンカー、距離、配達位置。

少ないファイルで十分なら統合して構いません。状態管理のためだけに新しいフレームワークを導入しないでください。DOMやメッシュ操作から切り離したロジックを自動テストできることが大切です。

## 座標と実アセット

- Three.js／GLBは **メートル単位、Y-up、床面はX/Z**。
- Blenderからの変換は `(x, y, z) → (x, z, -y)`。既存GLBとcollision.jsonは変換済み。再変換しない。
- 現在の開始位置は `x=-2.3, z=6.4`。プレイヤーYは地表、カメラはそこへ1.65mを加える。二重加算しない。
- 歩行2.1m/s、Shift時3.5m/s、半径0.23m。大きなdtは抑制し、衝突移動は細分化する。
- 桶は `Bucket_` で始まる39ノード。大半のtranslationは概ね `(-4.55, 0.136, 3.10)`。
- 井戸は `timber_well`、translationは概ね `(-6.40, 0.176, 2.20)`。
- translationはピボットであり、メッシュ中心や操作アンカーではない。読み込み後のworld matrixと実バウンディングを確認する。

## インスタンシングの注意

`optimizeInstances()` は同じgeometry/materialを使う複数オブジェクトを `InstancedMesh` にまとめ、元のノードを親から外します。従って最適化後に単に名前で桶を探して非表示にする設計は不安定です。

- 対話対象は最適化の前に登録し、可動対象だけバッチ化から除外するか、専用グループへ分離する。
- 39部品を一体として移す時はワールド変換を保つ。稲や関係ない道具を一緒に消さない。
- 安定したゲームIDと表示オブジェクトを別管理する。メッシュ名だけに進行状態を結び付けない。
- 共有geometry/materialを不用意に `dispose()` しない。保存した旧参照がシーンから外れていないかも確認する。
- 持っている桶の表示をカメラに付けるなら、近クリップや壁へのめり込みを確認する。体の衝突をなくして解決しない。

## 一時停止と描画

`ui.playing` が進行許可の基準です。`WalkUI` のmode変更で入力を解除し、Esc、pointerlock解除、ウィンドウ離脱でも停止します。ゲームの入力、時間経過、音も同じ停止規則に接続してください。

現在はタイトル・pause時の連続描画を抑えています。新しい状態でメッシュが変わったら必要な再描画を行い、静止画面で無駄に描画し続けないようにします。`reset()` は位置・視点だけの復帰です。
